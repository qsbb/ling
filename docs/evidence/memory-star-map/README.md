# 记忆库星图接入

`/memory` 的长期记忆入口现在有两种视图：星图与列表。两者共用服务端搜索、分页、来源筛选、导入、选中和详情。星图默认打开，首屏先给出可读的记忆卡片；点卡片进入当前分支已有的详情、来源与可见范围、纠正和撤回。

## 保留的设计

- 横轴按实际时间间隔连续排布，不把月份改成等宽表格；纵向保留经历、事实与线索、做法三条轨道，未知类型单独成轨。
- 十二月令环、月份高亮、同月弧线、事件微切片、下一幕、全景分镜和关联跳读都保留。
- 卡片、年份、记录间隔和跳转沿用原设计的读法。记录间隔只写「本批可见记录之间相隔 N 天」，不暗示这段时间没有记忆。
- 详情先读完整正文，再展开时间、依据、前后经过和相关连线。

## 放大镜与关联度

星图默认只读图。用户点卡片后：

- 左侧/下方出现镜片（桌面右侧浮层，不占布局），列出强/中关联；
- 同源事件 / 纠正链 = 强，实线；同一天 / 相邻三天 = 中，虚线；
- 其余卡片淡出到 20%，仍可点；
- 同地点、同主题、同群不自动算强关联；
- 镜片标题两行、关联最多 2 条、原文默认折叠；点“看完整详情”才进入既有详情、纠正、撤回。

真实 118 条数据里共享事件 0、纠正链 0，所以强关联为 0；这是数据事实，不用同月硬造强关联。

## 记忆范围

- 前端新增“会话：全部 / 仅私聊 / 仅群聊”，并显示卡片是私聊还是群聊。
- 群聊记忆应保留 `group_scope`，不能写成“仅本人”。
- 当前后端导入器只接受私聊：398 条私聊样本预览出 118 accepted；群聊全部 `outside_private_pair`。群聊的前端能力已就绪，等后端扩展。
- 详见 [`MEMORY-SCOPE-AND-BACKEND.md`](MEMORY-SCOPE-AND-BACKEND.md) 与 [`BACKEND-MEMORY-ALL-SCOPES.md`](BACKEND-MEMORY-ALL-SCOPES.md)。

## 布局

星图视图采用 A「全景长卷」：左侧固定月令环，右侧宽时间轴，详情不再占右侧栏，而是全宽贴在星图下方。列表视图仍保持原来的索引 + 右侧详情双栏。

- 桌面：`.mem-workspace--stars` 单列；`.mem-star-atlas` 为 190px 月令环 + 自适应时间轴；详情面板整宽、内部滚动。
- 375：月令环横向压在时间轴上方，轮盘 94px；星图首屏能看到第一张卡片。
- 320：同一套横向月令条，轮盘 86px；记忆页 tabs 从两行改成单行横向滚动，否则星图会被导航推到首屏外。
- 详情保留完整正文、来源与可见范围、事件微切片、全景分镜；桌面首屏能看到详情标题与正文开头。

## 接入时改了什么

- **时间口径**：`import_source.occurred_at` 才是发生时间，`created_at` 只表示记下时间。导入条目缺发生时间时进入独立「发生日期未知」列，不再拿记下时间顶替。详情同时显示发生时间（或「未记录」）与记下时间。
- **月份弧线**：同年同月与跨年同月分成两种弧线和两种标签；月令环分别标记，不再把同年重复说成「跨年共振」。
- **依据连线**：只连接纠正链和共享的具体来源事件。同地点、同主题、同群、同一段旧会话都不足以证明是同一件事，因此不再按旧会话画同源线。详情里的连线和分镜写明依据（事件 id 或纠正关系）。
- **窄屏**：月令环缩到 94/86px 压在时间轴上方；图例 320 下收起，星图首屏保留第一张卡片；画布在容器内横向平移，不撑破页面。
- **详情**：列表与星图共用同一个 `MemoryInspector`。星图详情改为下方全宽面板，桌面首屏可见标题与正文；窄屏只有主动点卡片才进入阅读态，返回时焦点回到原卡片。
- **只露出当前分支支持的能力**：旧分支专有的 `source_message_id`、`source_role`、`valid_from`、单条「遗忘」与查看原话接口不在 `origin/main`，本次没有伪造入口。纠正、撤回、来源与可见范围、隐私页的「遗忘全部」保持原样。

设计基线是本机旧分支 `90b8e57` 的 `MemoryStarMap.tsx` / `memory-star-map.css`。交接 bundle `4b4c749` 的树里没有这份文件，所以没有把旧分支整体合入；新分支以 `origin/main` 的实际字段为准重写了模型和接入层。

### 变异与恢复

历史星图渲染在 `/tmp/ling-memory-star-map-mut` 做过接线与依据两次变异；A 版布局另在 `/tmp/ling-memory-star-map-a-mut` 做了一次针对性变异：

- 把 `.mem-workspace--stars` 从单列改回双栏 → 同一条星图用例在“详情宽度 ≥ workspace 宽度”处失败，实际 431px 对 979px（[`logs/mutation-layout.log`](logs/mutation-layout.log)）。
- 恢复 CSS 后 `shasum -a 256` 与工作区一致，复跑同一用例通过（[`logs/mutation-layout-restored.log`](logs/mutation-layout-restored.log)）。

第一次变异最初没有变红，暴露出断言缺口：双栏时详情仍被自动放到第二行，只断“在下方”不够；补成“详情整宽”后才变红。原始工作区没有用于变异。
