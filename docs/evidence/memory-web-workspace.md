# 记忆页：从找、确认到修正

旧页要求用户先滚过核心记忆和常开表单，才能找到长期记忆；每行重复显示同一组按钮，删除全部也紧跟在列表后。新版将三件事作为浏览流程：找到一条记录、判断它从哪里来和谁能看到、作出更正或停止使用的决定。设置和永久清理不插在浏览流程里。

## 参考与取舍

- [Mem0 / OpenMemory 控制台存档](https://github.com/mem0ai/openmemory/blob/main/openmemory-archive/README.md)：把存储在系统里的记忆做成用户能浏览、管理的对象，而不是只能通过问模型得到回答。Ling 的管理 API 没有全文检索或分页，所以搜索范围明确限定于本次加载的数据，也不使用对话模型。
- [Letta 的核心记忆块](https://docs.letta.com/v1-sdk/memory/memory-blocks)：将常驻上下文与按需找到的历史分开。Ling 的核心记忆独立管理，仍遵守自己的预算、可见范围和完全隔离规则，不承诺每项每轮都出现。
- [Memory Companion 的记忆排查](https://github.com/menglimi/astrbot_plugin_memory_companion/blob/main/CHANGELOG.md)：让可见范围、召回编排和证据可解释。Ling 的详情显示已返回的来源和变更记录；没有单条详情或逐轮召回数据时，不伪造对话链接、当前注入状态或图谱。

未引入这些项目的代码或依赖，未修改记忆存储、检索和权限策略。历史记录只读；纠正、撤回和批量遗忘继续使用既有 API。

## 验证

独立 Playwright 验收用真实 Vite 与模拟 API 测试浏览、确认写入前不提交、跨分区保留草稿、键盘与窄屏操作、错误隔离及筛选竞态。分别在临时源码副本把已加载数量替换成总量、移除过期响应保护，对应验收断言都失败；共享工作树没有用于变异。
