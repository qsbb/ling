## 缺陷（R17 取证实测到，非推理）

10 轮真实模型对话里有 3 轮的**首次生成**（读视频之前）说出了**上一轮**视频的内容：

| 轮 | 真实视频 | 首答（读之前）说了什么 |
|---|---|---|
| A2 | blue / A2 | 「看了，红底白字一个 **A1**，挺简单的画面。」 |
| A4 | yellow / A4 | 「看了，绿底白字一个 **A3**，跟你之前发那几个差不多。」 |
| B3 | pink / B3 | 「看了，就个青底白字 **B2** 的静态画面，没看出哪儿有意思。」 |

三次全部指向**上一轮**；而这三轮读到观察之后的第二次生成都正确
（A4→黄 A4、B3→粉 B3）。反证：内容来自上下文里的**旧描述**。

## 根因（`src/ling/kernel/context.py`，三处）

1. **已描述条目不带任何标识**（原 `:788`）：`- {who}{when}发的{label}：{description}{tag}`。
   而"待看"那条**带**短号 `<<看视频 mXXXXXX>>`（原 `:846`）。模型无法把"某条描述"
   对应到"某个具体视频"，只能挑最近的一条来用。
2. **时间只到分钟**（`_as_local_hint` → ` HH:MM `）。同一分钟发的多条渲染成
   **逐字相同的前缀**，人眼也分不出。
3. **措辞错配**（原 `:796`）：块标题写「最近的 N 条**图片/语音**」、引导语写
   「对应历史里那些『发来**一张图片**』的消息」，而列表里装的是**视频**。
   `_MEDIA_KIND_LABELS` 里明明有 `video: "视频"`，是模板文案没跟上 kind。

### 改动后

```text
这个窗口里最近的 3 条语音/视频——这些是你**之前**收发过的、已经知道内容的，**不是**这一轮新发的：
- 主人 04:21:05 发的语音（第 1 条）：对方说自己今天有点累。（对方说的）
- 主人 04:21:05 发的视频（短号 m7d34e6）：画面是纯purple背景。（对方说的）
- 主人 04:21:05 发的视频（短号 m703743）：画面是纯green背景。（对方说的）
更早的语音/视频没有描述，你看不到，别假装看过。
标注为推断的内容只是你的猜测，不要当成对方告诉过你的事实。

这个窗口里有你**还没看过**的视频——这些是新的，不是上面那些已经知道内容的：
- 主人 04:21:06 发了个视频，你还没看。想看就写 <<看视频 mf04ccf>>（这条标记不会发出去）。
只有你写了标记，才会去看；没写就当没看见，别假装看过。
上面那条「之前收发过、已经知道内容的」列表里如果有视频，那是你看过的旧视频，不要拿它的内容当成这一条。
```

**注意**：两行的时间戳**仍然相同**（`04:21:05`，同一秒）。真正消歧的是**短号**，
不是秒。秒只是顺手补的精度，不靠它兜底。

## 设计取舍

### 视频给短号，图片/语音给序号（Lead 已确认接受）

- **视频**：用 `short_ref_for(evidence_id)`，与「待看」那条 `<<看视频 mXXXXXX>>`
  **同一个函数、同一个短号**。两套短号必然分叉，分叉的表现是"她写的短号对不上
  任何视频"——比原缺陷更难查。
- **图片/语音/表情**：**不给短号**，只给 `（第 N 条）`。
  理由：**短号是可执行动作的句柄，不是通用 ID**。图片没有 `<<看图片>>` 这种标记，
  给了短号她会尝试写，而解析不到任何东西——白瞎一轮，还平白多一条"没看成"日志。
  "给了做不到的句柄"正是这个仓库反复踩过的坑（`<<撤回 rXXXX>>` 那五道闸就是为此加的）。

**给视频短号是安全的**：`watch.py:334-338` 里 `if evidence.description:` → 直接用
已有描述、`cached=True`、**不再调模型**。所以指认一个已看过的视频不会二次烧钱。

### 为什么额外加那句"不要拿旧视频的内容当成这一条"

单纯加标识解决的是"分不清"，但实测到的错误形式是"**拿上一条顶替本条的**"。
所以待看块末尾直接写了针对性的禁令——对着观测到的错误下药，而不是只给一个更细的 ID
让她自己推。

## token 预算影响

| 项 | 数值 |
|---|---|
| 媒体车道预算 | `DEFAULT_BUDGETS["media"] = 1500` token → **3000 字符**（按 2 字符/token） |
| 实测最坏（3 已描述 + 3 待看，描述写长） | 媒体车道共 **686 字符 = 22.9%**，**未触发截断** |
| 单条车道最大 | 392 字符（13.1%） |
| 视频行增量 | **+15 字符**（短号 12 + 秒 3） |
| 非视频行增量 | **+11 字符**（序号 9 + 秒 3） |
| 3+1 场景整块增量 | **+132 字符**（203+98 → 255+178） |

**不会挤掉别的内容**：车道内余量 6.6 倍，且媒体是独立车道，不挤占历史/记忆。
