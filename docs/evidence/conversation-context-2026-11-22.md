## Ling 的第一期策略

- 普通轮次按同窗近期消息取数，最多 40 条并保留历史 token 上限。识别到发言人此前的开场或明确换题时，原文从那里开始。最近条数刚好切开一问一答时，从下一完整轮开始。
- 单独问候跳过自动召回，只查看五分钟内的相邻对话。短应答取相邻对话，最多四条，并保留它可能在接的那次提问和回复。明确换题从当前消息开始。
- 明确回指旧对话时沿同一窗口读取更早原文和滚动摘要，仍受历史预算约束。摘要已覆盖的原话由显式引用或原话工具读取。历史取数改变的是本轮提示词，聊天记录仍可查看。常驻记忆与旧事的自动召回分别处理。
- OneBot 显式引用通过当前窗口的入站 ID 映射或成功投递回执解析。被引用户发言按原文和已知署名显示，引用 Ling 发出的分段消息时显示那一轮记录的正文。目标不可读时在当前输入标明。
- `context_compiled` 日志按轮记录历史条数、摘要、引用、自动召回条数和整体 token 估算。现有提示词快照保留实际消息内容及来源。

针对修复的回归从本地 PostgreSQL 上的正常 OneBot 入口发起。合成对话沿用线上案例的消息顺序和长历史结构。线上快照用来定位输入来源，本地模型边界用于验证送入内容和日志。

## 同窗隔夜回放

在 `d4a8573` 上补跑三组同窗对照。模型使用本地测试路由，聊天通过实际 OneBot HTTP 入口，使用隔离 PostgreSQL 和测试投递回执。隔夜直接发新问题和单发「？」时，旧话题的一问一答仍进入历史原文。过去几小时内有连续聊天时，旧话题也会穿过中间的长空档进入历史。

普通轮次和短应答现在遇到相邻消息超过两小时的空档就停止往回取原文。两小时沿用窗口短记忆的闲置期限。正在连续聊天时，取数仍由相邻的消息间隔、主题信号和已有预算共同控制。单独问候沿用五分钟观察范围。原对话窗口继续使用，用户仍能翻阅记录、引用某一条旧消息，或者明确说「接着说昨天那个」来读取更早的原文和摘要。

三组回放在基线上均复现旧内容回流，修复后保留了紧邻续聊与明确回指。快照和日志在实际撞到空档时记录 `history_boundary=idle_gap`。
