# 导入旧记忆 · 验收判据

分支 `lingxi/astrbot-memory-import-web`，基线 `2b3fc01`，接口契约 `docs/ASTRBOT-MEMORY-IMPORT.md`。

**诚实声明**：这份判据是在实现已经落盘之后写的（同一个人既实现又验收）。因此它**不能**
证明"判据独立于实现"。能补救的是范围里写明的那几条半成品检验——它们是先定"什么算红"、
再去构造缺陷，不依赖实现细节。凡是没有半成品或反例支撑的条目，在结论里都标"弱"。

## A. 入口可达

| # | 输入 | 期望 | 哪个错误实现会让它红 |
|---|---|---|---|
| A1 | 记忆库有 0 条记忆 | 「导入旧记忆」按钮存在且可点 | 入口挂在空态面板里、或依赖列表非空 → 空库找不到入口 |
| A2 | 有记忆 | 同一入口存在 | 入口只在某一状态渲染 |
| A3 | 375×760 | 入口可见、可点 | 入口被窄屏样式隐藏或溢出到屏幕外 |

## B. 预览先把三件事说清

| # | 输入 | 期望 | 会让它红的错误实现 |
|---|---|---|---|
| B1 | preview 返回 destination | 页面出现 display_name 与 subject_id | 只显示"已选文件"，不给目标自然人 |

| B3 | `accepted=5,total=5` | 可导入数字为 5，并给出文件总条数 | 用 total 冒充 accepted；或前端自己算 |

## 半成品检验（先定"什么算红"，再造缺陷）

1. **只做预览、不做确认**：删掉确认按钮的 `commitMemoryImport` 调用（只保留预览）。
   期望 E1/E2/E3 全红。
2. **确认后不切来源**：`onViewImported` 里去掉 `onSourceChange`。
   期望 F1 红（请求里不再带 `source=`），而 E1 仍绿——这正说明 F1 覆盖的是另一条不变量。
3. **伪造发生时间**：G2 改成 `occurred_at ?? created_at`。
   期望 G2 红。

这三条的意义是：如果某个"半成品"下判据仍全绿，那条判据就没有在守护任何东西。
