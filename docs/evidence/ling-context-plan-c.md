## (2) C 的可行形态（明确不建议第一期；附条件式设计草图）

### 2.1 正式结论

**不建议第一期做 C。** 理由：见 §1.3；且 `00-criteria.md` §2.2 已预先声明准入条件——「只有数据支持（B 的半成品红暴露了『信号有但落点错』）时才评估 C，不无条件上 C」。该条件当前未满足（B 本身也未落地回放）。

### 2.2 若未来数据支持，C 的条件式形态（全部为**推理**，非结论）

以下逐条回答任务点名的设计问题，供第二期按需取用。**每段都带可反驳条件**，避免用强格式承载推测。

**分段粒度：按话题为主，时间作次级信号，事件边界作切分标记；不按固定时长。** 这是从 `P3-lightweight.md` §1–§2 的信号优先级（显式引用 > 显式找回锚点 > 承接词 > 时间位置 > 纯邻接）推出的工程选择，不是实测最优。可反驳条件：若 2×2 回放显示「无锚点但时间邻近的续接」才是主要误续来源，则时间权重应高于话题词，本粒度需改。不把「人类工作记忆 7±2」「20 分钟遗忘曲线」「论文执行时长」当 Ling 参数（对抗判据 H1–H3）；任何阈值只能来自代码常量或在回放集上按条件式校准（H2）。

**边界怎么标：在 `CompiledContext.annotated` 表达层加 `lane`/`key`，不新建数据表。** 现状 `annotated` 已有 `history/input/summary/evidence` 等 lane（`02-options.md` §7）。C 可在此基础上把同一窗口的消息标成「当前话题/较早话题/摘要派生」并显式写出「较早 ≠ 当前指代对象」——`ling-context-im-async.md` §4.7 也建议给常驻摘要加这类标注。可反驳条件：若标注后 C1/C3 不降反升（旧话题标记反而让模型更频繁引用旧事），则该表达层方案无效。

**如何避免破坏同一窗口复用：分段只改提示词装配，不改复用键与 `window_id`。** 复用键 `(actor_id, channel, window_ref, instance_key)` 和 recent history 的根键 `window_id`（`C-bridge-window-reuse.md` §3–§4）都保持原样；分段是「同一窗口内给消息加可见性注释」，不是物理分窗。可反驳条件：若实现需要新增 `topic_id` 参与取数键，则已越界到数据模型层，应视为「新窗口」分支而非 C。

**旧话题如何显式找回：靠锚点，不靠分段本身。** 时间锚点（「前天/上次 + 话题名词」）、引用/`@`、元话语（「刚看到/回晚了」+ 名词）触发回看（`P3` §2 第 1/2 条）；承接词只在最近 1–2 泡有效；无锚点短消息默认不恢复（`02-options.md` §1）。对抗判据 M-1/M-6 的区分测试要求：把「接着说前天那个方案」换成「接着说」仍判找回，就说明测的是「接着」二字而非锚点——该测试不过，找回实现就是假的。分段只让「旧」被看见地标注，**不能替代锚点识别**。

**群聊怎么跟对说话人和引用消息：分段必须携带四类标识，不得在切段时丢失。** 逐条 `sender_subject_id` 绑定、不继承上一条；`@` 是目标字段不是说话人；引用是消息→消息，不推出说话人；引用 id 可见集合按 `window_id` 限定（`ling-context-im-group.md` §4.1–4.4、`02-options.md` §2）。对抗判据 C4/M-9/M-10：引用目标在 12 条窗口外时必须展开正文或明确降级，**不得静默取最近一条**；同名不同人靠人级 id 分开。可反驳条件：若分段后「同名相邻不同人」样本（S-12）被并成一个人，则分段实现破坏了既有防护，必须回退。

**新窗口是否真的必要：倾向不一定，默认不新建。** 这是**推理 + 代码路径实测**的结论，不是实测的行为结论：窗口按聊天目标复用、与话题无关（`bridge.py:1479/1565`）；新建窗口会把「隔天续聊」和「几秒内换题」拆到不同窗口，反而丢掉判断所需的时间位置信号（`P3` §4）。分段在表达层，新窗口在数据层，二者不是同一杠杆；C 能成立的前提恰恰是「不动窗口」。只有独立证据——同一聊天目标长期存在多条稳定话题簇，且回放显示混取误续率显著高于分窗——才值得评估分窗（`P3` §4、`02-options.md` §3）。当前**无此证据**。

### 2.3 半成品红（C 若进入评估，先过这一关）

沿用 `00-criteria.md` §2.2，先于实现写死：

- **C-half-1 = 只加分段标签，不改变取数** → 预期红：**M-4/M-5**（换题自然度）。理由：分段本身不能替代换题识别；只贴标签而仍把旧题取进来，显式换题样本 S-02/S-13 仍会续旧。

- 两个半案各自全绿 = 判据没覆盖真正的不变量，C 的收益主张不成立。

1. **边界误判反致漏续**：把正在续的话题切成「旧」→ C3 上升。可反驳条件：若标注后 S-01/S-04 的锚点话题仍被正确识别为当前，此风险在该样本上不成立。
2. **标签挤占 token 预算**：分段标签占字符，可能挤掉其他车道（C5）。可反驳条件：对照快照的 `annotated` 字符/token 数不升或净降。
3. **误把表达层做成数据层**：若实现新增 `topic_id` 参与取数键，就破坏「同一窗口复用」并丢时间位置信号（§2.2）。可反驳条件：复用键与 `window_id` 在改动前后逐字节一致。
4. **群聊标识在切段时丢失**：逐条署名、`@`/引用区分、同名不同人防护被段边界吞掉（C4）。可反驳条件：S-09/S-10/S-12 的分段后快照仍逐条携带 sender 与 reply_to。
5. **把「摘要常驻」误当成分段能解**：常驻是取数/TTL 设计问题；分段只加标签不改「取不取」，若不动 `context.py:1673-1685` 的注入条件，旧摘要仍会进 prompt。可反驳条件：无锚点轮次里旧摘要是否仍出现，须在快照上断言。
6. **竞争性解释未排除**：误续可能来自召回相似度（E1）、近因位置（E2）、记忆合成（E3）、模板引导（E4）、模型惯性（E6），而非「缺分段」。不排除就归因为分段，是错误归因（对抗判据 §10）。

## (5) 最值得补的一组实验

采纳对抗判据 §10 的选型：**2×2 对照回放**，这是当前区分力最高、且资源只够一组时的首选。

### 5.1 设计

- **因子 A**：旧事片段是否存在（有 / 无）。
- **因子 B**：用户本轮是否真的在延续旧事（是 / 否）。
- 四格用**同一批真实模型回放**与**同一提示词模板**，只改这两个因子。
- 观测：模型是否接旧事，按「误提 / 续聊 / 换题」三分类记录（对应 C1/C3 与 C2）。
- 样本映射：A 有+B 是 ≈ S-01/S-04/S-07；A 有+B 否 ≈ S-02/S-05/S-06 位置二；A 无+B 是 ≈ S-03/S-06 位置一；A 无+B 否 ≈ 纯新开场对照。

### 5.2 条件式读法（不写期望值）

- 若「有片段 → 更多接旧事」在 B=否 时仍显著 → 支持 **E1/E2/E3/E4**（片段/位置/记忆合成/模板驱动），分段**可能**有用；
- 若只在 B=是 时接旧事 → 支持 **E5**（用户真延续，基线现象，非 bug），分段**无必要**；
- 若 A=无时也接旧事 → 支持 **E6**（模型自身惯性，空记忆对照组），分段**无效**；
- 四种走向互斥，因此这一组能同时区分「片段驱动 vs 意图驱动 vs 模型惯性 vs 模板驱动」——这正是任何单一 A/B/C 对比做不到的区分力（C7）。

### 5.3 前置条件（缺一不可）

1. **真实模型输入与回复**：需可用 API 或至少可复现的提示词快照；当前无 API env（§1.1），必须先解决取证手段，否则所有结果只能标 `SCRIPTED`。
2. **人工标注**：话题边界、误续/漏续标签；C2 自然度需多评分者或明确量表，禁止设计者自评当结论（C9）。
3. **成本记录**：A/B/C 各自的 `annotated` 字符/token 数与调用次数，按 C5/C6 口径记录；单次运行必须标「复述级（N=1）」（C10）。
4. **反例齐全**：C8 四类反例输入都要覆盖——不该续却像该续、该续却像不该续、群聊同名/相似昵称、旧事与新事关键词重叠。当前合成样本覆盖前两类与部分第三类，第四类需补。

### 5.4 从实验回 C 的判据（准入闸门）

只有当 2×2 结果同时满足：① B=否 且 A=有 时误续显著高于 A=无（证明片段驱动存在），② B 的半成品红暴露「信号有但落点错」（`02-options.md` §5 第 3 步），才进入 C 的 C-half-1/C-half-2 验证。否则结论写「C 不建议做」，并把资源投给 B 或取数/TTL 的局部修正（如 `context.py:1673-1685` 的摘要注入条件）。
