# 日程补排：为什么只排后续时段

前夜没有可用模型时，规则仍能提供睡眠与已确认约定；但不应因此锁死后续可选活动，也不应在服务恢复时回填已经发生的时段。补排取下一时段为可选活动下限，现有硬锚点仍按当前时间处理。生成启动与提交前都检查时段边界；丢弃超时答复不返还已经调用的模型预算。对同一时段重领已完成的降级作业，也不应重复消费预算。

## 验证与限制

在本地 PostgreSQL 的隔离 schema 运行 `tests/integration/test_life_schedule_worker.py`：首次生成不可用后切换人设，补排把新设定发送给替身模型，并提交由新设定决定的活动；旧设定和完整系统提示不发送。这个回归证明了数据接线，不是对真实供应商输出质量的评估。

在临时源码副本去掉「提交前检查边界」和「已提交降级版本不重跑」两道各自独立的判断：跨边界提交与未确认事件重领两条断言各自失败，按时返回的正例仍通过（2 失败、1 通过）。未修改原工作树的被测实现。
