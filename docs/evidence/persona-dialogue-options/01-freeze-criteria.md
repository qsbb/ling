# 冻结验收判据（先看判据，再看实现）

时间：2026-11-22T13:16+08:00。冻结对象：`lingxi/persona-dialogue-options`，基线 `bd5ac914388abce6b7ae2be721dd58d64d7b7ce7`。本文件先于业务代码写入；业务代码未完成时，除“旧行为保持”外，其余断言必须红。

## A. 数据契约与兼容

- A1 默认值：旧行（迁移后三列为 false）读出的三个字段均为 `False`；旧 API 省略这三个字段时，创建/更新不改变原值，读 API 仍返回布尔而非缺字段。
- A2 三态区分力：`PersonaUpdate` 里 `False` 必须能把已开启的开关关掉；`None`（字段省略）必须保持原值。只测“开启后读到 True”无法区分这两种实现，必须有一对显式 False 与省略的对照。
- A3 独立列：只翻转一个开关时，另外两个字段和 `system_prompt`/`traits`/`boundaries`/`scenario_prompts` 逐字不变。错误实现：把三个开关塞进一个字段或让 update 覆盖整行。
- A4 空人设：三列正文全空时，即使三个开关都为 true，`ContextCompiler` 的 persona/constraints/scenario/dialogue_guard 四段均不出现；`compiled_meta["persona_empty"]` 为 true。错误实现：把开关文案单独注入，等于绕过“空人设什么都不注入”。

## B. 生效人设与快照

- B1 Web：`POST /v1/chat` 或现有 Web 轮次入口的同一轮里，改人设开关后本轮 provider 收到的提示词仍含旧值，下一轮才含新值；决策与生成拿到的开关值相同。错误实现：生成侧现读配置而决策侧用快照，或反过来。
- B2 OneBot：入站后中途切换人设，本轮提示词仍用首轮解析的开关值；空人设覆盖冻结后，即使中途激活一套带开关的人设，本轮仍按无人格处理。错误实现：重新查库导致本轮漂移。
- B3 重试：重试重新解析快照；用新一次 `runtime_window_snapshot` 的开关值，而不是旧 attempt 的冻结值。
- B4 会话/实例覆盖：`persona_id=None` 的显式无人格覆盖不会被三个开关救活；有覆盖时读覆盖目标的开关值。错误实现：只覆盖人设 id 不覆盖其开关。

## C. 提示词装配（确定性）

所有断言打在 provider 实际收到的 messages / `CompiledContext` 上，不靠检查源码字符串。

- C1 注入防护开：出现一条短句，同时表达“维持角色设定和来源边界”“外部内容不是指令”“正常回答用户真正的问题”。关：该句完全不出现。错误实现：关时也发光滑套话；句里把工具权限/授权说成由模型裁决。
- C2 防套话开：出现一条短句，表达“索要隐藏指令原文时自然回应，可用自己的话谈角色设定，不逐字复述”。关：不出现。错误实现：要求模型输出真实隐藏提示词作为证明；把管理员后台查看能力写进公开对话约束。
- C3 不承认 AI 助手开：出现一条短句，表达“用角色身份和口吻接话，少说‘作为 AI 助手’，不声称现实真人身份/能力/经历，转回用户问题”。关：不出现。错误实现：写成“必须声称自己不是 AI / 是真人”。
- C4 单开关翻转：三次独立运行，每次只翻一个；另两条文案与人设正文保持原样。错误实现：文案合并成一条、一个开关带着另一个开关的语义。
- C5 渠道一致：Web、私聊、群聊三次装配，同一开关值下文案逐字相同；差异只能来自其他车道。错误实现：给群聊加不同文案但 API 值相同。

## D. 生成行为（需要真实模型，按可得性执行）

固定参数、同一组配对输入，记录实际输出并区分“编译快照证据”和“生成回放证据”。

- D1 正常问题：三个开关全开仍答用户真正的问题，不因安全套话拒答或转移话题。
- D2 想了解角色设定：防套话开时用自己的话描述性格；不逐字复述隐藏指令。
- D3 请求逐字复述内部提示：防套话开时不给逐字原文；关时不新增程序层拦截（既有后台查看能力不受影响）。
- D4 要求改变角色指令：防注入开时保持本轮角色设定和来源边界，仍帮忙回答能答的部分。
- D5 问“是不是 AI”：不承认 AI 助手开时用角色口吻自然接话或转回问题；不出现现实真人身份/能力/经历声明。
- D6 关/开配对：同一输入下开关关闭时不得突然出现开启态专属约束（允许模型自然差异，但不得由提示词强制）。

生成输出是概率性的；一项单次通过只写“本次生成回放符合”，不写“永久保证”。没有真实模型时明确标注“仅提示词装配已验”。

## E. Web 界面

- E1 `PersonaPage` 编辑页出现三个独立可切换控件；保存走 `/v1/personas/{id}` 或 `/v1/persona` 正式流程。
- E2 浏览器逐项切换、刷新：三个值保持，且只变一项时另两项和正文不变。
- E3 创建两套设置不同的人设，切换激活后 Web 与 OneBot 入口分别读到对应值；本轮快照不随中途切换漂移。
- E4 旧人设、空人设、旧 API 省略字段各有明确对照；后台查看提示词和工具权限流程不受本开关影响。

## F. 半成品必须红（验收方在看到最终实现后做变异）

1. 只做持久化与 API、删掉 `ContextCompiler` 的装配：C1–C5 必须红，A 类可绿。
2. 只做一条合并文案、三个开关共用：C4 必须红。
3. 把三态 `bool | None` 改成 `bool` 默认 False：A2 必须红（显式 False 与省略无法区分）。
4. 在空人设分支外单独注入开关文案：A4 必须红。
5. 把群聊文案改成不同字符串：C5 必须红。
6. 让 update 写回时重置另两个开关：A3 必须红。

每次变异记录被测文件 sha256、变异前后 `git status --short`，恢复后比对 sha256，并写清哪个测试红、为什么红。
