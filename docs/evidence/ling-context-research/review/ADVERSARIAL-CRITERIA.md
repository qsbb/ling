## 0. 判据的使用方式

对每一条断言/结论，审查时逐条给出三段式：

1. **能证明什么**（在何种观测条件下成立）
2. **不能证明什么**（哪些前提缺失、哪些替代解释未被排除）
3. **置信度三档**（见 §8）：实测 / 推理 / 转述（未核实）

任何一条只有"通过/不通过"字样的审查视为未完成。
一般原则：一条断言的效力 = 能把"错误实现"与"正确实现"区分开的最小观测集合；区分不开就写"无法证明"。

---

## 1. 证据来源的真实性与可复查性

每条外部事实（论文、实验结论、数字、参数）必须能回答四个问题：**谁说的、在哪说的、我怎么找到的、我能不能复算**。

| 编号 | 判据 | 若缺失 → 后果 |
|---|---|---|
| S1 | 论文必须给出：作者、题名、会议/期刊、年份、可点击 URL 或 DOI；只有"某研究显示"没有出处 → 标"转述/未核实" | 不可复查的引用不是证据，是修辞 |
| S2 | 论文里的实验结论必须区分：原文报告的数字 vs 作者对 Ling 的外推。两者不可混写为同一句事实 | 外推被当成原文结论会抬高可信度 |
| S3 | 引用源码必须给出：文件路径 + 行号区间（或稳定符号名）+ commit SHA；行号必须能在基线 SHA 上核对 | 行号漂移 / 引用了不存在的代码 |
| S4 | 引用命令输出必须给出：完整命令（含工作目录与环境变量前提）+ 原始输出（可截断但需说明截断规则）+ 执行时间；只有"我跑了测试，结果是 XX" → 标"转述" | 无法排除跑错分支/跑错环境 |
| S5 | 数字必须有来源标签：`代码常量/公式推导`（判据级）vs `某次运行实测`（复述级）vs `估计`（不可进结论表） | 复述被写成判据会掩盖差异（见 AGENTS.md「判据里的数字」） |
| S6 | 若结论依赖"时间/性能/长度"数值，必须区分测量口径：墙钟还是 CPU、p50 还是 max、样本量 N、输入集是什么 | 口径不同的两个数字不可直接比较 |
| S7 | 截图/图片不是文本证据：若引用截图，必须有对应的可复查日志/命令输出或提示词快照，否则截图只能证明"某时刻有过这张图"，不能证明图中结论 | 见 §2 |

**反例输入检验**：对每条引用问"如果这条引用是编造/记错的，审查者能在 5 分钟内发现吗？"——答不出"能"，则该引用不可作为结论支撑。

## 2. 截图不得作为输入证据；输入以提示词快照与回放为准

研究的对象是"模型实际看到了什么、产生了什么"，不是"屏幕上显示了什么"。

| 编号 | 判据 |
|---|---|
| V1 | 关于"模型收到什么上下文/提示词/记忆片段"的断言，必须以**提示词快照**（rendered prompt / compiler 输出）为准；截图只能作为 UI 呈现的旁证，不得替代快照 |
| V2 | 关于"模型输出了什么"的断言，必须以**回放记录**（真实调用日志 / response body）为准；界面截图中的文字若没有对应回放记录 → 只能标"UI 显示如此，未核实是否等于模型输出" |
| V3 | 截图与快照冲突时，以快照为准，并在报告中记录冲突本身（这往往是发现"UI 改了但 prompt 没改"类问题的线索） |
| V4 | 若方案用截图说明"用户会看到 X 从而产生 Y 行为"（人类行为推断），该推断不得写成 Ling 的系统行为事实；归入 §5 的人类参数误用检查 |
| V5 | "提示词快照"必须可定位：哪个 commit、哪次调用、输入是什么、快照文件 SHA256；缺省任一 → 快照不可复查 |

**半成品红测试（针对本条）**：造一个"只有截图、没有提示词快照"的伪证据包，审查判据必须判定"输入证据不足"——若不红，本条判据失效。

## 3. 脚本模拟不得冒充真实模型输出

| 编号 | 判据 |
|---|---|
| M1 | 凡声称"模型表现出 X 行为"，必须说明数据来源：真实 LLM API 响应（含模型名/版本/温度/时间）vs 脚本模拟/模板填充 vs 人工编写示例。三者混写 = 不通过 |
| M2 | 脚本/规则生成的"回复"不得用于证明"模型会理解为……""模型能自动接上……"；最多只能证明"在该规则下会产生该字符串" |
| M3 | 回放输入若是脚本构造的对话历史，必须标注"合成输入"；合成输入上的结果不可直接外推到真实用户对话分布 |
| M4 | 若方案以"这是确定性回放，所以可重复"为由使用脚本输出，可重复性只证明**管线一致**，不证明**模型行为真实**；两者必须分别陈述 |
| M5 | 真实模型输出与脚本模拟输出必须分栏/分节呈现，禁止把它们放进同一张"结果表"且用同一置信度 |

**变异反驳输入**：把结论中"模型"二字的所有出现替换为"脚本按规则"，若句子仍然成立 → 该句本来就没在谈模型，需改写；若不成立 → 该句确实依赖真实模型证据，检查其证据是否满足 M1。

## 4. 不得把人类工作记忆/论文时长当作 Ling 参数

| 编号 | 判据 |
|---|---|
| H1 | 论文里的人类被试参数（工作记忆容量、记忆时长"7±2"、"20 分钟遗忘曲线"等）只能作为**设计隐喻/启发来源**，不得直接写为"Ling 的记忆窗口应为 N" |
| H2 | 若采用某个数字作为 Ling 参数，必须给出 Ling 侧推导：token 预算、调用延迟、成本上限、对话分布观测中的至少一个；仅有"论文说人类是 X" → 判为无依据 |
| H3 | 论文实验时长（"持续 6 个月的研究"）是论文的执行时长，不是 Ling 的记忆保留时长；二者混淆 = 不通过 |
| H4 | "类人""类似人类记忆"类措辞必须跟一句限定：是功能类比还是机制类比；机制类比需要额外证据（Ling 的实现是否真的具有该机制） |
| H5 | 论文结论到 Ling 的每一步外推都要标推理档；不可因为论文是实测就把外推结论也写成实测档（见 §8） |

## 5. A/B/C 方案比较的量化要求

方案比较必须**逐项量化**，不接受"更自然""明显更好""感觉更准"这类无口径形容词作为结论。

| 编号 | 指标 | 必须有 |
|---|---|---|
| C1 | 误提旧事（false recall） | 定义：什么算"误提"（错误时间/错误对象/已结束话题被当作当前）；测例集与计数；A/B/C 各自的分子/分母 |
| C2 | 主动换题自然度（topic shift naturalness） | 评测协议：谁评、几条样本、评分量表定义、评分者一致性；不能用设计者自评当结论 |
| C3 | 漏续聊（missed continuation） | 定义：什么算"该续未续"；反例如"用户说了'刚才那个'但没接上"；测例集与计数 |
| C4 | 指错人/消息（wrong target attribution） | 定义：群聊中把 A 的话归给 B、引用了不存在的消息 id；测例集与计数 |
| C5 | 输入长度 | token 数（含 prompt 全量）、字符数、是否截断、截断位置；A/B/C 各自数值与口径 |
| C6 | 额外调用 | 次数（每轮/每会话）、延迟增量、失败降级路径；A/B/C 各自数值与口径 |

附加判据：

- C7：所有指标必须回答"如果 A/B/C 在这些指标上完全相同，这份比较还有什么区分力？"——答不出则比较退化成偏好陈述。
- C8：样本必须包含**反例输入**：至少一组"不该续聊但看起来该续"、一组"该续聊但看起来不该续"、一组"群聊中同名/相似昵称"、一组"旧事与新事关键词重叠"。缺任一 → 该指标的区分力不足。
- C9：C2 的自然度若没有多评分者或明确量表，只能标"推理/偏好"，不得进量化结论表。
- C10：C5/C6 的数字若来自单次运行，必须标"复述级（N=1）"，不能写成方案固有属性。

**半成品红测试（针对本条）**：只给 C1/C3 的正确率、不给 C5/C6 的成本，审查必须判"比较不完整"——因为一个零成本的差方案可能优于高成本的好方案，缺成本无法决策。

## 6. 必须有「半成品必须红」「反例输入」「区分力」三件套

这是 AGENTS.md 对我方角色的硬性要求，逐条应用到本次审查：

| 编号 | 判据 |
|---|---|
| A1 | 半成品红：对任一"方案 X 解决了问题 Y"的断言，构造只做一半的 X（如：只召回不排序、只存不取、只做检测不做抑制），检验文档是否明确指出该半案仍会失败。若文档暗示"做了任意一半就能改善"，判为缺乏半成品分析 |
| A2 | 反例输入：每个关键断言至少配一个"前提取反"的输入（见 §5 C8 与 §9 变异反驳） |
| A3 | 区分力：若两个机制在文档给出的所有证据上产生相同输出，必须指出能区分它们的观测；指不出 → 判"文档未证明二者不同"，哪怕它们确实不同 |
| A4 | 格式即置信度：表格/加粗/编号列表只能承载实测或明确规则；推测性归因必须用普通段落并带"推测/可能/未验证"字样（AGENTS.md「格式是一种置信度声明」） |
| A5 | 若文档用"全绿""通过""已验证"等词，必须追问：变异过吗？反例跑过吗？区分路径找到了吗？三者都没有 → 降档为"未对抗验证" |

## 8. 置信度三档（审查输出必须逐条标注）

| 档 | 措辞 | 要求 |
|---|---|---|
| **实测** | "我验证了……" | 有本轮亲自执行的命令/读取输出，或可在基线 SHA 上复现 |
| **推理** | "推测……因为……" | 说清依据，且列出至少一个能反驳它的观测 |
| **转述（未核实）** | "据 X 文档声称……（我未核实其来源）" | 必须带未核实标记，不可进结论表 |

规则：转述他人文档里的"实测"时，对我而言仍是转述档，除非我亲自复现。

## 9. 变异式反驳（至少 2 条，审查阶段执行）

收到四组产出路径后，从结论中挑至少 2 条做"关键前提取反"：

1. **变异 1（证据等级）**：把"真实模型回放"换成"脚本模拟输出"，看原结论是否仍成立；若仍成立 → 原结论与模型无关，应改写为规则结论。
2. **变异 2（参数来源）**：把"人类论文参数"换成"完全相反的观测（如人类工作记忆极小 vs 极大）"，看 Ling 参数推导是否还站得住；若站不住 → 原参数是无依据外推。
3. 可选变异 3（输入分布）：把"用户主动谈旧事"换成"用户输入与旧事无关"，看"续聊自然"结论是否只是关键词匹配的假象。
4. 可选变异 4（指人）：把群聊"用户明确 @某人"换成"无 @ 且昵称相似"，看指错人指标是否还有区分力。

每条变异写明：取反了什么前提 → 原结论是否成立 → 若不成立说明原结论依赖什么 → 若成立说明原结论本就不依赖该前提。

## 10. 「旧话题为何容易被继续接下去」的竞争性解释（审查阶段排序）

先写**候选解释池**（不预设立场，收到产出后再排序）：

- E1 召回相似度驱动：旧事片段因关键词/嵌入相似被检索到，模型顺势接上
- E2 位置/近因偏置：旧事出现在 prompt 靠前或靠后位置，被优先采纳
- E3 记忆合成偏置：记忆层把旧事摘要成"当前意图"，模型把它当用户仍在谈
- E4 提示词模板引导：system/developer 提示里有"保持话题连贯"类指令，鼓励续接
- E5 用户真实意图延续：用户本来就在继续同一话题（基线现象，非 bug）
- E6 模型自身对话惯性：无记忆输入时，LLM 也会偏好延续上文（需空记忆对照组）

排序依据（收到产出后填）：每条解释是否有对照组证据、是否有反例输入、是否能排除其他解释。

**最值得补的一组实验**（先写方向，收到产出后细化）：一个**2×2 对照回放**——因子 A：旧事片段是否存在（有/无）；因子 B：用户本轮是否真的在延续旧事（是/否）。四格都用同一批真实模型回放与同一提示词模板，只改这两个因子。观测：模型是否接旧事（误提/续聊/换题）。
理由：E1/E2/E3/E4 都预测"有旧事片段→更多接旧事"，E5 预测"用户真延续→接旧事"，E6 预测"无片段时也接旧事"。只有这个 2×2 能同时区分"片段驱动 vs 意图驱动 vs 模型惯性 vs 模板驱动"，是区分力最高的一组。若资源只够一组实验，选它。
