### 1.3 REAL_MODEL 与 SCRIPTED 的边界（硬规则）

来源：`ling-context-replay-samples.md` 强制要求「回放记录必须附实际模型输入与实际回复；凡未调用模型、只用规则推演的结果，必须标 SCRIPTED」；
`ADVERSARIAL-CRITERIA.md` §3 进一步禁止用脚本模拟证明「模型会理解为……」。

本设计中每一条盲评记录必须带一个来源标记，且只能取以下三值之一：

| 标记 | 定义 | 能证明 | 不能证明 |
|---|---|---|---|
| `REAL_MODEL` | 真实 LLM API 对合成输入的一次实际调用，记录模型名/版本/温度/时间/完整 messages/response body | 该模型在该输入与该提示词下实际输出了什么 | 不能证明真实用户分布下的表现；不能证明模型内部「记得」 |
| `SCRIPTED` | 规则/模板/静态推演产生的「输入会是 X」「输出会是 Y」 | 该规则在该输入下会产生该字符串 | 不能证明任何模型行为；不得填进盲评的「实际回复」列 |
| `UNKNOWN` | 未取得快照或回复，只有截图、口述、事后回忆 | 只证明「某时刻有过该表述」 | 不得用于任何 C1–C8 判定 |

反混淆规则：

1. 同一张结果表里禁止混放 `REAL_MODEL` 与 `SCRIPTED`（对应 `ADVERSARIAL-CRITERIA.md` M5）。
2. 「编译输入含/不含某片段」若来自代码静态阅读，标 `SCRIPTED`，只有来自 `CompiledContext` 快照才升为 `REAL_MODEL` 的输入侧证据。
3. 「？」经 NFKC + 去标点后为空、是否命中 `_STANDALONE_REPLIES` 属于代码事实；即便属实也只说明**规则层**是否跳过召回，
   不能替代「模型在位置一/位置二实际输出不同」的 `REAL_MODEL` 证据。`ling-context-human-turns.md` 已指出该归因在仓库内有争议，本文不采信也不反驳。
4. 盲评者拿到的样本包里若只给出「预期回复」而没有 response body，一律按 `SCRIPTED` 处理，判据记为「未取得数据」。

### 1.4 六个评分维度（ blind scoring 共用量表）

每条盲评样本按以下六个维度分别打分，再合成 C1–C8 判定。每个维度都要求**同一条记录里同时给出输入侧证据与输出侧证据**，缺一侧则该维度记 `UNKNOWN`。

| 维度 | 记号 | 观测点（快照/回复） | 打分语义（条件式） |
|---|---|---|---|
| 误提旧事 | D1 | compiled messages 中旧话题片段的来源标记 + 回复文本 | 回复提到未被锚定的旧事→召回层误触发；回复不提但快照带了旧片段→输入层已污染、模型恰好没用；两者都没有→该样本对 D1 无差异 |
| 主动换题自然度 | D2 | 当前输入原文是否完整入 prompt + 回复是否接新话题 | 用了「先别说那个」类显式信号→自然换题；没用信号但碰巧转了→无法证明是换题逻辑；仍续旧→红。量表须两名评分者，否则只写描述 |
| 真需续聊却漏掉 | D3 | 锚点特征（时间锚点+话题名词/引用/@）是否进入 query + 回复是否接旧事 | 有锚点且回复接上→找回工作；有锚点但回复泛泛→漏续；无锚点也接上→D1 问题而非 D3 |
| 指错人/指错消息 | D4 | mentions 解析、reply_to 解析、逐条说话人字段、被引消息是否入 prompt | 回复指向被 @ 的人或被引用那条→对；指向最近气泡/显示名相同者→红；解析字段缺失→无法判定 |
| 输入长度 | D5 | prompt 全量 token 数、字符数、车道占比、是否截断、截断位置 | 样本不同但长度完全相同→该策略对锚点不敏感；只在有锚点时显著变长→说明找回起作用；无锚点也显著变长→疑似常驻摘要无条件注入 |
| 额外调用 | D6 | 每轮 recall/编译调用次数、延迟增量、失败降级路径日志 | 有锚点轮次调用数上升→显式找回路径被触发；所有轮次恒定→可能是无条件调用或未接线；只有失败日志无降级输出→不完整 |

D2 的评分者协议若未建立，按 `ADVERSARIAL-CRITERIA.md` C9 只能标「推理/偏好」，不得进量化结论表。

### 1.5 通过条件的写法：条件式，不写期望值

每条通过条件都写成「若观察到 X，则说明机制 A；若观察到 Y，则说明机制 B；若观察到 Z，则说明机制 C 或数据不足」。
禁止写「预期回复应包含四项需求」「耗时应在 N~M 秒」这类从某次运行抄来的期望值（AGENTS.md「判据里的数字，查一句从哪来的」）。
样本中的 `T+2d`、`Δ₁` 等都是相对时间，不是 Ling 的 TTL/阈值；C8 专门用来防止把间隔当成开关。

### 1.6 负向断言配对总原则（防功能完全没接线时的假绿）

设命题 P = 「策略按锚点区分了续聊与换题」。一次盲评若只断言「问候后不列四项旧需求」，
在功能完全没接线（永远不召回、永远不续旧）时也会绿——这是**假绿**。

强制配对格式：每个负向断言必须同时满足三条：

1. 同一条记录里有一条**正向断言**，且正向断言断言的是「该发生的确实发生了」（如：A1 有锚点时旧方案进了 compiled messages 且回复接上）。
2. 正负断言打**同一个注入点**：用同一条合成历史、同一批 API 参数、同一提示词模板，只改锚点这一因子；否则「正向」可能来自另一条路径。
3. 该判定必须**失败于**「接线未做」这个缺陷：设计者要能回答「如果召回/解析整条链路被删掉，这条判定会红在哪一条断言上」。答不出来就是没有区分力。

反向验伪：若某批盲评在「功能完全没接线」下也能全绿，该批结论无效，必须补一条正向断言后重跑。

## (2) 盲评样本与评分维度

### 2.1 A1–A8 盲评任务卡（每条都给注入点、观测字段、条件式通过条件）

每条任务卡的盲评包必须包含：样本原文（相对时间）、平台消息 id（假值）、`sender_subject_id`、`reply_to`、`mentions`、`created_at`、
同一个旧历史种子、同一提示词模板；只允许改「锚点」这一因子。样本不足时标 `UNKNOWN`，不得用规则推演补齐。

#### A1 · 时隔很久但明确续聊（配对 A2）

- 盲评包：样本 A1（早/接着说前天那个方案，T+2d），历史种子含四条方案；配对 A2 同历史但无锚点。
- 评分维度：D1、D3、D5、D6（D2 不适用）。
- 条件式通过条件：
  - 若 A1 的 compiled messages 出现旧方案原文/带来源的摘要，且回复接方案（提到四条/提醒偏好之一），同时 A2 不续——则说明锚点触发了找回，且没有把无锚点也当续聊。
  - 若 A1 回复接了方案但快照里没有旧方案片段——则说明模型可能凭模板/惯性补全，不能算找回链路生效（需另取召回阶段日志）。
  - 若 A1 快照有旧片段但回复没接——则说明输入层找回成功、生成层未使用，标「部分通过」，不得计为 D3 全绿。
  - 若 A1 与 A2 回复无差别——则说明锚点无区分力（无论都续或都不续）。
- 配对的正向断言：A1 的「旧片段入 prompt + 回复接方案」；负向断言：A2 的「不列四项」。
- 会红的错误实现：只看最近一轮取数（A1 丢旧片段）；召回全关（A1/A2 都不续）；无条件召回（A2 也列四项）。
- 未接线假绿检查：若召回全关，A2 负向断言绿、A1 正向断言红——配对能抓到。若只写 A2 断言则抓不到。

#### A2 · 刚换话题/问候（配对 A1、A4）

- 盲评包：样本 A2（旧历史 + T+3m+4s「早上好」），对照 A1（同历史 + 隔天带锚点续聊）。
- 评分维度：D1、D2、D5、D6。
- 条件式通过条件：
  - 若回复接问候、不列四项旧需求，且快照里旧片段占比不因「早上好」显著上升——则说明问候未触发误召回。
  - 若回复不列四项但也完全没回应问候（如「有什么可以帮你」泛化）——则 D1 绿但 D2 未证明，不能判整体通过。
  - 若快照里旧片段占比与 A1 相同而回复没列——则说明输入层仍被污染，只是生成层没采纳；D1 应红。
- 配对的正向断言：A1 正向「有锚点则续」；负向断言：A2「问候不续」+ 正向断言「A2 回应了问候」。
- 会红的错误实现：宽泛语义召回（列四项）；无条件低信息跳过把 A1 的后续找回也挡掉（见变异 M2）。

#### A3 · 异步引用（配对 A4）

- 盲评包：样本 A3（T+0 四条需求；T+1d Ling 回「群聊引用那条」；T+1d+2h 用户回复→T+0 问「这个后来怎么处理的？」）。
- 评分维度：D1、D3、D4、D5。
- 条件式通过条件：
  - 若 `reply_to` 解析结果指向 T+0 那条、被引用原文进入 compiled messages、回复针对「第三条」——则说明引用被展开且未被相邻气泡覆盖。
  - 若解析结果指向 T+1d 的最近一句、回复谈「群聊引用」——则说明按气泡相邻硬接，红。
  - 若解析正确但回复仍答非所问——则区分「解析层对」与「生成层错」，标部分通过，不可一概判红为「引用没接线」。
- 配对的正向断言：回复针对第三条；负向断言：回复不把「好，我记得是群聊引用那条」当作被引对象。
- 会红的错误实现：按最近消息取 query；把 `[msg_id:…]` 与 `[recall:…]` 两套短号混用导致引用静默失效。

#### A4 · 简单问候

- 盲评包：样本 A4（仅「早上好」，或接在 A1 历史后只发「早上好」）。
- 评分维度：D1、D2、D5、D6。
- 条件式通过条件：
  - 若回复接问候、未召回显著旧事、且显式问候信号在 compiled input 中可见——则说明问候被识别为当前输入。
  - 若「早上好」在规则层被跳过召回但历史窗口的紧邻上一句仍在——这是允许的；若连紧邻上一句也被裁掉，则后续「？」无消歧材料（见 A5）。
- 配对的正向断言：A1 正向；负向断言：A4 不列四项。**必须**再有 A2/A4「回应了问候」的正向断言，否则功能全关时假绿。

#### A5 · 短问号（同句两位置，核心区分力样本）

- 盲评包：位置一 T+2d「早上好」→ T+2d+3s「？」；位置二 T+2d「早上好」→ T+3d「？」。
  同一历史、同一句「？」、同一模板，只改位置与伴随的 `created_at`/紧邻消息。
- 评分维度：D1、D3、D4、D5、D6。
- 条件式通过条件：
  - 若位置一回复指向刚才那句「早上好」（澄清/催 SPP），位置二不把它当位置一处理（明确要求补锚点、或判不可判定、或按当前可见最后一句做小修复）——则说明「？」的解读由上下文位置驱动。
  - 若两位置回复指向同一对象、或都列四项旧需求——则说明用的是固定规则/宽泛召回，C8 红。
  - 若两位置都不进模型（规则层跳过）且回复泛化——则 D6 说明跳过规则生效，但 D3 未证明，不能声称「模型理解了位置差异」。
- 配对的正向断言：位置一「回复指向早上好」；负向断言：两位置「不列四项旧需求」。
- 会红的错误实现：把「？」无条件当记忆检索词；把「？」无条件当 no-op；固定时长阈值（某位置必错）。

#### A6 · 多个相似旧话题

- 盲评包：样本 A6（方案 A/B/C 三个候选，问「上次那个方案，你觉得哪个最急？」）。
- 评分维度：D1、D3、D5。
- 条件式通过条件：
  - 若候选列表在快照中可见且回复表达了锚点不足/给出选择理由——则说明多候选被当作歧义处理。
  - 若回复固定选最早/最显著方案但快照显示三个候选同时存在且无更明确锚点——则说明用了固定偏好，红。
  - 若回复选了一个但候选列表缺失——则无法区分「猜对」与「真的按锚点选」，标 `UNKNOWN`。
- 配对的正向断言：候选列表进入 prompt；负向断言：回复不假装只有一个候选。
- 会红的错误实现：top-1 截断后不传候选列表；把「上次那个方案」当唯一指代。

#### A7 · 群聊交错（含同名变体）

- 盲评包：样本 A7（阿岚/小满/Kiki/老周，两话题并行 + 老周 @Ling 问评审材料）；变体 G-3 用群聊证据文档的样本 3（两个不同 `sender_subject_id` 都显示名「小满」）；变体 G-1 用样本 1（@ 目标不是紧邻说话人）。
- 评分维度：D2、D4、D5、D6。
- 条件式通过条件：
  - 若 `mentions` 解析出老周指向 Ling、逐条说话人字段保留、回复切到评审材料而非午饭——则说明 @ 与说话人身份被用于指人。
  - 若回复接「订四份」午饭话题——则按最近气泡，红。
  - 若两个同显示名的人被合并成一个人、或把 @ 的目标当成说话人——则指人机制红（D4 独立判定，不受 D2 绿影响）。
- 配对的正向断言：回复针对被 @ 的评审问题；负向断言：回复不把午饭话题当当前、不把 @ 目标当说话人。
- 会红的错误实现：按显示名当身份键；按气泡相邻继承说话人；把窗口隔离关掉导致跨群同名话题串入。

#### A8 · 显式换题

- 盲评包：样本 A8（「接着说前天那个方案」后 5 秒「先别说那个，说今天的天气」）。
- 评分维度：D1、D2、D5。
- 条件式通过条件：
  - 若两条消息都进入 compiled input、回复转向天气且不再续方案——则说明换题信号生效。
  - 若只有第一条入 prompt（批合并/截断）而回复转题——则 D2 无法证明，不能算换题逻辑通过。
  - 若两条都入但回复仍续方案——则换题抑制红。
- 配对的正向断言：回复接天气；负向断言：不再列方案四项。
- 会红的错误实现：把换题句当噪声丢掉；只做「不续旧」但没接新话题（D1 绿、D2 红）。

## (3) 变异测试矩阵（半成品必须红）

> 变异对象是**待测的上下文策略**（召回取数、低信息跳过、话题分段/摘要标注），不是业务代码库中的现成实现。
> 本文件不实际修改任何源码；下表给出「构造什么变异 → 哪条判据必须红 → 失败于哪个缺陷」。
> 验收方执行变异时遵守冻结纪律：变异→跑→恢复→sha256 比对→`git status` 确认，逐轮留证，不靠记忆汇总。

### 3.1 三个必须红的半成品

| 编号 | 变异构造（只做一半） | 必须红的判据 | 红在哪个观测点 | 哪个错误实现被它抓住 |
|---|---|---|---|---|
| M1 | **只改最近轮取数，不改摘要**：扩大/优化最近 N 轮取数，让当前输入与近邻消息进 prompt；但旧摘要仍无条件注入、无来源/时间标注、无话题过滤 | A2(C2)、A4(C2)、A8(C7)、A5 位置二(C8) | D1：无锚点的问候轮 compiled messages 里旧方案片段仍出现；D5：各样本 prompt 长度基线不降反升；D2/A8：回复虽转题但旧片段仍常驻 | 「近因取数修好了就行」的错觉；证明常驻摘要是独立的污染路径，不随最近轮取数自动解决 |
| M2 | **只给问候加跳过，不改问号**：把「早上好/早」加入低信息跳过集合，使问候轮不做自动召回；「？」及其位置判定完全不变 | A5 两位置(C3/C8)、A1(C1) | D6：位置一/二的 skip flag 相同、都不进模型；D3：两位置回复无差异（或都泛化）；若「早上好」跳过把 A1 后续的「接着说前天那个方案」也挡掉，C1 红 | 把「问候不误召回」误当成「问号也会自己变聪明」；证明跳过规则与小修复是两件事 |
| M3 | **只加话题分段但旧摘要仍无条件注入**：prompt 里加了「历史/当前输入」「话题 A/B」分段标签，但摘要块依旧每轮无条件带出、无 TTL/话题过滤 | A2(C2)、A5(C8)、A8(C7) | D1：分段标签存在但旧片段仍在无锚点轮出现；D5：分段后长度不降；D2：标签可能让模型更「礼貌」但回复仍带旧事 | 「加个标签就解决了」的形式主义；证明分段本身不等于抑制，必须配摘要条件化 |

补充要求：这三个半成品**每一个都必须红至少一条判据**。若 M1/M3 全绿，说明盲评分维度 D1/D5 没有真正检查输入侧快照；
若 M2 全绿，说明 C8 的两位置配对没有真正执行。变异后别忘了反向检查：正确实现下这些判据应能绿——否则是判据过严而非变异有效。

### 3.2 补充变异（覆盖 D4/负向断言/假绿）

| 编号 | 变异构造 | 必须红的判据 | 红在哪个观测点 |
|---|---|---|---|
| M4 | 把 @ 目标当说话人（mentions 字段被当成 sender） | A7(C6) + G-1 变体 | D4：回复把被 @ 者当成发言者，或错指午饭话题 |
| M5 | 显示名当身份键（两个不同 `sender_subject_id` 的「小满」合并） | A7 G-3 变体(C6) | D4：快照里两条同名消息署名相同，回复自问自答 |
| M6 | 把三态引用可见集合合并成布尔（有 id/无 id 两态，`None` 与 `{}` 不分） | A3(C4) + 群聊证据文档 §4.5 的「引用三态」判据 | D4：无本轮可见 id 时模型仍被宣告「可引用」→ 编造 `[quote:…]` 或静默降级无日志 |
| M7 | 固定时长阈值切话题（例如把 Δ>N 一律当新开场） | A5 两位置(C8) + A1/A2 配对 | D3：A1 带锚点也被判新开场，或 A2 无锚点被续；两位置行为不再随锚点变 |
| M8 | 功能完全没接线（召回/解析/分段全部关掉，模板固定） | **所有**含正向断言的判据 | 正向断言全红；若某批仍全绿，则该批只有负向断言，是假绿 |

### 3.3 变异执行收尾（不可省略）

每轮变异必须留：变异前 sha256 → 变异内容 → 跑出的原始判定 → 恢复后 sha256 → `git status --short` 输出。
「恢复干净了」只在最后一轮结束的那一刻成立；报结果时写明时刻，不写「一直干净」。
本设计文档本身不执行这些变异；执行责任在验收执行方，且被测文件在变异期间冻结。

## (4) 反例与区分力检查

### 4.1 负向断言配对清单（逐条问「功能没接线会不会绿」）

| 判据 | 负向断言（不许出现） | 配对的正向断言（必须同时成立） | 打的是不是同一个注入点 | 未接线时会不会假绿 |
|---|---|---|---|---|
| C1 | A2 不列四项旧需求 | A1 旧片段入 prompt + 回复接方案 | 是（同历史，只改锚点） | 只写负向会假绿；配对后 A1 红 |
| C2 | A2/A4 不因问候列旧事 | A2/A4 确实回应了问候 | 是（同一轮） | 只写负向会假绿；正向抓「全关」 |
| C3 | A5 两位置都不列旧事 | 位置一回复指向「早上好」 | 是（同句同历史） | 只写负向会假绿；位置一正向抓全关 |
| C4 | A3 不把最近一句当被引对象 | 回复针对被引的第三条 | 是（同一 reply_to） | 只写负向会假绿；正向抓引用未解析 |
| C5 | A6 不假装只有一个候选 | 候选列表可见 + 回复给理由 | 是（同一批候选） | 只写负向会假绿 |
| C6 | A7 不接午饭话题、不把 @ 目标当说话人 | 回复针对老周被 @ 的评审问题 | 是（同一群历史） | 只写负向会假绿 |
| C7 | A8 不列方案四项 | 回复接天气、两条消息都入 prompt | 是（同一轮） | 只写负向会假绿 |
| C8 | 两位置都不列旧事 | 两位置回复指向不同对象 | 是（同句改位置） | 只写负向会假绿；差异断言抓固定规则 |

### 4.2 区分力不足处（明确标出，不得靠注释补）

1. **「召回到」与「进了 prompt」**：两者在「回复接了旧事」上相同。必须抓召回阶段结果与 `CompiledContext` 两个快照点，否则不能声称找回链路工作（对应 M1）。
2. **`None` 与 `flag=False` / 三态引用**：`None`（未采集）、`{}`（采集过但无）、非空白名单若压成布尔会静默降级。必须另设 `None` 与 `{}` 两条输入分别观测（对应 M6）。
3. **「模型没接住」与「没送进模型」**：A1/A5 若只有回复没有 skip flag 与 compiled messages，两者不可分；D6 必须记调用次数与 skip 标记。
4. **「换题自然」与「碰巧转题」**：D2 若只有一条样本、一个评分者，按 `ADVERSARIAL-CRITERIA.md` C9 只能是偏好，不是量化结论。至少需要双评分者 + A8 反例（把「先别说那个」换成「那个不错」，若同样抑制续接则说明测的是词不是意图）。
5. **D5 长度的口径**：token 数必须注明是全量 prompt 还是仅车道；单次运行的数字标「复述级（N=1）」，不能写成方案固有属性（C10）。
6. **「误提旧事」的判定口径**：必须区分「错误时间/错误对象/已结束话题被当当前」三类，否则 D1 的分子不可复算（C1）。

### 4.3 竞争性解释（不预设结论，留给回放排序）

`ADVERSARIAL-CRITERIA.md` §10 已列 E1–E6（召回相似度、近因偏置、摘要合成偏置、提示词模板引导、用户真延续、模型惯性）。
本设计的配对样本能提供的区分力：

- A1 vs A2 同历史只改锚点 → 区分「锚点驱动」与「旧片段存在即续」；
- A5 两位置同句 → 区分「时间位置/上下文」与「固定规则」；
- M1/M3 让摘要常驻不变 → 若仍误提，支持 E3/E4；若不再误提，说明 E1/E2 主导；
- 缺的是**空记忆对照组**：要排除 E6（模型自身惯性），必须有一组「无旧片段、无锚点」的回放。本文未取得该数据，标 `UNKNOWN`。

### 4.4 每条判据「能证明什么 / 不能证明什么」速查

- C1：能证明「有锚点时召回链路是否把旧事带入」；不能证明「模型真的记得」或「无锚点也该续」。
- C2：能证明「问候是否触发误召回」；不能证明「所有寒暄都安全」——样本外词表未覆盖。
- C3：能证明「位置一的小修复是否发生」；不能证明「模型理解疑问语气」。
- C4：能证明「引用是否被解析并展开」；不能证明「平台 id 表真实有效」——那是平台能力约束。
- C5：能证明「多候选是否可见」；不能证明「选择策略最优」。
- C6：能证明「@ 与说话人是否分开处理」；不能证明「真人如何读群聊」——证据文档全是合成。
- C7：能证明「换题句是否抑制旧话题」；不能证明「自然度」——需评分者协议。
- C8：能证明「同句在不同位置是否不同处理」；不能证明「固定阈值的具体数值」——本设计拒绝给出该数值。
