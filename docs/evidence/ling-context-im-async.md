# 跨时段的异步续聊：开场、延迟回复与旧话题的记忆支撑

> 本文只做只读研究，不改业务代码。观测对象：HEAD `de43cbe79a78e0c01f7821470500eaa04ea79497`，分支 `main`，开始时 `git status` 为空。
>
> 全文所有对话片段均为**合成样本（synthetic）**，不是真实用户数据。QQ 号一律 `100200300` 形态，内网地址一律 `192.0.2.x`（RFC 5737 文档专用段）；任何消息文本都是为说明机制而编造的。

## (1) 数据性质

### 1.1 三类材料，权威等级不同

| 类别 | 本文里的位置 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| 合成样本（synthetic） | 第 (3) 节，共 8 个 | 说明「在某种消息序列与时间关系下，人**会**怎么解读、错误实现**会**怎么错」；作为回放判据的输入 | 不能当统计；不能证明真人一定这么想，也不能证明 Ling 现在就这么做 |
| 代码路径（本地实测） | 第 (2)、第 (4) 节里注「代码路径」处 | 证明 Ling **当前**取数逻辑长什么样（读的是 HEAD 的工作树） | 不证明模型实际输出；不证明这些逻辑在真实流量里被触发 |
| 外部研究（转述） | 第 (2) 节 2.3，文末 URL | 提供异步通信 / CSCW / 消息界面的概念词汇 | 本文没有拿到 IM 界面经典论文的原文（见第 (5) 节），不得把「据称」写成「已核实」 |

### 1.2 两条不可越过的界限

- **截图只能说明回复表现，真实输入以提示词快照 / 回放为准。** 一张「她回了什么」的截图，既看不到编译后提示词里到底带了哪些历史、摘要与记忆，也看不到查询字符串、候选过滤与窗口归属。判断「模型当时有没有看到前天那段」，只能读**提示词快照里的实际 messages** 与其对应的回放记录；从回复文本倒推输入是猜测，不是证据。本文所有「常见误读」都是对**错误实现**的预测，不是对真实截图里某次回复的归因。
- **不要把人类固定时长当 Ling 参数。** 「隔天」「前天」「几小时后才回」在样本里只是**相对时间关系**（`T`、`T+Δ`），用于区分「同一会话内的续接」与「跨会话的新开场」。本文不由此推出「超过 N 小时就算新话题」「N 分钟后可引用」这类固定阈值；任何数字阈值都必须由真实回放集校准，且平台引用窗口（例如 NapCat 的短 id 表）是**平台能力约束**，不是人类记忆参数。

### 1.3 置信度标记

沿用项目约定：`[实测]`＝有代码路径或快照输出支撑；`[推理]`＝基于 IM 机制的归因，可被反例推翻；`[转述·未核实]`＝引自外部说法但未拿到原文。排版上不把 `[推理]` 和 `[转述]` 写成表格结论，避免用格式冒充置信度。

### 2.2 Ling 当前的取数机制（代码路径，实测）

以下均基于 HEAD 工作树，只陈述代码路径，不评价好坏：

- `src/ling/domains/memory/recall_query.py:6-27`：`_STANDALONE_REPLIES` 含「嗯/哦/好/在吗/你好/hi/hello/ok/thanks…」，`should_skip_automatic_recall()` 对整条消息做 NFKC + 去标点后精确匹配才跳过；「早上好」「？」都**不在**集合里。`needs_recent_topic()` 用 `_TOPIC_FOLLOWUP` 匹配「后来呢/然后呢/哪家/哪一次/几号/原话…」。
- `src/ling/kernel/context.py:1550-1575`：允许长期记忆且不跳过时，用**当前消息原文**调 `_memory.recall()`；只有 `needs_recent_topic` 为真才把「最近一条非寒暄用户消息」拼进 query；`wants_history()` 由 `src/ling/domains/memory/service.py:1814-1818` 的 `HISTORY_QUERY_MARKERS`（「以前/之前/原来/过去/上次说过/曾经/旧地址…」）决定 `include_history`。
- `src/ling/kernel/context.py:1460-1529`：原文层从最新往回按页取，受 `HISTORY_TOKEN_BUDGET`、`HISTORY_FETCH_CAP` 和单条上限约束；`messages_for_prompt()`（`src/ling/domains/conversation/service.py:1302-1356`）只取 `state=completed`、`role in {user,actor}`、未被 `visible_to_model()` 过滤的消息，按 `sequence` 分页。
- `src/ling/kernel/context.py:230-244`：`_window_topic_live()` 只让 `topic/open_questions` 短记忆按 `expires_at` 过期；`summary` 与 `summary_through_sequence` 同处一行但**不判 TTL**，摘要一旦生成就随每轮上下文带出。
- `src/ling/kernel/context.py:1933-1977` 与 `HISTORY_MESSAGE_ID_LIMIT`（`:384`）：只有最近若干条用户消息带 `[msg_id:…]` 可引用标记；更早消息即使出现在原文/摘要里也不可引用。这是**平台短 id 表约束**，不是记忆时效判断。
- `src/ling/kernel/context.py:1768-1788`：历史消息渲染带 `sender` 与 `created_at`（`at` 字段），但时间提示 `_as_local_hint()`（`:168-181`）精度只到分钟；媒体车道另有秒级 `_as_local_hint_seconds()`（`:184-202`）。普通历史文本里**没有独立的日期分隔线/未读气泡渲染**。

## (3) 合成样本目录

> 全部 synthetic。时间列为相对时间：`T` = 某次会话起点；`Δ` 为正的间隔，不赋予固定小时数。「应取」指**人类理想解读**下上下文应覆盖的内容，不等于 Ling 现在一定取到。

### S1 · 隔天纯开场（新会话，不续旧话）

- **消息序列**（synthetic）
  - `T`　用户 100200300：「那个产品方案我列了四项需求」
  - `T+1min`　Ling：「好，我记下了，明天接着聊」
  - `T+Δ₁`　用户 100200300：「早」
  - `T+Δ₁+1min`　用户 100200300：「在吗」
- **时间戳关系**：`Δ₁` 跨夜；两条新消息彼此紧邻，且**无任何时间/话题锚点**。
- **人类理想解读**：「早 / 在吗」是重新建立会话的开场白，不是「四项需求」的续接；「在吗」问的是**对方在不在**，不是问方案。
- **常见误读**：因为历史/摘要里「四项需求」显著且窗口相同，把开场白接到旧话题上，回成「第二项改好了吗」。
- **对 Ling 取数策略的含义**：判据应看**有无锚点**而非间隔长短。可复用低信息跳过（「早」目前不在 `recall_query.py` 的 `_STANDALONE_REPLIES`，是候选缺口）；`[推理]` 首条无锚点时不把旧话题当当前指代对象。

### S2 · 隔天显式找回（合法续旧话）

- **消息序列**（synthetic）
  - `T`（同 S1 的旧话，此处省略重复行）
  - `T+Δ₁`　用户 100200300：「早」
  - `T+Δ₁+2min`　用户 100200300：「接着说前天那个方案」
  - `T+Δ₁+3min`　用户 100200300：「第二项我想改一下」
- **时间戳关系**：与 S1 **同一个 `Δ₁`**；差别只在第二条消息带「前天 + 那个方案」双锚点。
- **人类理想解读**：「接着说前天那个方案」主动回看更早消息，随后「第二项」的先行词就是方案里的第二项——这是显式找回，应取回旧话题。
- **常见误读**：把它当普通寒暄跳过召回，或只取最近一条「早」做 query，导致「第二项」无指代对象。
- **对 Ling 取数策略的含义**：`[实测]` 当前 `wants_history()` 的标记表**不含「前天」「接着说」「那个方案」**；`needs_recent_topic()` 也不含。`[推理]` 可把「时间锚点 + 话题名词」作为显式找回特征，混入查询串并抬高旧话题候选权重；但必须要求锚点完整——若把「接着说前天那个方案」换成「接着说」仍判找回，就说明测的是「接着」二字而非锚点。

### S3 · 看见后延迟回复（回应「刚看到的那条」）

- **消息序列**（synthetic）
  - `T`　Ling：「方案我按四项列好了，你看下」
  - `T+5min`　用户 100200300：「收到」
  - `T+Δ₂`　用户 100200300：「刚看到，第三项能拆成两个吗」
- **时间戳关系**：`Δ₂` 较大；期间该窗口**没有**其他消息，但 `[推理]` 中间可能发生了别的会话活动（回放里若能看到，是「延迟回」的证据）。
- **人类理想解读**：回复指向 `T` 那条「四项方案」，不是指向时间上最近的「收到」——因为内容含「刚看到」元话语 + 第三项细节；「收到」只是中间的一句确认。
- **常见误读**：按「最新一条」取数，把「收到」当被回应的对象，回成「你刚才说收到，什么意思」。
- **对 Ling 取数策略的含义**：`[推理]` 延迟回复的落点应由**元话语锚点（刚看到/回晚了）+ 内容指向的细节**决定，而不是由「最后一条气泡」决定。这与 `needs_recent_topic()` 当前只拼「最近一条用户消息」的方向相反——后者恰好会拼进「收到」。

### S4 · 晚看见 vs 延迟回复（Δt 不可区分）

- **消息序列**（synthetic）
  - `T`　Ling：「方案我按四项列好了，你看下」
  - `T+Δ₂`　用户 100200300：「第三项能拆成两个吗」
- **时间戳关系**：与 S3 **相同的 `Δ₂`**，但**没有**「收到」、也没有「刚看到」。
- **人类理想解读**：**不可判定**。可能是延迟回，也可能是隔了很久才看见；单看时间戳无法区分。
- **常见误读**：拿 Δt 大小直接归因成「她想了一会儿才回」或「她隔天才看见」，并把 `T` 的话题当成刚刚仍在聊的话题。
- **对 Ling 取数策略的含义**：`[推理]` 拿不到「中间活动」或元话语时，标注不可判定，不默认某一解释；不要把固定时长参数化。此样本与 S3 配对，用来证明「Δt 相同但解读不同」，任何只看间隔的判据都会在这对样本上失效。

### S5 · 三种输入分岔：「你还记得前天聊了什么吗」

- **消息序列**（synthetic）
  - `T`　（前天有话题 X 的对话，省略）
  - `T+Δ₁`　用户 100200300：「你还记得前天聊了什么吗」
- **时间戳关系**：跨夜；显式历史询问词「前天 + 记得 + 聊了什么」。
- **人类理想解读**：这是**元问题**，询问助手的记忆，期待回忆并复述 X；它不是在继续 X 本身。
- **常见误读**：把记忆询问当普通寒暄跳过，或当普通语义检索返回一堆相关但非当次话题的记忆；也可能漏掉已关闭的旧值。
- **对 Ling 取数策略的含义**：`[实测]` `wants_history()` 的标记表含「以前/之前/上次说过」但不含「前天」，「记得」也不在；`[推理]` 应让「前天 + 聊了什么 / 还记得吗」进入历史查询路径，并允许命中有效期已结束但仍在保留期内的旧值；同时区分「回答关于记忆的问题」与「续接该话题」两种输出意图。

### S6 · 三种输入分岔：「早上好」

- **消息序列**（synthetic）
  - `T`　（前天有话题 X 的对话，省略）
  - `T+Δ₁`　用户 100200300：「早上好」
- **时间戳关系**：跨夜首条；无锚点、无引用。
- **人类理想解读**：问候，新会话开场；不应接 X。
- **常见误读**：`[实测·代码路径]` 「早上好」**不在** `should_skip_automatic_recall()` 的 `_STANDALONE_REPLIES` 里，也不在 `wants_history()` 标记里 → 会以「早上好」做自动记忆查询；若向量召回把显著旧事 X 拉进来，就会误续接。
- **对 Ling 取数策略的含义**：补「早上好」这类常见问候到跳过集合是**候选缺口**；但要配一条反例（见 S2）：若问候后面紧跟「接着说前天那个方案」，后续轮仍要做显式找回。只加跳过而不给找回留门，会把 S2 一起挡掉。

### S7 · 三种输入分岔：「接着说前天那个方案」

- **消息序列**（synthetic）
  - `T`　用户 100200300：「那个产品方案我列了四项需求」
  - `T+Δ₁`　用户 100200300：「接着说前天那个方案」
- **时间戳关系**：跨夜首条即带双锚点，无前置问候。
- **人类理想解读**：直接续接旧话题，取回四项需求；「接着说」不是寒暄而是续接指令。
- **常见误读**：因它是「隔天首条」就一律判新开场，忽略锚点；或因只匹配「接着」二字而在 S1 的「早」上也误触发。
- **对 Ling 取数策略的含义**：与 S1 配对证明「同是跨夜首条，锚点决定语义」；与 S2 配对证明「有问候不影响后续找回」。判据必须是「时间锚点 + 话题名词」的组合，而不是首条位置或单个词。

### S8 · 界面支架：未读气泡 / 日期分隔线 / 引用回复

- **消息序列**（synthetic）
  - `T-Δ₃`　用户 100200300：「方案第一项写好了」
  - `[日期分隔线：今天]`　（界面元素，非消息）
  - `T`　用户 100200300：「第二项也写好了」
  - `[未读气泡：2 条]`　（界面元素，非消息）
  - `T+Δ₄`　用户 100200300：「引用 > 第二项也写好了 / 这条改成三个」
- **时间戳关系**：跨日；引用块显式指向 `T` 那条，而不是时间上更近的未读计数本身。
- **人类理想解读**：日期分隔线把「昨天」和「今天」切段；未读气泡说明有两条未读、需要补看；引用块把「这条」稳定钉在被引消息上，不受后面又来新消息影响。
- **常见误读**：把未读计数当话题内容；把「这条」指向最新一条而非被引那条；把日期分隔线两边的话当成同一段连续对话。
- **对 Ling 取数策略的含义**：`[实测]` 普通历史渲染只有 `sender + HH:MM`（`_as_local_hint()` 精确到分钟），**没有**独立日期分隔线 / 未读气泡字段；`[实测]` 可引用标记只给最近 `HISTORY_MESSAGE_ID_LIMIT` 条用户消息，旧消息即使被引用也可能拿不到 id（`docs/OUTBOUND-DELIVERY-RESEARCH.md` 记为平台短 id 表约束）。`[推理]` 若接入层能拿到 quoted message 的 id/内容，应把它作为「回应目标」的强证据，优先于时间顺序；但这是**平台能力约束**，不能反推人类记忆也按同样的条数上限遗忘。

## (4) 异步规则建议

> 以下是从合成样本与代码路径推导的判据草案，供回放验证；不是已经上线的行为。每条都写清「能证明什么 / 不能证明什么」。

1. **开场与续接按锚点分，不按 Δt 分。**（S1 vs S2/S7）无时间/话题锚点的跨夜首句判新开场；带「前天/上次 + 名词」或引用/@ 的判显式找回。能证明：两个同 Δt 样本被正确分开。不能证明：真人隔天第一句真的总是开场——这是 `[推理]` 先验，存在约定好继续的反例。
2. **「回应刚看到的那条」由指向证据决定，不由最新气泡决定。**（S3 vs S4）元话语（「刚看到/回晚了」）与被回应的内容细节是强证据；Δt 与「最后一条消息」都不是。能证明：S3 不应指向「收到」。不能证明：在没有元话语的 S4 里判定是延迟回还是晚看见——那应保持不可判定。
3. **「你还记得前天聊了什么吗」「早上好」「接着说前天那个方案」三类输入分三路。**（S5/S6/S7）记忆元问题走历史查询并允许旧值；问候走低信息跳过或轻量开场；续接指令走显式找回并抬高锚定话题权重。能证明：三类文本得到不同处理。不能证明：只靠关键词表能覆盖所有变体——必须留在真实回放集上校准。
4. **短回复的角色由时间位置与锚点共同决定。**（S1/S3）「？」「嗯」在几秒窗内是澄清刚才那句；跨夜且无锚点时应视为新会话的一部分或要求额外锚点。能证明：同一字符在不同位置得到不同处理。不能证明：字符本身的含义——「？」不携带记忆语义。
5. **界面支架是取数线索，不是记忆本身。**（S8）日期分隔线、未读气泡、引用块能帮助人切段与定位，若平台提供应作为「回应目标」的强信号；缺失时降级为不确定，不得用固定条数/固定时长替代。能证明：有引用时指向被引消息。不能证明：平台没给引用时对象就不存在——那只是不可见。
6. **判定「模型是否看到旧话题」只读提示词快照 / 回放。** 快照里出现旧话题且用户消息无锚点，是误续接的直接证据；从截图回复倒推是猜测。能证明：输入与输出之间的因果链。不能证明：模型内部「记得」与否——只能证明它当轮看到了什么。
7. **本项目的具体落点（代码路径实测，非建议已实现）**：补「早上好」到 `_STANDALONE_REPLIES`；为「前天/记得/接着说 + 名词」在 `recall_query.py` 增加显式找回特征；`needs_recent_topic()` 拼上一句时要排除「收到/刚看到」这类元话语误拼（对照 S3）；摘要常驻（`_window_topic_live` 不判 TTL 的部分）应带「这是较早对话摘要，不代表当前话题」的显式标注，避免把旧话题当当前指代。每条都要用变异验证：关掉该判断时对应样本必须变红。
