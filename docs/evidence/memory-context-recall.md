# 简短回复的长期记忆召回

Ling 已经用本轮用户原话查询长期记忆。断言和情节在排序前按受众、来源窗口、保留期和删除状态过滤。召回结合 BM25、可选的向量检索和重排，断言还可通过实体关联匹配。向量开启时，可见候选可以在没有字面命中的情况下参与排序。相对分数下限以榜首为基准，因此「嗯」或「你在吗？」也可能把无关旧事带进对话。

两个参考仓库都以本轮消息为默认查询，并允许低信息轮次跳过长期记忆。两者都给显式记忆请求保留独立的处理路径，并对普通状态询问要求近期、直接相关的证据。Ling 已有按本轮原话查询的入口，本次采用低信息轮次的准入规则。 [qsbb fork 的召回路由](https://github.com/qsbb/astrbot_plugin_memory_companion/blob/0472d46d53e0c72c997386ece406423846e3b149/core/service.py#L10546-L10569) [menglimi 上游的召回路由](https://github.com/menglimi/astrbot_plugin_memory_companion/blob/f6e6e58a2e469f9dcca40fa6f23f6da350527eb2/core/service.py#L11919-L11943)

## 对话中的行为

- 整条消息是空白、常见标点、简单应答、寒暄或在线确认时，对话编译跳过自动证据召回。编译追踪记为 `memory_recall_skipped=low_information`。这类轮次省去记忆查询、向量调用、检索日志和召回强化。
- 「苏州？」和「嗯，你还记得我以前住在杭州吗？」仍用原话查询。历史问题可以读到有效期已结束、且仍在保留期内的旧值。获准检索的候选继续经过现有受众和来源过滤。
- 最近对话、常驻核心记忆和当前环境仍按各自的规则编译。这里使用一组固定的整句匹配，覆盖有限的中英文表达。带话题的混合消息、未列入的寒暄变体和一般性的状态问题仍走常规查询。规则仅根据本轮文本判断，空文本附件也会跳过这一路自动查询。

## 验证

测试使用本地隔离 PostgreSQL，并串行持有 `/tmp/ling-test-database.lock`。向量提供方使用确定性替身。新用例通过真实的上下文编译和数据访问路径，分别检查证据注入、向量调用、召回日志、强化计数和近期对话。直接调用记忆服务查询同样的短文本提供正向对照。短地名和带应答前缀的显式历史请求核对了证据与原话审计查询。群窗口的回归用例分别在来源群和另一群查询相同关键词。

- 基准提交为 `83cf9571aa4c7d08ac2f860196b8910537377fa5`。原有定向基线 53 条通过，1 条已知预期失败。应用改动后的记忆、上下文和受众回归 385 条通过，1 条已知预期失败。使用最终版向量替身重跑新用例和受众快照，共 21 条通过。
- 在隔离副本关闭准入判断，五种低信息输入都重新命中 30 天前的无关记忆，即使查询与记忆的向量余弦相似度为零。将判断替换为长度上限后，「苏州？」回归失败。恢复后逐字节确认上下文文件与交付文件相同。
- 依照交付要求停止全量运行。验收覆盖到上下文和数据库副作用，实际模型回复与独立复核留待后续验证。
