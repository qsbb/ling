## (1) 问题与目标

反例线索（来自 `LEAD-notes.md` §6、`ling-context-human-turns.md` §4，**未获真实快照核实**）：用户先问旧事 → 发「早上好」→ 对问候回「？」，回复却续列很久以前的产品需求。目标是把**当前这轮到底指向哪段上下文**判对，而不是让模型凭相关性去猜。

现状（A，即现有行为；**[代码路径]** 已逐项在 HEAD 核对符号存在）：

- 窗口按聊天目标复用，与话题无关：`bridge.py` 的 `_ensure_window()` / `_find_or_create_window()`。同一聊天目标隔天、换题仍回同一 `Window`。**[推理]**「同一窗口 ≠ 同一话题」是反例的结构性前提。
- 原文层只有一种取数策略：按 `sequence` 从新往旧取到 `HISTORY_TOKEN_BUDGET` 满（`context.py` 的 `messages_for_prompt()` 调用与 `usable` 筛选，`conversation/service.py::messages_for_prompt`）。
- 摘要 `window_ctx.summary` 只要非空就无条件注入（`context.py` 摘要注入段）；`_window_topic_live()` 只让 `topic/open_questions` 短记忆按 `expires_at` 过期，摘要不判 TTL。**[代码路径]** 旧话题一旦进摘要就每轮带出，与当前话题无关。
- 召回 query 只有 `query=user_text`；仅当 `needs_recent_topic()` 命中才拼「最近一条非寒暄用户消息」（`context.py` 召段）。群聊里该拼接额外限定 `sender_subject_id == subject_id`。
- 自动召回准入：`recall_query.py` 的 `_STANDALONE_REPLIES` + `should_skip_automatic_recall()`（NFKC + 去标点后精确匹配）；`_TOPIC_FOLLOWUP` + `needs_recent_topic()`。**[实测]**「？」经归一化后 plain 为空 → 跳过召回；「早上好」不跳过，会以 `query="早上好"` 调 `_memory.recall()`；「后来呢？」命中 `needs_recent_topic`。所以「？触发召回捞出旧需求」这条归因不成立，**旧事来源收敛为摘要常驻、原文窗口、以及「早上好」的宽泛召回（后者是否真命中旧需求未验证）**。
- 入站 `envelope.reply_to` / `mentions_actor` 已存在，目前只喂给「回不回」的决策（`bridge.py` 的 `channel_mentioned` / `replied_to_actor`、`_is_addressed()`），**没有传给 `compile()` 作取数信号**。
- 引用 id 只对最近 `HISTORY_MESSAGE_ID_LIMIT` 条用户消息标 `[msg_id:…]`（`context.py::_message_id_marks()`），更旧的不可引用，这是平台短 id 表约束，不是话题时效。

B 的目标：在**不改窗口模型、不改摘要生成、不新建窗口**的前提下，给当前轮计算一个「指向哪段」的判定，用它调整原文取数、召回 query 与摘要的可见性权重，使「显式锚点能把旧话合法拉回」「无锚点的问候/短问号不误续旧事」「群聊跟对说话人与被引消息」。所有效果必须由提示词快照/回放（而非截图、而非脚本规则推演）验证；未取得真实模型输出前，本文不声称任何行为已被证明正确。

## (2) 信号与取数规则

### 2.1 当前轮信号识别（信号清单）

按 `M0-synthesis.md` 的四类信号，落到可计算的输入特征：

| 信号 | 识别输入（特征来源） | 指向 |
|---|---|---|
| 短问号 / 低信息回复 | `user_text` 归一化后为空或属 `_STANDALONE_REPLIES`；上一句角色/内容；上一句是否构成可确认断言或问候相邻对（Sacks 类框架在此只作结构标注，非定长阈值） | 紧接上一句 → 澄清/催上一句；隔天且无锚点 → 新开场，不续旧话 |
| 简单问候 | 「早上好/早/在吗/你好」等；是否跨天首条；是否紧随带锚点的找回消息 | 新开场或承接问候，不因显著旧事而续接；**但问候后紧跟显式找回时，后续轮仍须能找回** |
| 「后来呢」类承接 | `needs_recent_topic()`（已实测命中「后来呢」）；先行词是否在最近几轮 | 接上一话题/上一句，不构成回看更早的许可 |
| 显式找回 | 时间锚点（前天/上次/那天）+ 话题名词，或元话语（刚看到/回晚了）+ 名词；`wants_history()` 的 `HISTORY_QUERY_MARKERS` 只覆盖一部分，**不覆盖「前天/接着说/那个方案」** | 回看更早消息；要求锚点完整，仅「接着说」不算 |
| 引用 / @ | `envelope.reply_to`（平台消息 id）、`mentions_actor`；本轮可见 `[msg_id:…]` 集合 | 回看被引用那条；@ 只改「对谁说」，不改「谁说的」 |
| 换题指令 | 「先别说那个/不聊这个了/换一个」等显式指令 | 抑制旧话题续接；反例须用「那个不错」对照，否则测的是词不是换题意图 |

**[不足]** 上表的词典/规则覆盖度、锚点完整性的判据都未经中文回放集校准，均为待校准初值。「在线状态/输入中/已读」只有弱先验权重，不作为取数主判据（Kojima 等原文只支持「打字丰富度 ≠ 共在」，且属转述到 IM 的推理）。

### 2.2 取数优先级

**显式锚点 > 时间位置 > 指代距离 > 在线状态**，命中即停（与 `M0-synthesis.md` 一致）：

1. **显式引用 / 被 @**：`reply_to` 或 `mentions_actor` → 展开被引用消息及其邻近上下文。引用目标若落在 `[msg_id:…]` 可引用窗口外，标注「引用目标不可见/悬空」，不静默接最近一条。
2. **显式找回锚点**：时间锚点 + 话题名词，或元话语 + 名词 → 用锚点词定位原文/记忆，纳入目标话题；不依赖向量相似度猜。
3. **承接词**：「后来呢/然后呢/接着/刚/还说是」→ 最近话题/上一句。`needs_recent_topic()` 已部分覆盖；B 把「上一话题」限定在最近几轮内。
4. **时间位置 + 短回复 / 问候**：无锚点的「？」「嗯」「早上好」——紧接上一句则澄清/应答那句；跨天首句且纯开场则新开场；同一句在两种位置必须得到不同处理（C8）。Δt 本身**不可判定**「延迟回 vs 晚看见」，不强行归因。
5. **纯时间邻接兜底**：取最近几轮完整语段，由模型自行判断；**不**把很久以前的话题因相关性接进来。

现状（A）只实现了第 3 条的一部分与第 5 条；第 1、2、4 条是 B 的主要增量点。时间只作为「短回复指向哪一句」的次级信号，不作为「是否续旧话题」的主判据。

### 2.3 规则伪代码（仅示意，不落地）

```
def resolve_target(turn, recent_turns, visible_ids):
    if turn.reply_to in visible_ids:                 # 优先级 1
        return展开(turn.reply_to 及其邻近), mode="quote"
    if 锚点完整(turn.text):                          # 优先级 2：时间/话题/元话语 + 名词
        return 定位(turn.text 的锚点词), mode="explicit_recall"
    if needs_recent_topic(turn.text):                # 优先级 3
        return 最近几轮内上一话题, mode="carry"
    if is_low_info(turn.text) or is_greeting(turn.text):  # 优先级 4
        if 紧接上一句(turn, recent_turns): return 上一句, mode="local_reply"
        if 跨天且无锚点(turn):           return 新开场, mode="new_opening"
    return 最近几轮完整语段, mode="recency_fallback"      # 优先级 5
```

「紧接/跨天」的分档是**待回放校准**的条件式阈值，不写死秒数；「锚点完整」要求时间词与名词共现，「先别说那个」的反例输入必须得到与「那个不错」不同的结果。

## (4) 群聊与旧话题恢复

### 4.1 群聊怎么跟对说话人和被引用的消息

**[代码路径，依据 `ling-context-im-group.md` §2.2]**：四类标识不能互相推导——

- `window_ref` 形如 `<instance>:group:<gid>`，按段解析（第二段必须是 `group`）；不要用 `":group:" in ref`（会把 `onebot:private:group:123` 误判成群）。**群内仍按 `window_id` 隔离取数**：`is_group=True` 不等于「所有群是同一个对话」。
- 内部会话以 `Window.visibility == group_scope` 为唯一权威，`is_group` 是派生值，未知 fail-closed 到非群（`kernel/visibility.py`）。
- 引用：用**本轮真实渲染过的** `[msg_id:<token>]` 作候选；`[quote:…]` 只接受本轮可见 id 表的 token；`None`（未采集）/ `{}`（采集过但无）/ 非空三态不许合并。编造的「消息序号」（如 `[quote:3]`）会被静默降级、正文照发。
- 说话人：键是 `sender_subject_id`，显示名（含群名片）只用于展示；群名片 ≠ 人名昵称时渲染成「名片（人名）」，一人一名；「@」的账号是**目标字段，不是说话人字段**。

规则：**逐条绑定说话人，不继承上一条**；显式引用存在时以引用为准（引用是消息→消息，不是消息→人，被引用的说话人 ≠ 引用者）；无引用时把「回指哪条」标为歧义，不静默取紧邻上一句。`@` 只改变「对谁说」，不改变「这条是谁说的」，也不是「接哪句」的替代品；引用与群/私聊无关，只看本轮有没有可见真实 id。低信息量消息（`？`/`嗯`/`哈哈`）保留原文、不压缩成摘要、不作为长期记忆提炼的事实来源。上述多条的正确性证据来自合成样本的机制推演（回放判据 C6 群聊说话人 / C7 换题抑制所对应的样本），不是人因实测。

### 4.2 旧话题在用户重新提起时如何恢复

**[推理，依据 `ling-context-human-topics.md` 卡片 B/规则 3]**：恢复靠的是「可重识别的旧内容 + 明确的再进入动作」，不是「它还在工作记忆里」。因此：

- 用户用「你上次说的那件事 / 接着说前天那个方案」显式带回 → 直接可接，并让对方知道接的是哪件事；用锚点词定位原文/记忆，命中摘要块只作定位辅助，**引用/细节要求原文时回到原文取数**（摘要≠原文）。
- 没有明说、但旧话题有未完成的承诺/待办或明确未答问题 → 只有 `intents`/承诺表里有具体来源且仍有效时才可主动带回，不编造「你答应过」。
- 「自然重提」（当前情境又提到同一对象）当作当前话题处理，不包装成「我记得你以前说过」。
- 恢复后若模型只回「我记得」，但后续话题并未真正引用该旧内容，按 `ling-context-im-offline.md` 卡片 E4 的方向，这份额外工作被削弱——**恢复必须以取数进入快照为证，不以一句「我记得」为证**。判据：快照里出现锚定话题的原文/证据，回复接住；仅有摘要而用户要求细节时须回原文。

## (5) 成本 / 风险与未验证项

### 5.1 输入长度与额外调用代价（只给定性口径，不给复述式期望值）

**[推理]** B 不新建车道，但会改变各车道的内容与长度：

- 输入长度：显式锚点展开、引用目标邻域、语段优先保住连续气泡，可能使 `compiled` 的 tokens/字符数上升；无锚点轮次降低摘要权重、短回复跳过宽泛召回，可能使其下降。**两个方向都要记录**，上升要查是否挤掉其他车道，下降要查是否漏掉锚点。比较指标 C5 要求给 token 数（全量 prompt）、字符数、是否截断与截断位置；单次运行数字只能标「复述级（N=1）」（比较指标 C10）。
- 额外调用：若锚点召回走 `_memory.recall()` 或新增检索，记录每轮 DB/检索调用次数、延迟增量与失败降级路径。次数不变＝改造落在现有取数内；次数上升＝分别记在哪种信号上，判断是否值得。「零额外调用」不是目标（比较指标 C6）。
- 不把论文里的任何固定时长/容量当这里的预算；预算来自 `HISTORY_TOKEN_BUDGET` 等工程常量与回放观测。

### 5.2 风险与半成品（比较判据 A1：半成品必须红）

- **只做信号识别、不改取数**：能标出 mode，但原文/摘要/query 不变 → 无锚点问候仍带旧摘要，误提旧事不会下降，半案失败。
- **只加召回、不做优先级**：宽泛召回会把旧事拉进来，反而放大误续；必须配「显式锚点 > 时间位置」的门与反例。
- **只加跳过、不给找回留门**：把「早上好」加进 `_STANDALONE_REPLIES` 会挡掉 S2「早上好 → 接着说前天那个方案」的后续找回；跳过与找回必须成对设计。
- **只做引用展开、不做窗口隔离**：跨窗 id 被当成可见，引用错窗消息（C4）。
- **只改 `compile()`、不接 `reply_to`**：引用信号进不了取数，群聊仍按气泡相邻接错句。

以上半案必须在验收时构造并确认对应判据变红；全绿而无变异不足以证明测到了东西。

### 5.3 判据 C1–C8 的证明力（引用 `ling-context-replay-samples.md`，先看判据再看实现）

> 编号口径：本节的 C1–C8 指 `ling-context-replay-samples.md` 的八条回放判据（C1 显式找回、C2 问候不误召回、C3 短问号定位、C4 异步引用、C5 多候选、C6 群聊说话人、C7 换题抑制、C8 条件式时间）。`ADVERSARIAL-CRITERIA.md` 里另有一套同名的 A/B/C 方案比较指标（C1 误提旧事、C2 换题自然度……C8 反例输入），两套编号不要混用；涉及比较指标时本文写全名（如「比较指标 C5 输入长度」）。

| 判据 | B 能证明什么（若回放通过） | 不能证明什么 |
|---|---|---|
| C1 显式找回（A1） | 锚点召回路径能把旧方案原文/摘要带进快照且回复接方案；关掉锚点识别会红 | 不能证明摘要常驻本身是问题；不能证明「早上好」的宽泛召回命中了什么（需单独看 `memory_hits`） |
| C2 问候不误召回（A2、A4） | 问候轮不因宽泛语义召回而列旧需求；对比 A1 证明锚点在起作用 | 不能证明真人隔天第一句总是开场（存在约定续聊的反例）；不能区分「摘要常驻带出」与「召回命中」——需配 `lane="summary"` 与 `evidence_selected` 分别计数（LEAD-notes §6.5） |
| C3 短问号定位（A5 位置一） | 紧接问候的「？」澄清上一句；与 A5 位置二成对时证明时间位置在起作用 | 不能证明「？」携带记忆语义（实测 plain 为空）；不能给出固定秒数阈值（C8） |
| C4 异步引用（A3） | 展开被引用的「第三条」，回复针对它；按气泡相邻的错误实现会红 | 不能证明引用目标在可引用窗口外时系统能找回——那是悬空降级路径，须另测 |
| C5 多候选（A6） | 多个「方案」时优先最明确锚点，或显式表明不确定 | 不能证明固定取最显著/最早一定错（需构造锚点相反的输入）；「不确定」是否算合格只能人工标注 |
| C6 群聊说话人（A7） | 跟对 @Ling 的老周，不被午饭话题带走 | 不能证明用户侧 QQ 引用/@ 的界面语义（未取得官方文档原文）；同名不同人需另配样本（`ling-context-im-group.md` 样本 3） |
| C7 换题抑制（A8） | 「先别说那个」后停止旧话题续接 | 不能证明「那个不错」等近似句不会被误抑制——须配反例，否则测的是词不是换题意图 |
| C8 条件式时间（A5 两位置） | 同一「？」在不同位置解读不同；固定时长阈值的实现必然一处错 | 不能给出任何具体秒数；不能区分「延迟回 vs 晚看见」（`ling-context-im-async.md` S4 本来就是不可判定） |

证据纪律：关于「模型看到什么/输出什么」必须以提示词快照与回放为准（ADVERSARIAL-CRITERIA V1/V2）；未调用模型、只用规则推演的结果标 `SCRIPTED`，不得冒充真实输出（`ling-context-replay-samples.md`）。合成样本只能说明「哪种线索组合下会产生歧义」，不能替代真人实验。

## (6) 与 A / C 的取舍

**A = 对照现有行为**（不是「什么都不做的方案」的简称）：保留现有取数路径作为基线，用于配对回放。A 的价值是提供「同一历史、同一模型、只改当前消息/只改取数策略」的差分；没有 A，B 的任何收益都无法归因（比较指标 C7）。A 的成本为零改造，但保留了 §1 列出的误续风险。**B 的成本/收益**：收益是把显式锚点、问候、引用等当前轮信号接进取数，直接针对 C1/C3/C4/C6/C7；成本是新增信号识别与可能的额外检索、输入长度变化、以及多组反例/变异验收的工作量。**若 A 在回放里已经足够好**（误提旧事、漏续聊、指错人都为零且成本更低），B 不值得做——这是回放后才能下的结论，本文不预设。

**C = 更明确的上下文分段**（本方案不评估 C 本身）：C 指的是把同一聊天目标里的多条稳定话题簇显式切成段/分窗，而非在现有窗口内做取数重排。边界：

- B 只改「当前轮取哪段」，**不新建窗口、不改窗口复用规则、不改摘要生成**；C 才动上下文的分段结构。
- B 的默认答案是不分窗：同一聊天目标里「隔天续聊」与「几秒内换题」必须靠时间位置/锚点区分，分窗会把两者都拆开，反而丢掉判断所需信号（`bridge.py::_ensure_window` 的复用语义）。
- 只有回放显示**同一聊天目标里长期存在多条稳定话题簇、且 B 之后误续聊率仍显著高于分窗**时，才值得评估 C。所需数据：①话题边界与误续/漏续人工标注；②每条入站消息的 `reply_to`/锚点/时间位置特征分布；③同源句子在分段前后的快照与回复对照（`P3-lightweight.md` §5）。**[不足]** 这些数据当前未提供，因此本文不能从「模型接错了」反推「必须分段」。
- 比较指标 C7 自问：若 A/B/C 在比较指标 C1–C6 上完全相同，比较就退化为偏好陈述。B 与 A 的区分力在于**同一句「？」/同一段旧史、只改锚点或只改取数策略**的配对回放；B 与 C 的区分力在于**同一窗口内改取数 vs 改分段结构**的对照，后者缺数据时不得下结论。
