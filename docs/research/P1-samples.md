> 本文是**合成情境研究**，不含任何真实用户数据。所有 QQ 号 `100200300` 段、
> 地址 `192.0.2.x` 段均为文档占位。示例消息均为作者构造，不是从日志摘取。

## 0. 先写判据：什么算「能区分错误实现」

这一节在查看任何候选方案代码之前写完。每条判据都回答同一个问题：
**「哪个错误实现会让这条红？」** 答不出来的条目已经删掉，没有留在本文里。

### 0.1 判据的三条硬要求

1. **条件式，不复述式。** 不写「期望 X」，写「若出现 A → 说明机制 1；若出现 B →
   说明机制 2；若出现 C → 说明机制 3」。数字只作为构造输入时的刻度，不作为
   「通过/失败」的阈值。
2. **每个断言配反例输入。** 对每条判据问：把输入里那个触发条件换掉，正确实现
   是否应当改变行为？若正确实现在反例输入上**也**给出同样结果，这条断言没有
   区分力，必须换输入或删掉。
3. **区分力靠配对，不靠单样本。** 单一样本上的「对」只能证明「没红」；要证明
   「取的是 A 信号而不是 B 信号」，必须构造 A/B 相反、其余相同的两个样本，
   要求正确实现给出**不同**结果。

### 0.2 判据总表（先看这张，再看任何样本）

下面每一条都对应第 1 节的样本编号。表里只写「能证明什么」，不写「应该输出什么
具体内容」——具体回复措辞是模型的自由，不是判据。

| 编号 | 判据（条件式） | 哪个错误实现会红 | 反例输入（必须同样跑一遍） |
|---|---|---|---|
| J1 | 输入含**显式找回锚点**（「前天那个方案」）+ 历史里有多个旧话题时：回复所指对象 = 锚点命中的话题，**不是**「最近一条话题」。若回复接的是最近话题 → 实现只用「最后 N 条」而没做锚点匹配；若回复把两个话题混提 → 实现没做话题边界。 | 只按时间近邻取上下文；没有话题索引 | 把锚点换成「刚才那个」，同一历史 → 正确实现应转向最近话题；若仍指向前天 → 实现把「找回」和「续接」当成同一逻辑 |
| J2 | **同样的句子**（「早上好」）在两组输入里必须产出**可区分**的回复对象：A 组（隔天，前一轮有明确未完结话题 + 本句带「昨天那个…」）指向旧话题，B 组（几秒内，上一句是完整结束语 / 已换题）不指向旧话题。若两组指向同一对象 → 实现只看了句子字面，没看时间/锚点/话题状态。 | 关键词触发（见到「早上好」就当新开场，或见到旧话题就一律续接） | 把 B 组的间隔拉长但**去掉**未完结信号 → 正确实现仍不应续旧话题；若续了 → 实现把「间隔长」直接当「续聊」（时间阈值硬编码） |
| J3 | 输入含**引用旧气泡**（消息 id 指向 N 条以前的某条）时：回复所指对象 = 被引用那条，**不是**时间上最近的一条。若引用被忽略、回复按最近一条理解 → 实现丢弃了引用标记或未把它接进上下文。 | 只取最近 N 条、不解析 `[msg_id:]`/reply_to | 把引用的 id 改为**指向最近一条**、旧话保留但不再被引用 → 正确实现应改指最近一条；若仍指旧话 → 实现把「历史里存在某句话」当成「用户在引用它」 |
| J4 | 简单问候（「你好」）且历史**无**未完结话题时：回复不主动提起任何旧话题细节。若凭空续旧话 → 实现在问候类输入上错误触发了话题续接。 | 一律把全量历史塞进提示词并要求模型「接着聊」 | 在历史里放一个**明显已完结**的话题（「好的，就这样」），同样输入 → 正确实现仍不续；若续了 → 实现没区分完结/未完结 |
| J5 | 短问号「？」单独成句时：所指对象 = **紧邻前一句**（几秒窗）或被引用句；若回复去解释更早的旧话题 → 实现把「？」当成通用追问、忽略了即时锚定。 | 把「？」当「继续讲」的硬编码指令 | 把「？」换成完整问句「你说的方案是哪个？」 → 正确实现应改用显式指代消歧；若行为不变 → 实现没区分有内容/无内容问句 |
| J6 | 多个**相似**旧话题（两条都说「方案」，仅主题词/时间锚点不同）时：回复必须**消歧到锚点指定的那一条**，且**不把另一条的细节串进来**。若两条细节混杂 → 实现做了相似度Top-1但没做锚点过滤；若总是取较新一条 → 实现只按时间排序。 | 纯向量相似度检索、无锚点约束 | 交换两条话题的**新旧顺序**，锚点不变 → 正确实现应仍指同一主题；若跟着新旧变 → 实现是靠时间近邻而非锚点 |
| J7 | 群聊交错：两条话题并行 + 一条 `@` 或引用**跳回旧话**时：(a) 回复对象 = 被 @ / 被引用的人或那条旧话；(b) 说话人名字不串（不把 A 的话安到 B 头上）；(c) 关闭 @ / 引用后回复回到最近话题。若 (a)(c) 不随开关变化 → 实现忽略了群聊的显式指向信号。 | 把群聊当单时间线、只看最近消息 | 把 @ 去掉、保持其他全部相同 → 正确实现应回到最近话题；若仍指旧话 → 实现把「历史里有那个人说过话」当成「被 @ 了」 |

### 0.3 覆盖层面的两条元判据

这两条不是单条样本能验的，是对**整套样本集**的要求：

- **M1（半成品必须红）**：把任意候选实现拆成两半——「只做时间/近邻取数」和「只做
  锚点/引用解析」——分别在样本集上跑，必须各自至少红一条。若两个半成品全绿，
  说明样本集只覆盖了「两个机制给出相同结果」的输入，整套样本无区分力。
  **[推理]** 这一条需要实际跑过候选实现才能判定；本轮未跑，状态**未取得数据**。
- **M2（语义不同必须可区分）**：若某实现声称「引用缺失」与「引用指向空」在语义上
  不同，样本集中必须有输入使二者产出**不同**的可观察结果（例如 prompt 里
  `[msg_id:]` 出现 vs 不出现）。若无论如何都同结果，这条「语义不同」只是注释。

### 0.4 判据能力的诚实边界（先写，避免事后归因）

- 本样本集判的是**上下文取数与话题指向**，不是中文生成质量、不是语气是否自然。
- 判断「回复指向哪个话题」需要人工或独立判定器给回复打标签；本文只定义标签的
  判定口径（回复中出现的主题词、指代对象、是否复述旧话细节），**不声称已经判过**。
- 时间信息在 prompt 快照里**不可直接观察**：[观测] 历史 user/assistant 消息在
  `context.py:1732-1789` 只加 `[msg_id:]` 与说话人前缀，`at` 只写进 `annotated`
  元信息（`context.py:1787`），进不了 `messages`；唯一可见时间是全局环境事实
  「此刻：…」（`env_facts.py:184`）。因此「隔天 vs 几秒」在**真实模型输入**层面
  只能靠用户原话的显式锚点（「前天」「刚才」）与话题内容区分，不能靠消息时间戳。
  这一事实直接决定了第 2 节配对实验的构造方式。

## 1. 七类最小中文回放样本

### 样本格式约定

每条消息写成：

```
[相对时间] 说话人: 文本   （引用: idX | 群聊: 是/否）
```

- **相对时间**是构造输入用的刻度（`t0` 为序列首条），不假设模型能看见它：
  如上节所述，历史消息本身不带时间戳，只有全局「此刻」可见。所以样本刻意让
  用户**原话携带锚点**（「前天」「刚才」），使区分信号真实存在于模型输入里。
- **引用**表示平台 `reply_to` / `[msg_id:]` 指向的历史消息 id。
- 每条样本给出：完整序列、用户最后一句、期望行为、错误行为示例、对应判据、
  以及「哪个错误实现会红」。

---

### ① 时隔很久却明确续聊（J1）

**场景**：私聊；单窗口；只有一条时间线。

```
[t0-72h]   用户100200300: 前两天说的那个日程方案，我整理了三版
[t0-72h+1m] 助手: 好，三版都记下了，你要发的时候叫我
[t0-71h]   用户100200300: 第一版偏保守，第二版我把预算砍了
[t0-71h+1m] 助手: 收到，第二版是砍预算那版
[t0-30m]   用户100200300: 顺手问下，周末那家咖啡店还开着吗
[t0-29m]   助手: 我这边没有实时营业信息，你看看地图
[t0]       用户100200300: 接着说前天那个方案
```

- **用户最后一句**：「接着说前天那个方案」
- **期望行为**：接的是「日程方案/三版」（t0-72h 的那串），不是「咖啡店」（最近话题）。
  可提「第二版砍预算」等已给细节。
- **错误行为示例**：
  - E1a：回「那家店……」→ 只用了最近话题。
  - E1b：同时讲三版方案和咖啡店 → 没做话题边界。
  - E1c：回「哪个方案？」→ 锚点匹配失败（有明确「前天」却当无指代）。
- **能区分的判据**：J1。若回复指咖啡店 → 近邻取数错误实现红；若混提两话题 →
  无话题边界错误实现红。
- **反例输入**：把最后一句换成「接着说刚才那个」（锚点指向最近），同一历史。
  正确实现应转指咖啡店；若仍指三版方案 → 实现把「找回」和「续接」当成同一逻辑。

### ② 刚换话题：同句「早上好」的两种语境（J2，核心配对）

这是任务 2 的**核心取舍实验**，完整设计见第 2 节。这里先列两个样本的成员。

**②-A 隔天仍在续聊**

```
[t0-26h]   用户100200300: 那个迁移方案我只写了骨架，明天接着补
[t0-26h+1m] 助手: 好，骨架先放着，明天等你
[t0-25h]   用户100200300: 对了，里面那块权限我还没定
[t0-25h+1m] 助手: 权限那块等你定了再说
[t0]       用户100200300: 早上好
[t0+3s]    用户100200300: 昨天那个迁移方案，权限那块我们定一下
```

- **用户最后一句**：「昨天那个迁移方案，权限那块我们定一下」（第二句才是锚点句，
  第一句「早上好」是开场）
- **期望行为**：续迁移方案的权限话题。
- **错误行为示例**：只回「早上好呀」完全不接权限；或把「权限」当成全新话题。
- **能区分的判据**：J2-A 半条（锚点在，必须续旧）。

**②-B 几秒内已经换题**

```
[t0-8s]    用户100200300: 那个迁移方案我写完了，就这样定了
[t0-7s]    助手: 好，那这事就收尾了
[t0-3s]    用户100200300: 早上好
[t0]       用户100200300: ？
```

- **用户最后一句**：「？」
- **期望行为**：指向「刚才那句」的语境——即刚打完招呼、对方在等回应；**不**续
  已收尾的迁移方案。
- **错误行为示例**：回迁移方案细节（把收尾话题又续起来）；或复述「早安」当问候
  （没处理紧跟的「？」）。
- **能区分的判据**：J2-B 半条 + J5。
- **配对要点**：A/B 都出现「早上好」，但 A 有「昨天那个…权限」显式找回锚点、
  旧话题**未完结**；B 的旧话题有「就这样定了/收尾了」**完结标记**、无找回锚点。
  若实现对 A/B 给出同类回复，则是关键词触发实现（J2 红）。

### ③ 异步引用：引用/回复旧气泡（J3）

**场景**：私聊；引用一条 5 条以前的旧消息。

```
[t0-2h]     用户100200300: 上次说的食谱我改了，少放了糖   （id: m100200301）
[t0-2h+1m]  助手: 好，少糖版记下了
[t0-1h]     用户100200300: 对了你周末有空吗
[t0-1h+1m]  助手: 周末我这边看情况，你有什么安排
[t0-30m]    用户100200300: 另外那个书单也更新了
[t0-29m]    助手: 书单更新收到
[t0]        用户100200300: 就按这个再给我一份   （引用: m100200301）
```

- **用户最后一句**：「就按这个再给我一份」（`reply_to=m100200301`，指向 2 小时前的
  「少糖食谱」）
- **期望行为**：给的是**少糖食谱**的另一份，不是最近的书单或周末安排。
- **错误行为示例**：回书单（最近话题）；回「哪个？」）；忽略引用当普通追问。
- **能区分的判据**：J3。若忽略引用 → 近邻取数红。
- **反例输入**：把 `reply_to` 改成指向最近一条书单消息，历史不变。正确实现应改指
  书单；若仍指食谱 → 实现把「历史里存在食谱」当成「用户在引用食谱」。
- **可观测落点**：[观测] 历史消息在 `context.py:1768-1770` 会被加上
  `[msg_id:<token>]`（仅最近 12 条，`HISTORY_MESSAGE_ID_LIMIT=12` at
  `context.py:384`）；当前句也带 `current_mark`（`context.py:1837-1838`）。
  样本里被引用消息距末尾 5 条，在 12 条限额内——若把距离拉到 >12 条，正确实现
  应当**没有可用 id 可引**，行为应变化；这是 J3 的天然边界输入。

### ④ 简单问候（J4）

**场景**：私聊；历史里有一个**已完结**话题。

```
[t0-3h]   用户100200300: 上次那个报销单我交了
[t0-3h+1m] 助手: 好，交了就行
[t0-2h]   用户100200300: 嗯，没事了
[t0-2h+1m] 助手: 好
[t0]      用户100200300: 你好
```

- **用户最后一句**：「你好」
- **期望行为**：打招呼即可，不主动提报销单。
- **错误行为示例**：回「报销单交得怎么样了」→ 把完结话题又续起来。
- **能区分的判据**：J4。若续旧话 → 「一律把全量历史塞进去要求接着聊」红。
- **反例输入**：在历史里换成一个**未完结**话题（「报销单我还没弄完，回头说」），
  同样输入「你好」。正确实现仍不续（问候本身无锚点）；若这时才续 → 实现把
  「历史有未完结话题」当成「本句要续它」，缺少「必须有锚点」的前提。

### ⑤ 短问号「？」（J5）

**场景**：私聊；紧跟在一句问候后，且有更早的旧话题存在。

```
[t0-1d]   用户100200300: 昨天那个海报配色我再想想
[t0-1d+1m] 助手: 好，等你定了告诉我
[t0-6s]   用户100200300: 早
[t0]      用户100200300: ？
```

- **用户最后一句**：「？」
- **期望行为**：回应的对象是「刚才那句『早』」——即对方在等一个回应；**不是**去
  解释海报配色。
- **错误行为示例**：回配色方案；或只回「？」（没处理即时语境）。
- **能区分的判据**：J5。若回旧话题 → 把「？」当通用追问的实现红。
- **反例输入**：把「？」换成有内容的问句「海报配色想好了吗？」。正确实现应改用
  显式指代消歧到海报；若行为与「？」完全相同 → 实现没区分有内容/无内容问句。
- **与 ②-B 的关系**：②-B 同样以「？」结尾，但那里旧话题是**已完结**的；本节旧
  话题**未完结**。两条合起来能判「？」是否只在有未完结话题时才误锚定。

### ⑥ 多个相似旧话题：区分指哪一个（J6）

**场景**：私聊；两条都说「方案」，主题词不同（预算 vs 人员），时间一小一大。

```
[t0-3d]   用户100200300: 我那个预算方案刚起了头，还没细化   （话题X）
[t0-3d+1m] 助手: 好，预算方案先放着
[t0-1h]   用户100200300: 人员方案里我想把面试流程改一下   （话题Y）
[t0-1h+1m] 助手: 收到，人员方案改面试流程
[t0]      用户100200300: 接着说前天那个方案
```

- **用户最后一句**：「接着说前天那个方案」
- **期望行为**：指**话题X（预算方案）**，因为锚点「前天」与 X 的时间吻合；Y 是
  1 小时前，且回复里不应混入「面试流程」细节。
- **错误行为示例**：
  - E6a：回「面试流程……」（取了最近/相似度更高的 Y）→ 时间近邻红。
  - E6b：既说预算又说面试流程 → 没做锚点过滤的 Top-N 混排红。
- **能区分的判据**：J6。
- **反例输入**：交换 X/Y 的新旧顺序（预算方案变成 1 小时前、人员方案变成前天），
  锚点「前天那个方案」不变。正确实现应改指**人员方案**；若仍指预算 → 实现是靠
  「方案」这个词本身的固定联想或时间近邻，而不是靠锚点匹配。这条反例是 J6 的

## 2. 核心配对实验：同一句「早上好」的两种语境

### 2.1 为什么要配对而不是分别看

单独看 ②-A 或 ②-B，任何实现都可能「碰巧对」：一个总是续旧话的实现在 A 上通过，
一个总是当新开场的实现在 B 上通过。**只有把两者放进同一次实验、要求同一实现在
两句相同的输入上给出不同指向，才能证明它真的用了「锚点/完结状态」而不是句子
字面或固定策略。** 这正是 AGENTS.md「区分力」与「三态字段要三条」的直接应用。

### 2.2 配对表（其余变量尽量对齐）

| 变量 | ②-A 隔天续聊 | ②-B 几秒换题 |
|---|---|---|
| 触发句 | 「早上好」 | 「早上好」 |
| 后接句 | 「昨天那个迁移方案，权限那块我们定一下」 | 「？」 |
| 旧话题状态 | 未完结（「明天接着补」「权限还没定」） | 已完结（「写完了」「就这样定了」「收尾了」） |
| 显式锚点 | 有（「昨天那个…权限」） | 无 |
| 距旧话题 | 约 26 小时 | 约 8 秒 |
| 历史里旧话题存在 | 是 | 是 |

**控制变量说明**：两组都用「迁移方案」这个旧话题，都保留「早上好」这句开场，
都让旧话题出现在历史里。唯一系统差异是**锚点有无 + 完结状态 + 时间间隔**。
若实现只看句子字面（「早上好」→新开场，或旧话题存在→续接），两组必然同类回复。

### 2.3 条件式判据（不是期望值）

对同一实现的输出按「回复所指对象」分类：

- **A→旧话题、B→不续旧话题**：说明实现消费了「显式锚点 / 完结状态」这组信号。
  这是**唯一**算通过的象限。
- **A→旧、B→旧**（一律续旧）：实现只用了「历史里有未完结/有旧话题」或「最后 N 条
  里有相关内容」，忽略了完结标记与锚点缺失。
- **A→新、B→新**（一律当新开场）：实现被「早上好」字面触发，或把长间隔直接当
  换题、短间隔直接当续聊的反向硬编码。
- **A→新、B→旧**（完全反了）：实现把「隔天」当换题、「几秒」当续聊，时间信号
  接反；或错误地把「？」当续旧话题指令。

**为什么这四种结果都有信息量**：它们分别指向「锚点消费 / 历史存在触发 / 字面
触发 / 信号接反」四种不同机制，不是「对/错」两分。即便结果落在不通过象限，实验
也产出了「是哪类错误」的结论。

**反例输入（验证判据本身有区分力）**：

1. 把 B 组的间隔从 8 秒拉长到 26 小时，但**保留**「已完结」标记、**去掉**任何
   找回锚点。正确实现仍应**不续**旧话题。若续了 → 实现用「时间间隔长短」直接
   当续聊开关（时间阈值硬编码），这正是本实验要排除的错误实现。
2. 把 A 组的「昨天那个迁移方案，权限那块我们定一下」改成只有「早上好」（去掉
   锚点），保留未完结状态与 26 小时间隔。正确实现应**不**续旧话题（无锚点不该
   猜）。若仍续 → 实现把「间隔长 + 未完结」当充分条件，缺少「必须有显式锚点」
   的约束。

这两条反例把 J2 从「隔天/几秒的对比」升级为「锚点 vs 时间 vs 完结状态」的三因素
实验——任何只靠单一因素的实现都会在某个反例上红。

### 2.4 本实验的已知限制（先写，防止事后归因）

- **[观测]** 历史消息在 prompt 里没有时间戳（见 0.4），所以「26 小时 vs 8 秒」
  这个差异**不直接存在于真实模型输入**里，只存在于脚本构造的输入元数据中。
  模型若要区分 A/B，依据的是**用户原话里的「昨天那个…」与「已完结」措辞**，
  不是数值化的时间间隔。
- 因此本实验判的是「实现是否把锚点/完结状态接进上下文并让模型可用」，不是
  「模型是否真的会读时间戳」。若候选实现声称「靠时间衰减判断续聊」，本样本集
  **无法验证该声称**——需要先让时间进入 prompt（改动观测对象），那是另一个任务。
- 本轮**未运行**该实验，无真实输出，状态：**未取得数据**。
