# M3 · 跨时段异步续聊：隔天开场、看见后延迟回复、旧话被重新带回来的信号

> 合成情境研究，无真实用户数据。QQ 号一律 `100200300` 形态，内网地址 `192.0.2.x`。
> 截图只说明表现，判定以提示词快照与回放为准。
>
> 置信度：**[观测]** 快照/回放可直接看到；**[推理]** 基于 IM 机制的归因，可被反例推翻。

---

## 0. 本方向要解释的核心问题

反例里的「前天聊了什么 → 早上好 → ？」跨越了时段。「？」到底是在问**刚才那句
问候**，还是在**续前天的话题**？人能区分，是因为有一组信号；模型若只按
「相关性」检索，就会把前天的四项需求捞回来接上。

本方向给出这组信号，并明确哪些**不可区分**，必须靠额外证据。

---

## ① 研究 / 观察情境

### S3.1 隔天开场

隔天第一句话通常是**重新建立会话**的动作，而非昨天话题的延续。

**合成情境 D（隔天纯开场）**

```
[前天 22:14] 用户 100200300: 那个产品方案我列了四项需求
[Ling 前天 22:15]: 好，我记下了，明天接着聊
[今天 08:02] 用户 100200300: 早
[今天 08:03] 用户 100200300: 在吗
```

「早」「在吗」是开场白，不是「四项需求」的续接。若上下文把前天对话整段带进来，
模型容易把开场白误接到旧话题——这正是反例的一步。

**合成情境 E（隔天显式找回）**

```
[今天 08:02] 用户 100200300: 早
[今天 08:04] 用户 100200300: 接着说前天那个方案
[今天 08:05] 用户 100200300: 第二项我想改一下
```

这里「接着说前天那个方案」是**显式找回**：带时间锚点（「前天」）+ 话题锚点
（「那个方案」）。它和 D 的差别不在间隔，而在**有没有找回标记**。

### S3.2 看见后延迟回复

人可能看见消息后不当场回，几小时后才回。此时那条消息在界面上仍是「最后一条」，
但对人已经是旧话。**Δt 本身不能区分「延迟回复」与「隔了很久才看见」**：
两者在时间戳上完全一致。需要额外信号：

- 中间是否 Insert 了其他会话活动（说明人一直在线，是延迟回）；
- 回复内容是否引用原话细节（说明确实看过）；
- 是否带「刚看到」「抱歉回晚了」元话语（显式延迟标记）。

### S3.3 旧话被重新带回来的三种方式

| 方式 | 触发文本 | 性质 |
| --- | --- | --- |
| 显式找回 | 「接着说前天那个方案」「上次你说的 X」 | 主动回看更早消息，强信号 |
| 引用/@ | 引用块或 @ 指向旧消息 | 显式指针，强信号（群聊尤甚，见 M2） |
| 隐式回指 | 「那个」「第二项」「还是之前那个」 | 需结合窗口判断，弱信号 |

**反例里最危险的是第三种被误用**：用户回「？」时，既没有找回词，也没有引用，
模型却把很久以前的四项需求当成「那个」的指代对象。

## ② 可观察行为（可写成回放判据）

**B3.1 隔天开场 vs 显式找回**
- [观测] 会话间时间断档后第一条入站消息。
- 判据：若首条为纯开场（「早」「在吗」「睡了吗」）且无时间/话题锚点 → 判为
  **新开场**，不应续接旧话题；若首条或紧接班带「前天/上次/那天 + 名词」→
  判为**显式找回**，应把锚定话题纳入取数。
- 区分力：两种输入的 Δt 相同、首条都可能是短句。必须用**有无锚点**区分，
  不能用间隔长短。反例：把 E 的「接着说前天那个方案」换成「接着说」，若判据
  仍判找回，说明它测的是「接着」这个词而非「锚点完整」。

**B3.2 延迟回复的不可区分性**
- [观测] 我方发出 → 对方入站的 Δt 较大。
- 条件式：Δt 大 → 存在两种解释（延迟回 / 晚看见）；**单靠 Δt 不可判定**。
  若回放里有「中间其他会话活动」或对方文本含「刚看到/回晚了」→ 倾向延迟回；
  否则保持不可判定，不强行归因。
- 反例输入：同一段 Δt 配上「刚看到，回你前天那个」——此时有元话语锚点，
  应判为延迟回 + 显式找回，而非纯开场。

**B3.3 短回复的时间依赖角色**
- [观测] 短回复文本「嗯」「？」「哦」「好」。
- 判据：**同一文本在不同时间位置承担不同作用**。
  - 几秒窗内、紧接某句 → 对**刚才那句**的澄清/应答（「？」= 要求澄清刚才那句）。
  - 隔天、作为首条 → **新开场的一部分**，或需要额外锚点才成立。
  - 隔天、带引用/锚点 → 对**旧话**的延迟反应。
- 若模型对这三种位置给出相同处理，说明它没用时间位置信号。

**B3.4 旧话题被意外续接的检测**
- [观测] 提示词快照里出现很久以前的话题内容（如四项需求），而当前用户消息
  无任何找回/引用/锚点。
- 判据：若快照带入了旧话题但用户消息无锚点 → **存在误续接风险**；
  应检查该旧话题是否来自「相关性召回」而非用户显式指回。这是可写进回放判据的
  负向条件。
- 配对的正向判据：同样带旧话题，但用户消息有显式找回 → 应判为**合法续接**。
  只有正向/只有负向都不足以证明「按锚点区分」。

## ③ 对 Ling 上下文取数的启示

1. **时间断档后，默认语义是「新会话」，不是「续旧话」。** 除非出现显式找回
   （时间/话题锚点）、引用/@、或带元话语的延迟标记，否则不应把很久以前的
   话题当作当前指代对象。「早上好 → ？」里的「？」应澄清**刚才那句问候**。

2. **区分「隔天仍在续聊」与「几秒内已换题」的信号清单（本方向结论）：**

   | 信号 | 指向「隔天仍在续聊」 | 指向「几秒内已换题」 |
   | --- | --- | --- |
   | 时间/话题锚点 | 「前天那个方案」显式找回 | 无锚点 |
   | 引用/@ | 指向旧消息的显式指针 | 无引用，接最近气泡 |
   | 指代先行词位置 | 先行词在很久以前且被锚点重新激活 | 先行词在最近 1–2 泡 |
   | 开场白 | 隔天首条多为新开场，非续聊 | — |
   | 短回复位置 | 隔天短回复多为新开场/需锚点 | 几秒内短回复 = 澄清刚才那句 |
   | 元话语 | 「刚看到」= 延迟回，可能接旧话 | 无 |

3. **「？」的角色由位置决定，不由字符决定。** 这是反例的直接教训：
   「？」在几秒内是澄清刚才那句；隔天且无锚点时是新会话里的疑问，
   不是对前天话题的追问。取数里应带**时间位置 + 锚点**两个特征，而不是只做
   文本相似度。

4. **Δt 不可单独作判据。** 见 B3.2：延迟回与晚看见在时间戳上同形，必须引入
   中间活动或元话语作为额外证据；拿不到就标注「不可判定」，不要编答案。

5. **提示词快照的权威用法：** 要判断「模型当时到底有没有看到前天那段」，
   读快照里的实际 messages，而不是从记忆检索日志推断。快照里出现旧话题且
   用户无锚点，就是误续接的直接证据。

## ④ 适用边界

- 本组是机制推理 + 合成情境，不是对真实跨时段对话的统计；各信号权重需在本项目
  中文回放集上校准。
- 「隔天首条多为新开场」是**[推理]**先验，存在反例（如两人约定好隔天继续同一
  话题且首条就直接接上）；因此判据要求「无锚点」才判新开场，留了例外空间。
- 平台能否提供「中间其他会话活动」「已读回执」取决于接入能力；缺失时 B3.2
  退化为不可判定，不得默认某一解释。
- 不覆盖群聊锚点细节（M2）、私聊气泡合并（M1）、线下共同在场（M4）。
