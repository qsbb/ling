# M2 · QQ 群内并行话题：多条话题交错、引用回复、@、只扫最近几句

> 合成情境研究，无真实用户数据。QQ 号一律 `100200300` 形态，内网地址 `192.0.2.x`。
> 截图只说明表现，判定以提示词快照与回放为准。
>
> 置信度：**[观测]** 可从快照/回放直接看到；**[推理]** 基于 IM 机制的归因，可被反例推翻。

---

## 0. 本方向要解释的现象

群里同时有几条话题在跑。人**只扫最近几句**，靠**引用回复**和 **@** 跳回旧话，
而不是按时间线顺序读全部。Ling 若在群里把「一串气泡」当成单一连续话题，
就会把互不相关的话题接成一条，或把被引用/被 @ 的旧话漏掉。

反例在群聊里的放大版：群里前天有人列了四项产品需求，今天有人发「早上好」，
另一人回「？」。如果没有引用/@ 锚点，模型可能把「？」接到那四项需求上——
但**在群里，「？」更可能是对刚发的问候或某条最近消息的回应**。

## ① 研究 / 观察情境

### S2.1 并行话题交错

**合成情境 B（两条话题交错）**

```
[14:02] 用户 100200301: 周五团建去哪定了吗
[14:03] 用户 100200302: 我倾向城郊那个营地
[14:05] 用户 100200303: 对了上次那个方案文档谁更新了
[14:05] 用户 100200304: @100200300 你看下
[14:06] 用户 100200301: 营地我可以带烧烤架
[14:06] 用户 100200300: 文档我今晚更
```

时间线上交错着「团建地点」和「方案文档」两条话题。最后一条「文档我今晚更」
若只看最近几句，会被「烧烤架」带偏；但 **@ 锚点**明确把它接回 14:05 的文档话题。

### S2.2 引用回复的跳跃结构

引用回复在界面上是「引用块 + 新评论」，在语义上是**显式指针**：新消息的目标
不是时间上的上一条，而是被引用的那条（可能很久以前）。人用引用回复就是为了
**在多条并行话题里精确定位**，避免歧义。

**合成情境 C（引用跳回旧话）**

```
[昨天 20:31] 用户 100200305: 我那个需求清单列了四项
[今天 09:12] 用户 100200300: 引用[昨天 20:31 100200305: 我那个需求清单列了四项]
                              你列的四项里第二项我有个想法
```

这里「四项」是**显式找回**：引用把旧话重新拉进当前语境，模型必须接被引用内容，
而不是接「今天 09:12 之前的最近一句」。

### S2.3 只扫最近几句

群消息速率高，人普遍**只看屏幕底部最近几条**，更早的靠滚动/搜索/@ 提醒才回看。
这带来两个后果：

- 大多数群内回应针对**最近气泡**；
- 少数带引用/@ 的回应针对**任意旧话**——这些是「回看更早消息」的强信号。

### S2.4 @ 的双重作用

@ 既是**注意力路由**（提醒某人看），也是**话题锚点**（把被 @ 的话和某个话题绑定）。
被 @ 的人对这条的回复义务感更强，即便它已经沉到屏幕上方。

## ② 可观察行为（可写成回放判据）

**B2.1 并行话题分离**
- [观测] 一段群消息里出现两个互不相干的语义簇（如「团建」与「方案文档」）交错。
- 判据：若模型回复只依据「时间上最近的一条」，则**未做话题分离**；若回复能
  对准被引用/@ 锚定的簇，则用了锚点。输入必须包含**两个簇交错**，否则单簇
  情形下「按最近」和「按话题」结果相同，无法区分。

**B2.2 引用回复的锚点优先**
- [观测] 入站消息带引用结构（快照里表现为 `[quote:…]` 或等价字段，指向平台消息 id）。
- 判据：若回复接的是**被引用的那条旧话**而非时间上一条 → 锚点生效；
  若回复接的是时间上一条 → 引用被忽略，**这是缺陷**。
- 反例：去掉引用结构，只留同样的文本。若两种输入下回复相同，说明模型根本没读引用。

**B2.3 @ 作为路由与锚点**
- [观测] 入站消息 @ 了某用户。
- 判据：被 @ 的对象应能从 @ 字段确定，而非从文本猜测；@ 指向的目标话题应与
  @ 所在消息绑定。若 @ 信息与文本冲突（@ 了 A 但文字说「B 你看下」），
  需要明确优先级规则——这是可写进回放判据的边界情形。

**B2.4 最近几件的窗口**
- [观测] 群里 N 条消息里只有末尾 K 条进入提示词快照。
- 判据：若 K 固定且不带引用/@ 展开，则被引用但落在窗口外的旧话会丢失；
  应检查「引用目标是否在快照中可见」。若不可见，属于**锚点悬空**，是缺陷。

## ③ 对 Ling 上下文取数的启示

1. **引用/@ 是「回看更早消息」的显式信号，优先级高于时间邻近。** 在群里，
   「接上一句」的默认假设不成立——默认应是「接被引用/@ 的那句」。
   取数必须把引用目标**展开进快照**，否则锚点悬空。

2. **区分续聊 vs 换题的群聊侧信号：**
   - **有引用/@** → 强信号：主动跳到指定旧话（回看更早消息），无论间隔多久。
   - **无引用/@ + 紧接最近气泡** → 多为「接上一句」。
   - **无引用/@ + 隔了很久 + 带「对了/另外/前天那个」** → 换题后重新提起旧话题，
     属于显式找回，不是续上一句。
   - **无引用/@ + 隔了很久 + 只有短词（「嗯」「？」）** → 多半是对**最近一条**
     的延迟反应，而不是对很久以前话题的接续；群里尤其如此，因为最近一条通常
     已被多条话题覆盖。

3. **单窗口私聊的「连续气泡合并」在群里要改成「话题簇合并」。** 群里同一话题的
   消息在时间上不连续（被其他话题插断），按时间合并会把不同话题揉在一起。
   应按引用链/@ 关系聚簇。

4. **群里「在线状态」更弱。** 多人同时在线使在线几乎不携带信息。M1 里「在线 +
   短回复」的弱先验在群里应进一步降级。

5. **ID 空间再强调：** `[quote:…]` 是平台消息 id。引用展开时若把平台 id 当成
   本地 id，会指向错误消息或悬空。

## ④ 适用边界

- 本组基于通用群聊交互机制推理 + 合成情境，不是对 QQ 群消息结构的实测；
  实际引用字段形态需按本项目接入器核对。
- 「只扫最近几句」是人的阅读倾向，不是可精确量化的窗口大小；K 的具体取值
  需用本项目回放标注，不能杜撰。
- 不覆盖私聊（M1）、跨时段语义（M3）、线下（M4）。
- 群里若关闭引用显示或 @ 通知被屏蔽，锚点信号消失，判据退化为纯时间窗口，
  此时误接旧话的风险上升——这是已知失效模式，不是边界外的特例。
