# M1 · QQ 私聊：单窗口、异步、连续气泡、在线状态

> 本组是**合成情境研究**，不含任何真实用户数据。示例中 QQ 号一律 `100200300`，
> 内网地址一律 `192.0.2.x`。截图只用于说明表现，判定一律以**提示词快照**
> （实际发给模型的 messages）和回放为准。
>
> 置信度约定：**[观测]** 指回放/快照里可直接看到的字段或文本；**[推理]**
> 指基于 IM 交互机制的归因，可被反例推翻；**[转述未核实]** 不在此文使用。

---

## 0. 反例在本方向上的形状

背景反例里「先问前天 → 发「早上好」→ 对刚才问候回「？」」，在私聊里是
**单窗口里三条相邻气泡**。模型先解释问候、又续列很久以前的四项产品需求，
等于把「？」之后的语段错误地锚定到了更早的话题。

本文要回答的核心不是「模型为什么会列旧需求」，而是：**在私聊这种只有一条
时间线、没有显式话题标签的界面里，哪些信号能区分「还在续旧话题」和
「已经换题了」。**

---

## ① 研究 / 观察情境

### S1.1 连续气泡的视觉语法

QQ 私聊是**单会话窗口**：所有消息按到达时间排成一条竖列，没有文件夹、
没有话题分栏。人的阅读方式通常是「从下往上扫最近几条」，而不是从头读起。
一条消息在视觉上是一个气泡；多条同向气泡连续出现时，会被读成**一个语段**
（一串气泡 = 一句完整的话或一次连续的情绪表达），而不是 N 个独立命题。

**合成情境 A（一串气泡读成一句）**

```
[09:41] 用户 100200300: 那个方案我昨晚想了想
[09:41] 用户 100200300: 第一块可以砍掉
[09:41] 用户 100200300: 剩下的我明天发你
```

第三条「剩下的我明天发你」在语义上依赖前两条（「剩下的」指的是「砍掉第一块之后」）。
人读的是这三泡合成的一句；若上下文取数只保留最后一泡，「剩下的」就无指代对象。

### S1.2 异步：发送与查看解耦

私聊里「对方在线」≠「对方在看这条消息」。存在三种可分离的状态：

| 状态 | 含义 | 能否从平台事件直接观测 |
| --- | --- | --- |
| 已送达 | 平台把消息投递到设备 | 通常有回执 |
| 已读 | 对方打开会话并看到 | 视客户端能力而定，常不可得 |
| 已回应 | 对方发出了下一条 | 可从入站事件直接观测 |

**「看见消息后延迟回复」**是常态：人可能先看见、去做别的事、几小时后再回。
这段延迟里，消息在界面上一直是「最后一条」，但对人来说它已经是**旧话**。

### S1.3 在线状态的作用

「在线」是一个**弱在场信号**：它提高「对方可能马上回」的先验，但不保证
接续。反之「离线」也不等于对话结束——异步通讯里离线几小时后再回很常见。
在线状态应作为**辅助信号**，不能单独作为「仍在续聊」的依据。

## ② 可观察行为（可写成回放判据）

以下每条都给出**条件式判据**，而不是期望值。数字只是示例刻度，不是结论。

**B1.1 连续气泡合并**
- [观测] 回放里可见多条入站消息的 `created_at` 落在很短的窗口内，且属于同一会话。
- 判据：若「短时间内连续的 N 条同向消息」在提示词快照里被编译成 N 条独立历史项，
  则**未做气泡合并**；若被标成同一语段或有显式「这是一串连续消息」的结构，
  则做了合并。两种结果对应不同的上下文取数策略，不能混为一谈。
- 区分力：单看「最后一条」在任何一种实现下都会出现，无法证明合并；必须同时
  检查「倒数第二条」是否仍可见。

**B1.2 指代落空检测**
- [观测] 最后一条含指代/省略词（「剩下的」「那个」「也」「还是」）。
- 判据：若该指代词在提示词快照的可见历史里**找不到先行词** → 取数窗口过窄，
  应当向前扩展；若可见历史里有多个候选先行词 → 需要消歧，不能默认取最近的。
- 反例输入：把「剩下的」换成完整名词「剩下的方案」，此时窗口过窄不会造成指代
  落空——若判据在这条输入上也报警，说明它测的是「有指代词」而非「指代落空」。

**B1.3 已读未回与延迟回复**
- [观测] 有「我方发出 → 对方入站」的时间差 Δt。
- 条件式：Δt 很小 → 更像即时接续；Δt 很大 → 可能是「看见后延迟回」，也可能是
  「隔了很久才看见」。**两者在 Δt 上不可区分**，需要额外信号（见 M3）。
- 判据写法：不要写「Δt > X 即为延迟回复」；要写「Δt 落在某区间时，存在 A/B 两种
  解释，需再看 XXX 信号才能判定」。

**B1.4 在线状态的弱证据**
- [观测] 回放里若记录了入站时刻的在线状态。
- 判据：在线状态下收到短回复（「嗯」「？」），与离线状态下收到同样短回复，
  **接续概率是否不同**需要在本项目回放集上验证，不能从文献反推。
- 边界：在线状态缺失是常态，判据必须能在缺失时退化为「不用该信号」，而不是报错
  或默认在线。

## ③ 对 Ling 上下文取数的启示

1. **单窗口不等于单话题。** 私聊里时间顺序是唯一的组织维度，但话题并不按
   气泡边界切换。取数若只按「最近 N 条」切，会同时犯两种错：把一串气泡切断
   （指代落空），以及把换题前的话带进来（旧话题被续接）。需要**气泡合并 + 话题
   边界**两层结构，而不是单层窗口。

2. **区分「隔天仍在续聊」与「几秒内已换题」的私聊侧信号：**
   - **显式承接词**：「刚才」「接着」「后来呢」「还说是」指向前一语段。
   - **显式找回词**：「前天那个」「上次说的」「你之前提的」指向更早、且带
     时间/事件锚点——这是**主动回看更早消息**的信号，不是续上一句。
   - **指代距离**：指代词的先行词在最近 1–2 泡内 → 多为续上一句；先行词在
     很久以前 → 多为回看更早消息，或已换题后重新提起。
   - **时间断档 + 开场白**：隔天出现「在吗」「早」「睡了吗」通常是**新开场**，
     不是昨天话题的延续；若紧跟着出现「对了昨天那个……」才是找回。
   - **短回复的歧义**：「嗯」「？」在几秒窗内多为对**刚才那句**的回应；隔天出现
     则多为**新开场的一部分或对旧话的延迟反应**，需结合是否带锚点判断。

3. **提示词快照是唯一权威。** 快照是整份实际发给模型的 messages，含用户原话
   完整副本。要判断「上下文里到底有没有那段旧话」，读快照，不读行为日志摘要
   （后者按契约只截 60 字，且不是事实源）。

4. **引用/撤回标记各有 ID 空间。** 快照里 `[quote:…]` 是平台消息 id，
   `[recall:rXXXX]` 是本地消息 id 短号。二者语义不同，取数时不要混用；否则
   会把「用户引用了旧话」误判成「用户要撤回某条」。

## ④ 适用边界

- 本组基于**通用私聊交互机制**的推理与合成情境，不是对 QQ 客户端实现的实测。
  具体回执字段、已读状态是否可见，需按本项目实际接入能力核对。
- 气泡合并的「短时间窗口」阈值、指代距离的分档，都是**待校准的工程初值**，
  必须在 Ling 自己的中文对话回放集上验证，不能当行为学结论。
- 「在线状态提高接续概率」是**[推理]**，未在本项目验证；若接入器拿不到在线
  状态，整条判据应降级不用。
- 不覆盖群聊（见 M2）、跨时段（见 M3）、线下（见 M4）。私聊里的「延迟回复」
  只给出不可区分性，完整判据在 M3。
