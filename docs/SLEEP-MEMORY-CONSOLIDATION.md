# 睡眠期记忆整理与可信召回设计

日期：2026-11-09。本文是实施设计；本次仅新增本文档，未修改代码、未写数据库、未执行 Git 写操作。行号以本日工作树为准，真库只做只读查询。

## §1 结论

1. **睡眠期压缩**：在预计入睡后由独立 `memory.consolidate` 作业按人、按晚整理有效断言与情节，先确定性去重、建来源索引和冲突标记，再按需生成不可直接当事实的日摘要；
   不绑醒时的 `sleep.settle`。
2. **召回防错**：先保证候选覆盖，再由权限、有效期、来源、冲突和绝对相关性硬门决定能否进入证据车道；
   摘要只能引导回查当前有效的原始证据，不能凭自身获得“用户确实说过”的资格。

## §3 睡眠期压缩设计

13. **调度点**：在 `life.schedule` 已计算的 `night_window` 中，于 `bed_at+30 分钟` 投独立 `memory.consolidate`；这只是预计睡眠窗口，不宣称角色真的睡着。
   `dream.generate` 在醒前窗口、`sleep.settle` 在醒后；三者不互相等待。依据：`src/ling/worker.py:3302-3386,3390-3406,3481-3497,4138-4233`。
14. 作业粒度为 `(actor_id, subject_id, sleep_date)`；`sleep_date` 沿用“醒来所在本地日”，时间窗取该晚 `bed_at` 前一个角色本地日至 `bed_at`，存 UTC 截止和时区快照，避免午夜把一晚拆两次。
   只对窗口内有新来源的主体投递，空窗零模型、零正文写入。
15. Outbox 主键固定 `memory_consolidate:{actor}:{subject}:{sleep_date}`；另建 `memory_consolidation_runs` 同三元组唯一，状态与输入水位、规则版本、来源集合哈希、结果 ID、失败原因持久化。
   重复扫描及至少一次重放只读已完成结果；唯一约束而非进程变量保证“一晚最多一次提交”。依据：`worker.py:3057-3089` 的投递模式及 `src/ling/infra/models.py:678-691`。
16. `sleep.settle` 不承担压缩：它是醒时跨夜情绪结算、靠 `(actor_id,sleep_date)` 幂等，无模型且不能因梦失败停摆。
   压缩可能慢或失败，不能影响 `I_wake`。依据：`worker.py:4190-4211`；`src/ling/domains/affect/service.py:246`；`docs/DREAM-SCHEDULE-DESIGN.md:123-124,184`。
17. **输入硬门**：只读当前合并组内、受众允许、未撤回、未归档、未超保留期的断言／情节；当前事实再要求 `valid_until>now`。
   已关闭值只进历史候选，不进现状合并；梦、计划、模型推断与无证据自我经历一律不入事实候选。
18. 对 `memory.extract` 未完成的轮次不猜提取结果；以已完成来源的水位生成本晚快照，迟到事件留到次晚整理。
   正常召回可立即用新原行，不必等待下一晚；任何回补都不得绕过清除墓碑。
19. **同槽位断言**：先将多值槽位的列表拆成原子值候选，仅当每个原子值都能在对应原话或可信来源中定位，且主体、槽位、归属、受众、来源窗口和事实时间口径一致才去重。
   `likes=咖啡、散步` 与 `likes=咖啡` 可共享“咖啡”索引；无法可靠拆分时保留原行待核，不做文本拼接。
20. 输出优先是 `memory_clusters`／成员关系而非新事实行；选一条来源最完整、未失效的原行作代表，其他重复行保留审计并标 `duplicate_of`、退出默认检索。
   若要物化多值展示摘要，只能保存为 `fact_eligible=false` 的索引，展开每个值时再回查支持它的原行。
21. 单值槽位（`name/lives_in/works_at/birthday/health`）**绝不列表合并**；同值重复可归组，不同值按 `valid_from/valid_until` 与纠正链保留历史或标冲突。
   既有 `_close_previous_values` 只按单个 subject 关闭，合并组冲突需新增跨组校验。依据：`service.py:157-167,894-930`。
22. **事件级情节**：输入是相同来源 `turn_id/source_event_ids`，或同受众同窗口、时间接近且文本高度相似的未归档情节；“同文本”只是候选，不能跨不同人的真实重复事件直接等同。
   输出为事件簇、代表情节 ID、成员 ID 和共同来源，原行不删；严格等价的冗余行退出默认召回，仍可审计。
23. 事件级短摘要若由规则生成，仅摘取原行已有的用户话语／动作标签；角色回复与用户陈述分开标记。
   `memory.extract` 现把两者并入 Episode，`origin=external_observation`，但召回时给情节 `confidence=1.0`，故摘要不能继承这个 1.0 当事实确信度。依据：`worker.py:440-460`；`service.py:802-813`。
24. **跨天“发生了什么”**：输入为该主体该窗已核验的事件簇与有证据的活动／承诺回执，按来源时间组成最多 N 条日索引；输出为日期、事件 ID 列表、极短主题和缺口标记。
   原情节保留；日索引只用于先定位事件，不作为独立断言或“完成了”证明。
25. 空白日、只有计划或只有梦时不造“今天发生了什么”；同一天不同主体／私聊／群聊分别建索引，读时再按当前 AudienceSnapshot 逐项校验。
   跨窗组合即使文字相近也不能把私聊洗进群聊。依据：`service.py:995-1005`；`src/ling/kernel/context.py:580-617`。
26. **模型取舍**：首期三类整理全部确定性、零模型。
   后续若确需自然语言日索引，可选 `memory.extract` 职责每天每主体最多 1 次、输入估算 ≤2000 token、输出 ≤300 token、只传已许可事件短摘要和 ID；预算为本设计工程上限，尚无真库质量评测，不借 `dialogue.fast`。依据：`worker.py:255-275` 的职责用法；`docs/DREAM-SCHEDULE-DESIGN.md:20,126` 的预算纪律。
27. 模型仅返回 `{event_ids,text}`，ID 必在输入集、文本不得新增人名／地点／日期／完成声称；代码校验失败直接丢弃模型文本，保留规则索引。
   模型产物 `origin=derived_summary,fact_eligible=false`，永不经 `propose` 或 `memory.extract` 回写断言。
28. 模型调用前持久预留额度，记录可能已开始调用的状态；超时或崩溃不自动重复付费。
   提交时重验来源版本、撤回、授权和作业 lease；过期回答不提交。作业错误不回滚原记忆，不阻断梦与情绪结算。
29. 当夜只处理有界批量（初值每主体 500 断言＋500 情节，按主键游标分片）；超出记 `partial` 与未处理水位，下一晚续做，不把未扫完冒称压缩完成。
   批次上限是待压测工程值。

## §4 压缩产物如何标注与防污染

30. 新索引行至少存 `subject_id,actor_id,sleep_date,kind,origin,fact_eligible,visibility,source_visibility,source_window_id,source_event_ids,source_row_ids,input_hash,rule_version,created_at,valid_from,valid_until,retention_deadline,conflict_state`；
   成员链接可有多个，但每个展示片段必须能回溯具体来源行。
31. 索引的保存截止取所有来源行当前**最早**保留截止与策略上限的较早者；不得因生成摘要而续期。
   任一来源撤回、到期、权限收窄或身份拆分时重算支持集；支持集空即失效，不能靠旧 `source_event_ids` 继续读。
32. 置信度不做 `max(source.confidence)`；多来源组合的每个原子结论分别记录支持与反证，展示级置信度最多取其最弱必需证据的等级。
   模型润色不加分；若来源只是角色台词，用户事实等级为 0。
33. `conflict_state` 取 `clear/needs_confirmation/resolved/historical`；`needs_confirmation` 不进 `mention`，现状问答也不二选一猜测，只在当前用户明确询问且受众许可时说“记录不一致，需要确认”。
   确认必须有新用户明确陈述或权威回执，不能由睡眠模型投票。
34. 规则断言：单值槽位同一合并组、同一受众、有效期有交集且规范化值不同 ⇒ `needs_confirmation`；`likes` 与 `dislikes` 对同一原子对象同时有效 ⇒ 冲突；同一事件出现互斥结果（完成／未完成）但来源不充分 ⇒ 冲突。
   仅字符串相似不自动改事实。
35. 特别防复活：北京／上海／广州三条 `lives_in` 若均 `valid_until<=now`，现状摘要数为 0；问“以前”才按各自有效期展示历史，绝不产生一个无 `valid_until` 的“住在三地”。
   旧实现已有该事故注释及过滤，但新索引要在**读时**重验。依据：`service.py:974-990,596-605,1586-1637`。
36. 清除必须原子建立主体（含合并组来源）的持久 tombstone／代次，撤回既有行并撤销该代次所有 pending／leased `memory.extract` 与 `memory.consolidate`；worker 在提取前、写入事务内复查代次，失效任务不落任何内容。
   现有清除只处理已有投影，不能靠取消 pending 解决已经认领的竞态。依据：`service.py:1431-1490`；`worker.py:389-511,4314-4367`。
37. Outbox 今后只存 `turn_id/window_id/subject_id/代次`，执行时按权限读原消息；
   完成、死亡或清除后清理历史 payload 原文的策略需另作数据迁移与审计，不能以“已撤回记忆”误称原文已物理删除。

## §5 召回正确性修复

38. **该注入没注入——候选覆盖。** 当前断言先 `updated_at DESC LIMIT 500` 后才权限过滤和算相关性，旧但高度相关、从未进入这 500 条的行确会永远漏掉。`reinforce/mark_recalled` 虽未显式赋 `updated_at`，`TimestampMixin.onupdate` 会使 SQLAlchemy UPDATE 写它；因此“强化完全不改更新时间”这一前提不成立，反复命中者反而可能长期占坑。依据：`service.py:559-607,1391-1429`；`src/ling/infra/models.py:47-50`；本次编译两条 UPDATE 均含 `updated_at`。
39. 改为数据库端受众／有效期／保留期预过滤，再做“最近、重要、词法／实体／向量”多路有界候选的去重并集；高重要性长尾保留固定配额，不能只靠 `updated_at`。
   每路独立游标与索引；总候选上限和每路命中率用真实回放定，不在本文杜撰最终权重。
40. 情节按相同的 `subject_group` 展开、先过滤再有界取候选，加入事件簇去重；按 `occurred_at,id` 稳定分页，不能简单取最新 500 后再做语义排序。
   合并／拆分后同样复核 `source_filter`。依据：`service.py:738-772`；`src/ling/domains/identity/service.py:738-755`。
41. **不该注入却注入——绝对证据门。** 当前 `relative_score_floor=0.35` 只相对第一名，`kept or scored[:1]` 甚至保底留一条；RRF 排名本身约 0.016，无法把固定 RRF 数字当相关性概率。配置 embedding 时所有授权候选可入排序，BM25=0 的行也可凭排名得分。依据：`service.py:650-707,823-835`；`src/ling/ports/config.py:116-119`。
42. 增加独立的绝对相关性证据：词法确有命中、实体关系有可追溯路径、向量相似度或 reranker 分达到各自**经标注回放校准**的阈值之一；纯新近度／重要性不得通过。
   全部低于门槛就返回 0 条，不保底注入第一名；历史问句另用历史意图和来源校验。
43. 阈值先用真实查询构造“应召回／不应召回／错主体／过期／冲突”标注集，按路线分别画 precision–recall，优先把误注入率压到预设目标，再看漏召回；离线回放与线上影子日志验证后设配置值。
   本文不声称 `0.35` 或某个向量分已有可靠统计依据。
44. 重排输出与 RRF 尾部目前混用分数尺度，不能在混合集上套一个绝对阈值；分别保留 `raw_relevance,score_kind,reranked`，只在同尺度内比较。
   依据：`service.py:1346-1389`。
45. **注入的是不是正确的——来源等级。** 自动断言的 `confidence` 由模型 JSON 自报，缺失／非法默认 0.7，正则降级为 0.6；手工创建的值由请求方提交，缺省 0.6，`MemoryProposal` 自身默认 0.5。
   `gate` 只验归属、槽位与原话近似锚定，不校准概率；解析器遇非法 attribution 还会默认 `user`，需要改为拒绝。
   `classify_usage` 却把 ≥0.75 当 `mention`、≥0.45 当 `tone`；情节召回固定 1.0。因此现有档位是表达启发式，不能视为已证实真值。依据：`src/ling/domains/memory/extract.py:93-103,159-195,199-320,341-354`；`src/ling/api/routes/manage.py:67-77,185-197`；`src/ling/contracts/v1.py:761-772`；`worker.py:471-503`；`service.py:802-813,1550-1574`。
46. 将 `mention` 准入改为“原话／回执可追溯 + 当前有效 + 无冲突 + 受众允许 + 校准等级够高”；模型自报只作弱信号。
   混合用户与角色文本的情节默认只能回答“那次对话提到过”，不能凭 1.0 陈述角色台词为用户事实。
47. 召回后、预算选择前按 `(合并组,slot,事实时间,受众)` 做冲突裁决；同槽两条矛盾行即使均 ≥0.75 也不得同时进 `mention`。
   `render_evidence` 目前逐条分组，无跨条矛盾检查；提示“以本轮用户为准”是最后一道表达约束，不能代替数据闸。依据：`service.py:1598-1649`；`context.py:618-660`。
48. 在预算选取时优先放当前问题直接命中的已证实来源；记录“预过滤数／各路候选数／绝对门拒绝原因／冲突数／预算截断数／最终注入 ID”，只留 ID 与原因码，别把原文或梦写入运行日志。
   `MemoryRetrievalLog` 目前仅存 query、hit IDs、总过滤数、strategy，无法完整解释漏召回。依据：`service.py:837-848`；`src/ling/infra/models.py:1232-1243`。

## §6 与既有裁决的关系

49. `docs/ASYNC-TOOL-DECISION.md:7,24-30,39-43` 裁定只对显式视频建后台读作业、不建设通用异步工具框架；本设计的 `memory.consolidate` 是已有 outbox 的领域维护事件，不是用户工具调用，不发主动补话，不复用媒体 `call_id`。
   慢模型若启用仍需独立 worker／限额，不阻塞普通 outbox。
50. 同文 `:30-34` 要求模型开始后未知结果不盲重试、结果读时再核授权且不保证下一轮必注入；记忆摘要同样持久记状态并读时重验，不能因为索引存在就承诺注入。
   没有冲突，实施时共享“至少一次执行、业务幂等”纪律。
51. `docs/MEDIA-WILLINGNESS-DESIGN.md:34-48,100-101` 把意愿、预算、真实回执分开；记忆压缩只整理已发生且有来源的内容，不把“想看／等会儿／正在准备”浓缩成看过，也不触发观看、延后回复或媒体忙态。
   媒体推断仍保持原不确定标记。无执行边界冲突。
52. `docs/DREAM-SCHEDULE-DESIGN.md:112-115,123-126,182-184,218` 要求梦为模拟叙事、计划非经历、醒时情绪独立；本设计禁止梦进事实输入，睡眠作业也不声称角色真的在睡眠中“思考”。
   梦与压缩并行、互不读写结果；若共享 `memory.extract` 模型额度，按持久预算协调，缺额只降级可选文字索引。
53. 梦只存 `dream_reports(origin=simulated,visibility=actor_private)`，不写事实链；确定性压缩所得“原子事实的索引”可指向事实链但自己不是新证据，模型日摘要完全不具事实资格。
   若以后将摘要作为检索入口，必须先逐项展开并重验原来源，不能把梦／摘要直接交给 `MemoryService.propose`。依据：`src/ling/infra/models.py:2521-2536`；`src/ling/domains/dream/service.py:21-31`。

## §7 分阶段实施与可程序化验收

54. **P0 清除与读侧硬门**：先加持久清除代次及 worker 双检查、撤权／过期／冲突门，修掉出错注入；
   上线前用回放量化影响，不等睡眠压缩完成。
55. **P1 覆盖与去重**：情节合并组、分页候选、事件簇，断言多路候选与绝对证据门；
   保留原行和检索诊断。
56. **P2 夜间整理**：`life.schedule` 投独立作业、run 唯一键、确定性三类索引和来源失效传播，先影子运行对照旧召回，再允许索引辅助检索。
57. **P3 可选语言润色**：有离线标注收益和持久预算后才开启，模型只写不可事实化的日索引；
   梦、情绪结算始终独立。
58. 验收 1：清除与 pending `memory.extract` 并发，完成后该代次新增断言、情节、索引均为 0；
   已认领任务也不能写回。
59. 验收 2：待处理 outbox payload 不含用户原文；
   历史含原文事件按迁移策略处理，清除后读侧不得再从其生成内容。
60. 验收 3：A 合并进 B 后分别以 A/B 查询，合法情节命中集合一致；
   拆分后只回各自有权来源。
61. 验收 4：制造 501 条新断言和 1 条旧高相关断言，旧行仍进候选并可注入；
   全不相关查询返回空。
62. 验收 5：制造 1000 条情节，单次 DB 取数与内存候选始终不超过已设批次上限，深页相关事件仍可由索引路径找到。
63. 验收 6：同一情节正文 8 条且同受众同事件，默认最多返回 1 个事件簇；
   同文但不同真实事件不能误并。
64. 验收 7：`likes=咖啡、散步` 与 `likes=咖啡` 合并后“咖啡”只展示一次，两个原来源仍可追查；
   无法锚定的子项不生成。
65. 验收 8：三个过期 `lives_in` 值压缩后现状召回为 0；
   问历史时仅在有效历史窗口列出，绝不生成“三地现住”。
66. 验收 9：同一单值槽位两个现行相异值，即使自报置信度 0.99，也不同时进 `mention`，冲突状态为 `needs_confirmation`。
67. 验收 10：同一对象同时有效 `likes/dislikes` 被标冲突；
   明确用户纠正后旧项退出现状且保留历史链。
68. 验收 11：模型输出凭空新增地点、改写来源 ID、把角色台词称用户话或输出梦内容，提交数与可事实注入数均为 0。
69. 验收 12：撤权、到期、身份拆分或源行撤回后，已生成日索引的该片段在下一次读取中为 0，不等夜间重建。
70. 验收 13：两个 worker 同时扫同一晚，仅 1 条 outbox、1 条 run、每类确定性产物至多 1 份；
   重放 10 次不增模型调用。
71. 验收 14：压缩任务超时／失败、梦失败、跨夜情绪结算分别注入故障，另外两条链照常推进；
   晚到模型回答不能覆盖新来源版本。
72. 验收 15：标注集分别统计漏召回、误注入、错主体／跨群／过期泄漏；
   绝对门阈值须在该集上达到预先签收目标，不能仅用单元测试通过代替校准。

73. 验收 16：模型候选 attribution 为未知值时拒收，不默认改成 `user`；手工提交高置信度但无有效来源时仍不能进入 `mention`。

## §8 不做什么

74. 不把睡眠或梦拟人化成“她夜里确认了事实”，不从梦、计划、角色台词或模型润色中生成用户事实。
75. 不把旧 `compact_low_value` 原样扩大到所有槽位，不用 `confidence=max` 或新摘要创建时间延长任何来源的有效期与保留期。
76. 不物理删除为审计所需的原行或抹掉 supersede 链；
   “清除”语义与数据库物理擦除需另行明确，不能混称。
77. 不让压缩完成、outbox done 或情节 `confidence=1.0` 直接获得注入许可；
   不把高分当真值，也不为了凑证据保底注入一条噪声。
78. 不新增自动补话、梦到事实的转写、全局异步工具框架或无额度上限的夜间模型调用。
