# 开发自定义工具插件

Ling v1 插件是单独运行的**只读 HTTP 工具**。部署者安装和启停，管理员能在「人设 → 对话 → 工具状态与自定义插件」查看。它不是 Python 热加载，也不兼容 AstrBot 插件包；插件不获得 Ling 数据库、模型密钥或对话历史。

## 开发和安装

1. 启动你信任的插件服务。可用 [目录示例](../examples/tool-plugin/catalog.py) 起步：`python examples/tool-plugin/catalog.py` 默认只监听本机。容器部署时，用 API/Worker 都可达的私有服务地址；不需要把插件端口公布到公网。
2. 在 Ling 的 `LING_DATA_DIR`（Compose 通常为挂载到 `/data` 的应用数据卷）创建 `tool-plugins.json`。采用写临时文件后原子替换的方式。开启状态随清单读取生效，不用重建 Ling 镜像。

   ```json
   {
     "schema_version": "v1",
     "plugins": [
       {
         "id": "catalog",
         "name": "示例商品目录",
         "endpoint": "http://127.0.0.1:8095/v1/call",
         "enabled": true
       }
     ]
   }
   ```

   此例的回环地址仅适用于 Ling 和示例同在宿主机运行；容器内的回环不是宿主机。ID 用小写字母开头、只含小写字母、数字或下划线，最长 40 字符；清单最多 16 个条目，ID 不可重复。没写 `enabled` 时默认停用；删除条目或改为 `false` 即撤销后续调用。清单错误时所有插件关闭。
3. 在「人设 → 对话」开启工具调用并发布，给当前对话模型启用供应商的原生工具选项。非密封私聊发送 `/plugin catalog 茶`。普通对话不会把插件暴露给模型；停用、分组或密封窗口不发起请求。

## HTTP 契约

- Ling 向固定端点 POST JSON：`{"schema_version":"v1","text":"茶"}`。最长 400 字符，只发当前指令内的输入，不发送模型改写、历史消息或凭据。
- 服务返回 HTTP 200 和 `{"schema_version":"v1","result":"茉莉花茶、白茶"}`。响应不得压缩，最多 16 KiB；进入模型时还有 3,200 字符的截断限制，并标记为不可信数据。超时、非 200、非 JSON 或无结果都不是成功。重试旧轮次不会再次调用插件；需要再查时请发新指令。
- 不跟随重定向，不接受由聊天者或模型指定的 URL。固定 HTTP 服务也应当足够可信：Ling 无法阻止独立服务对其自身环境执行副作用。不要接入会发消息、执行命令或修改数据的插件端点。
