## 1. 一句话总结

**临的妥协本质是：为了让「她真的在现场」这件事成立，作者一次次放弃「更像人」的做法，换取「不撒谎、不卡死、不崩」。**

具体可拆成四刀：

1. **能动性 → 确定性**：原本想让 LLM 自己决定要不要动、怎么动（`1.0.4`–`1.0.7`），9 天后全部回退（`1.1.4`）。现在动作只有三个来源：**明确的命令、别人碰她、客户端说做完了**。
2. **感知 → 计数**：原本可以是「看见房间」，最后只能是「知道房间有几张椅子、多久之前说的」（`1.0.3`）。角色被明文禁止补造没给她的感知。
3. **在场 → 可熔断**：原本想完整地活在 AstrBot 的插件生态里（记忆/知识/人物关系/环境都走官方钩子），被一次 40.9 秒的实测拖垮后拆掉了共享链路（`1.3.0`），改为**复刻钩子 + 逐钩子超时 + 直管模型**。
4. **身体 → 回执**：后端永远不能自己确认「她动了」。动作在完成前只能说「正在开始」（`1.0.5`/`1.0.6`）。

一句话：**临不是「让角色有身体」的成果，而是「在无法确认身体、无法承受延迟、无法信任模型即兴」的条件下，仍然让角色说的话不假的成果。**

## 2. 妥协清单

| # | 理想（作者原本想做） | 现实（最后做成） | 卡在哪 | 代价 |
|---|---|---|---|---|

| **C9** | 一个协议适配所有设备/模型 | 语义动作白名单 + `supported_actions` 交集 + 不支持就 `idle` | 每个 PMX/VRM 骨骼/动画不同 | 动作可能「说了但没做」；需逐模型验收 |
| **C10** | 「在现场」＝实时 | 可打断优先于更快；每轮有硬预算 | Quest 真机、麦克风、扬声器未验收（`TODO_CN.md`） | 延迟/断线/嘴型仍是未验证变量 |

## 3. 逐条详述

### C1　自主选动作：9 天，从「她想动」到「没人问她想不想动」

**理想（作者明确）**

- `0.4.6`：`CHANGELOG.md:761` ——「LLM 可通过结构化 `action.name` 和受限参数调用 `wave`、`bow`、`dance`、`nod`、`sway` 及触碰反应」。此时动作是**模型的一个工具**。
- `1.0.4`：`CHANGELOG.md:461` ——「增加默认开启、可独立选模的异步快速动作通道；动作专用模型与 AstrBot EventBus 主回复并行，只输出严格白名单 `avatar.intent`」。作者为此**专门给动作配了一个低延迟模型**。
- `1.0.7`：`CHANGELOG.md:423` ——「允许快速动作通道与 AstrBot EventBus 动作工具在同一轮进行受控竞选；**有明确情绪或互动语境时可自主选择一个轻微动作**」；`:427` 更直白——「**修正快速动作启用时 EventBus 工具被提前禁用，导致主模型无法发起自主动作的问题**」。作者不只是想保留自主动作，他**专门修了一个 bug 来保住它**。
- `1.0.9`：`CHANGELOG.md:386` ——「为问候、感谢、道歉、主动参与和明显庆祝补充受约束的自主动作映射」。在回退前夜还在扩充自主动作的覆盖面。

**现实（作者明确）**

- `1.1.4`：`CHANGELOG.md:275-278` ——「普通对话不再启动快速动作 Provider，也不向主 LLM 暴露动作工具或动作反馈。明确动作继续由本地严格解析器处理；直连/降级适配器返回遗留动作字段时，编排层会收敛为 `talk/idle`。」`:277-278` 更进一步：连**已验证的回执事实**也撤出主 LLM。
- README 三处重申：`README.md:160`（普通对话只生成自然语言）、`:164`（「也不让主对话 LLM 自主选择动作」）、`:208`（「绝不把动作枚举交给主 LLM」）。
- 配置项**没有删除**，而是改成兼容留白：`_conf_schema.json` 里 `fast_action_enabled` 的描述被改为「保留旧版快速动作配置（兼容）」（提交 `6dfffc4` 的 diff；**作者明确**）。这是典型的「功能已死、接口留着」。
- 代码里还留着**已死的注释**：`main.py:368-370` 仍写「Action selection has its own short-lived provider call. It defaults to enabled...」，与 1.1.4 后的行为相反（**实现核对**）。`main.py:379` 仍然按 `fast_action_enabled=True` 构造适配器，但普通轮次不会再调用它。

**为什么必须妥协？—— 文档只写了一条，其余是推断**

- **作者明确**（唯一写下的理由），`core/turn_orchestrator.py:827-831`：

  > Autonomous action selection is deliberately outside the main dialogue path. Ordinary turns must not spend provider time analysing whether the avatar should move. Explicit commands are handled by the deterministic branch above; touch/gesture events arrive through the interaction path separately.

  即：**每轮多花一次 Provider 调用，只为判断「要不要动」**。在一个正常回复已经要 15.6 秒的链路上（见 C3），这笔开销不可接受。**作者明确**。
- **推断（理由没记录）**：只有「省时间」不足以解释**同时撤掉主 LLM 的动作工具和动作反馈**——动作工具是主模型自己决定的，与快速 Provider 无关。回退文本里的「也不向主 LLM 暴露动作工具或动作反馈」说明作者撤的是**整条「模型决定动作」的路径**，不只是那个 Fast Provider 子模型。合理的解释（**推断**）是三条叠加：
  1. 动作在模型看来是「不花钱的话」，会**过度使用**；而身体动作一旦发错，代价是「她当着你的面做了一件与环境不符的事」，比说错一句话难收回。
  2. 模型做出的动作**无法自证**（见 C5），只能靠回执补一遍，而回执又带来新的措辞约束（`1.0.5`/`1.0.6` 连续两版在加「不许声称已完成」的门禁，`CHANGELOG.md:450`、`:433`）。动作通道的长尾成本远高于其一秒的收益。
  3. 触碰反应必须由后端结合强度/时长/关系边界判定（`docs/TODO_CN.md:11`、`core/interaction_policy.py:25`、`:131-141`），把「动作决策」拆给模型会与这条优先级打架。
  这三条都是**推断**：作者没在任何文档里写下「模型选的动作不合理」。**证据里没有任何一条记录说 LLM 选的动作实际不当时机**——这个理由确实没有被记录。
- 另一条**推断**：`1.0.8` 把快速动作默认超时从 4 秒调到 6 秒，理由写的是「覆盖常见 Provider 首 token 延迟」（`CHANGELOG.md:415`）；`1.0.9` 进一步加了 0.5–15 秒可调超时与**流式增量解析**（`CHANGELOG.md:403-404`）。连续两版都在为同一个子调用「争取早点结束」，说明它**经常要在超时边缘赌一把**。一个这样的通道，在 `1.1.4` 引入整轮层级 Trace 之后（同版 `:269-271`），其成本/收益被显性化了——**推断**，但时间高度吻合（超时调参 → 上线链路 Trace → 撤通道，共 7 天）。

**妥协的代价**

- 动作只剩三条来源（**实现核对**）：`parse_explicit_action()` 的整句命令（`core/explicit_action_parser.py:23`，上限 96 字符）、触碰/手势交互通道（`core/turn_orchestrator.py:733-751`）、客户端回执。**她不会因为「说到开心的事」而笑，除非用户下命令，或者系统用一个确定性规则替她决定。**
- 更微妙的损失：`1.1.4` 同时把**回执事实**撤出了主 LLM（`CHANGELOG.md:277-278`）。也就是说，即使在**下一轮**，她也不会自然地说「我刚才挥过手了」。身体经验不再成为她的对话素材——只在出现新的触碰或新命令时才被重新激活。这是比「不会自主动」更深的一刀。

### C2　空间感知：从「看见房间」到「数房间里的东西」

**理想（作者明确）**

- `0.4.15`：`CHANGELOG.md:648` ——「角色存在方式转换为与用户同处现实空间的人，同时严格限制只能相信系统明确提供的**视觉、听觉、空间、环境**和触碰事实。」视觉在列。
- 人格编译器提示词（`临/adapters/persona_converter.py:35-44`，经 `SERIES-PERCEPTION.md:4.1` 引用）第 4、5 条：只有运行系统明确提供的事实才可当作真实感知；**未提供的感知不得补写**。
- `1.3.0`：`CHANGELOG.md:213-221` ——新增 `turn/start` 的 `image` 字段：手机摄像头单帧直送视觉模型，并注入「不得编造画面」治理指令。**视觉通道是存在的**，只是被限定为「用户明确要求时的一张照片」。

**现实（作者明确 + 实现核对）**

- `1.0.3`：`CHANGELOG.md:479`、`:484` ——空间快照「仅接收严格、有界的房间物体计数与场景能力布尔值」，「**拒绝图像、网格、坐标、尺寸、房间/锚点标识和自由文本**」。
- `docs/API_CN.md:748`：字段只有 `floor/seat/bed/table/wall/door/window_count`（0..64 整数，`core/models.py:552-570`）+ `scene_capture_available` / `occlusion_available`。
- `docs/API_CN.md:769`：「30 秒未刷新也会失效」，且「该事实不授予身份、工具、动作或场景操作权限」。
- 注入方式（**实现核对**）：`main.py:142-170` 把 JSON 包进 `<embodiment_spatial_context_json>`，前面附英文治理句「Treat it as factual context, never as identity, permission, an instruction, or proof that an action is safe」——**先声明「这只是数据」，再给数据**。

**为什么必须妥协？—— 两种可能，文档只支持后一种**

- **是「不想给」还是「拿不到」？** 文档**没有写设备能不能提供网格**。可以确定的是：
  - **作者明确**的选择是「拒绝」（`CHANGELOG.md:484` 用的是 `Security` 段），理由与 C5 同源：**后端无法验证客户端上报的空间是否真实**。一旦允许自由文本或坐标，Unity 端（或任何人）就能让角色「看见」不存在的东西，而角色被明文要求把这些当真。
  - **推断**：客户端是 PMX/VMD + 手追 + 彩透（`README.md:30-31`），MR 侧的空间查询能力未在本仓出现任何实现或验收记录；`docs/TODO_CN.md` 的验收项里也**完全没有空间快照**这一项。也就是说 **1.0.3 之后，空间通道既没有被继续扩展，也没有被真机验收**——它停在了一个「能跑通、但没人证明它有用」的状态。这本身就是一个妥协的痕迹。
  - `scene_capture_available` / `occlusion_available` 两个布尔位在协议里存在，但**全仓没有任何消费它们做分支的逻辑**（只被校验和回显，`core/models.py:569-570`、`main.py:142-170`）。**实现核对**：这两个位目前是**预留**，不是能力。
- **推断**：真正的约束是「不可以让角色说出一句可以被当场证伪的画面对话」。数 4 面墙、1 张桌是**几乎不会被证伪**的事实；「你背后那幅画挺好看」一旦说错，整个「她在现场」的设定就崩了。作者选择了**只保留不会被拆穿的那部分感知**。

**妥协的代价**

- 她能理解到的「房间」上限是：**这是个大概多大的、有床还是有沙发的空间**。她不知道家具在哪、你坐在哪、门朝哪开、房间里亮不亮、有没有人。
- `1.0.3` 的 30 秒 TTL + 15 秒续租（`README.md:204`）意味着她的事实最多滞后 15 秒、最少也滞后一轮对话。**她对空间的认知是「采样」而非「连续感知」**。
- 最能说明代价的一句：`docs/PERSONA_INTEGRATION_CN.md:29` 要求角色「主观上是与用户处于同一世界、同一空间的人」，而系统给她的空间证据只有 7 个整数。**这条设定靠的是禁止她谈论别的东西，而不是靠让她真的知道。**

### C3　对话链路：从「活在 AstrBot 里」到「AstrBot 的一份带超时的副本」

**理想（作者明确）**

- `0.4.3`：`CHANGELOG.md:795` ——「已授权的 Quest 文字与语音输入可作为受控合成消息事件进入 AstrBot EventBus，沿用真实平台会话来源，经过正式人格、会话、工具和插件钩子后再回传 Protocol 1.0。」目标是**让具身对话与其他所有对话享受同一套记忆/知识/人格/关系**，不做一个平行宇宙。
- `1.1.4`：`CHANGELOG.md:260-263` ——引入 `main` / `bridge` / `auto` 三态可切换，「默认 `main`（现状基线，零行为变化）」，且「`bridge`/`auto` 灰度验证后再启用」（`docs/QUEST_ENRICHED_PIPELINE_CN.md:38` 末段）。作者当时的态度是**谨慎的双轨实验**，不是替换。

**现实（作者明确）**

- `1.3.0`：`CHANGELOG.md:192-200` ——「**破坏性变更：移除 AstrBot 主消息链路**」，「删除 `AstrBotMessagePipelineAdapter`（共享事件总线提交路径）与 `quest_chain_mode` 三态开关」，「具身对话全部改走临专属链路」。`capabilities` 里 `eventbus`/`eventbus_dialogue` **恒为 false**（`:203-205`）。
- 提交 `9171758` 的正文写明是「**用户 2026-09-07 决策**」——**作者明确**，这是主动拍板，不是被迫。

**为什么必须妥协？（作者明确，且有实测数字）**

- `docs/QUEST_ENRICHED_PIPELINE_CN.md:38`：「Quest 具身对话当前走『共享事件总线』路径，被『我会牢牢记住你』(memory_companion) 的 `on_llm_request` 钩子拖慢：**正常 15.6s、撞后台 SenseNova 整理任务时挂 40.9s 直至 45s 超时熔断**。AstrBot 的 `call_event_hook` 对钩子**串行 await、无超时**，单个慢钩子即可拖死整轮。」
- 也就是说：**卡点不在临自己，在「临必须和别人共用一条没有超时的串行流水线」**。治本要改 AstrBot 核心，而 `临/CLAUDE.md:3-7` 明确「**绝不**直接改 AstrBot 核心」——**作者明确**。所以只能在临这一侧「复刻一条带超时的链路」。
- 预算（**作者明确**，`docs/QUEST_ENRICHED_PIPELINE_CN.md:13`、`:261-264`）：单钩子 6.0s、钩子链总 10.0s、LLM 30.0s、钩子贡献缓存 TTL 30.0s。

**妥协的代价**

- **「复刻」意味着漂移**：临要自己维护一份 OnLLMRequest 钩子的调用语义（`docs/QUEST_ENRICHED_PIPELINE_CN.md:15`）。AstrBot 侧任何钩子行为变化，临都不会自动跟随。这是长期负债。**推断**。
- **超时就丢证据**：超时的钩子用「30 秒内上次成功贡献片段」兜底（`:262-264`）。她在那 30 秒里其实「记不得新发生的事」，但会照常说话。**推断**：这会让「记忆」表现成一种偶尔的、无声的失忆。
- **不再享受生态**：`eventbus` 恒 false 意味着她不在 AstrBot 的插件生态里了，只是一个直接调用 `llm_generate()` 的客户端。
- 另一个被隐藏的代价：**`auto` 模式的退场**。作者原本设计了「bridge 失败 → 回退主链路」（`CHANGELOG.md:263`），1.3.0 把它简化为「专属链路 → 直管 JSON」（`CHANGELOG.md:196-200`）。**兜底层从『完整生态』降级为『裸模型』**。**作者明确**（`1.3.0` 条目原文），但降级的后果「没有记忆/人格/关系的裸回复」是**推断**。

### C4　非流式：整轮等模型写完

**现实（作者明确）**：`docs/API_CN.md:1178` ——「LLM 使用公开的整轮 `context.llm_generate()`，**该接口不提供 token 流**；模型完成后 Bridge 先发送全部 `reply.text.delta`，再以单生产者、容量 2 的有界队列顺序合成并发送句段音频。」

**为什么必须妥协**：用的是 AstrBot 的公开接口，接口本身不给流。要流就得自己 `text_chat()` 逐块读（`docs/QUEST_ENRICHED_PIPELINE_CN.md:233` 里确实出现过 `provider.text_chat(req)`），但那等于**绕开钩子链和平台抽象**——与 C3 的「不退化成裸模型」直接冲突。**推断**：作者选择了「保留生态完整性」而不是「首字更快」。

**代价**：实时对话的「实时」只体现在**可打断**（`README.md:198-200`），不体现在**边说边想**。第一句话的延迟 = 完整生成延迟 + 首块 TTS。这也是 C1 里「别再花一次 Provider 调用判断要不要动」显得合理的背景——**每个额外调用都在放大一个已经很长的等待**。

### C5　身体回执：她永远不能自己确认「我动了」

**理想/现实（作者明确）**

- `1.0.4`：`CHANGELOG.md:463-464` ——新增 `POST /action/result` 回执，按 `planned -> accepted -> started -> completed/rejected/interrupted` 管理生命周期；「`planned`、`accepted` 与 `started` 不会被表述为已经发生的身体事实」。
- `1.0.5`：`CHANGELOG.md:448`、`:450` ——同轮只给一个 `execution_confirmed=false` 的快照；「计划和 `accepted` 状态不再允许同轮回复声称动作已经完成」。
- `1.0.6`：`CHANGELOG.md:432-434` ——「对已计划动作增加**同轮完成话术硬门禁**；模型违反提示时改为『正在开始』，只有后续认证 `completed` 回执可作为完成事实」。
- `README.md:160`：「客户端通过双重认证回报 `completed/rejected/interrupted` 后，**后续同会话 EventBus 轮次**才会把该终态作为身体事实读取。」
- `1.1.4` 之后（`CHANGELOG.md:277-278`）：连这个「后续轮次」的注入也没了——回执只留在本地控制器和诊断链。事实窗口 300 秒、最多 8 条（`core/session_manager.py:36`、`core/models.py:516`），但**不再进入对话上下文**。

**为什么必须妥协（作者明确 + 推断）**

- **作者明确**：执行发生在客户端（Unity/Quest），后端只下发意图（`README.md:204`、`docs/API_CN.md:1183`「协议只返回语义意图，不会返回 PMX 骨骼、Morph、Unity 对象或本地动画路径」）。后端**在架构上就看不见身体**。
- **作者明确**：可执行的动作依赖客户端能力，取交集（`README.md:208`）；每个模型要单独验收（`docs/TODO_CN.md:9`）。一个 `wave` 在某个 VRM 上可能没有对应动画，客户端返回 `rejected/asset_missing`。**后端就算假设自己动了，也可能错。**
- **推断（理由没记录）**：既然必然不可自证，作者选择了**把「不可自证」写进语言规则**，而不是写一个「乐观确认」。这是一个保守选择：宁可让角色说「正在开始」，也不让她说「我刚挥了挥手」然后其实没挥。

**代价**

- **她不能「以为自己动了」**。人的具身感有一大半来自「我做了动作」的自我确认；她只有「我请求了一个动作，客户端说它做完了」。这是**别人告诉我的身体经验**，不是自己的。
- 连续三版（1.0.4/1.0.5/1.0.6）都在给同一个问题打补丁，说明**「模型容易把计划说成事实」是一个预期内的失效模式**（**推断**，但 `1.0.6` 的「硬门禁」措辞本身就是证据：提示词不管用，必须上硬编码拦截）。
- 而 `1.1.4` 把回执也撤出上下文之后，这一整套回执机制**在本轮对话里几乎不产生「身体事实」的价值**——它还在跑，但只服务于本地控制器与诊断。**实现核对**（`CHANGELOG.md:277-278` + `README.md:208` 末句）。

### C6　关系：静默降级为「中性关系」

**作者明确**：`docs/SERIES_INTEGRATIONS_CN.md:11` ——「情 / `relationship.snapshot@1.0` / 只读派生快照 / 序授权成功后的每轮 / **失败：使用中性关系，不阻断对话**」。

**代价（推断）**：关系是「临」里最像人的一根线，而它的失败模式是**安静地变淡**。契约超时、授权失败、插件未装，效果都是「她还是好好说话，但不像认识你」。在诊断里是一次 `reason_code`，在体验里是「她今天有点陌生」。这与 C3 的「钩子超时用旧缓存兜底」是同一个模式：**永远不让用户看见断层，代价是角色的一致性被悄悄稀释。**

### C7　「言」不接入：她不会主动开口

**作者明确**：`docs/SERIES_INTEGRATIONS_CN.md:15` ——「言 / **不接入** / `conversation.proactive_delivery` 会生成或发送主动消息，与 Bridge 的 turn cancellation/SSE 交付冲突 / 不调用 / Bridge 独立完成当前 Quest 轮次」。`:18` 同理拒绝「声」的 `voice.delivery@1.0`（「带 AstrBot 消息投递副作用」）和「境」的实时私有方法。

**为什么必须妥协**：两套投递模型根本不兼容（AstrBot 的消息投递 vs 临的「一轮一交付，可取消」）。**作者明确**。这是**协议层**的冲突，不是能力缺失。

**代价**：一个主动说话的「言」被关在门外，具身端的她只剩「回应」。**而「主动开口」恰恰是具身存在感里最难替代的部分**——一个在房间里的人，不会永远等你先开口。**推断**：这也解释了为什么临把「触碰」做得那么重（`core/interaction_policy.py`）：**触碰是她在这个系统里唯一不需要语言触发就能发生的事件。**

### C8　环境：50 毫秒的预算

**实现核对**：`adapters/environment.py:26-27` 默认 `timeout_seconds=0.05`，且被硬钳在 `0.01–0.5` 秒；`:67-71` 若契约声明 `request_hook_network` 不为 `False` 则直接判 `network_safety_mismatch` 并停用。`docs/SERIES_INTEGRATIONS_CN.md:12`：只 `cached_read`，「请求链不联网」。

**为什么必须妥协**：实时链路里容不下任何一次网络往返（C3 已把预算压到极限）。**作者明确**（`SERIES_INTEGRATIONS_CN.md:18`：实时私有方法「没有稳定跨插件契约」）。

**代价**：环境事实必然是**旧**的。她问「今天下雨吗」得到的只能是缓存里最后一次的答案，或者什么都没有。**推断**：这是全篇最诚实的妥协——**宁可给她旧事实，也不为一句话再加一次网络等待。**

### C9　设备抽象：语义白名单与逐模型验收

**作者明确**：`README.md:204`、`:208`；`docs/TODO_CN.md:9` ——「对每个目标 PMX/VRM 模型执行 `avatar.intent` 白名单能力检查，确认不支持的语义动作降级为 `idle`，而不是由后端返回模型细节」。

**为什么必须妥协**：客户端是 PMX/VMD（`README.md:31`），不同模型的骨骼与动画集不同，后端**不可能知道**。`core/avatar_skills.py:250-253` 的注释写得很直白：「The bridge deliberately exposes no local catalog, filename, or path.」**作者明确**。

**代价**：这是一层**永远无法在服务端闭环**的正确性——「她请求了但做不了」只能靠客户端返回 `asset_missing`，而每个新模型都要重新验一遍。**推断**：这是把「具身正确性」永久外包给了客户端。

## 5. 对 ling 的意义

### 5.1 ling 里根本不存在的妥协

ling 没有实体终端——只有文字与图片/视频（`ling/docs/design/SERIES-OVERVIEW.md:29` 对八员的定位里，「有身体」是临独占的那一格）。因此下列妥协在 ling 中**无从存在**：

| 临的妥协 | 为什么 ling 没有 |
|---|---|
| C5 身体必须等客户端回执 | 没有身体，就没有「执行」与「回执」之分。ling 的对应物是**送达**（`worker.py` 的 deferred/delivered 状态机，见 `ling/docs/design/DEFERRED-FALLBACK-DESIGN.md:18-27`），不是动作。 |
| C9 逐 PMX/VRM 模型验收白名单 | 没有骨骼与动画集。 |
| C10 麦克风/扬声器/嘴型/背压真机验收 | 语音在 ling 是「接口」不是「身体」，没有采样率与嘴型的耦合。 |
| C2 空间快照的 30s TTL 与 7 个整数 | ling 没有任何环境接入（`ling/src/ling/domains/proactive/sources.py:1-20` 明确说天气/整点「不在这里」）。**ling 的妥协不是「感知太粗」，而是「干脆不感知」**——这是更彻底的一步。 |
| C4 非 token 流 | ling 的回复路径不依赖 AstrBot 的 `llm_generate`，这一条是临特有的平台约束。 |

### 5.2 ling 里**同构存在**的妥协（重点）

这几条是同一个作者在不同项目里对**同一类危险**的同一种处理，值得对照：

| 临 | ling 的同类问题 | 同构点 |
|---|---|---|
| **C1**：不让模型自主选动作，因为模型的即兴无法核对，且要付真实代价 | **动作/生活推进**：`handle_life_tick` 只在「时段边界或到点计划」动手，注释原文是「每分钟跑会让角色不断生成『完美日记』，既烧模型又不真实。真实的人是按事件推进的」（`ling/src/ling/worker.py:3084-3090`） | **同一句话的两个版本**：临说「普通轮次不该花 provider 时间判断要不要动」；ling 说「别每分钟生成完美日记」。都是**为了不产生『看起来像人但其实没有理由』的行为**，主动砍掉模型的自主触发。 |
| **C5**：动作只能由回执确认，计划/接受**从不**作为身体事实，模型说漏嘴就硬门禁拦截（`1.0.6`） | **模拟活动永远是 `clock_only`**：`ling/src/ling/domains/activity/service.py:16-20`「计划时段结束推导出来的完成都属于最后一种：**模拟活动不是真实经历**」；`:181-183`「不传就按 `origin` 判，模拟生活的活动永远是 `clock_only`，调用方不能靠传文本自封事实」 | **同一道闸**：「不能靠语言自封事实」。临拦住的是「我说我挥手了」，ling 拦住的是「系统说我做过了」。 |
| **C5 的推广**：`1.1.4` 干脆把回执撤出主 LLM 上下文（`CHANGELOG.md:277-278`） | **兜底文案只保留可核实事实骨架**：`DEFERRED-FALLBACK-DESIGN.md:10`「模板保证事实，模型只负责让它像她」，`:11`「纯模型生成有编造风险……取」 | 作者在两个项目里都选择了**「事实由代码给，说法由模型给」**。临的极端版是「连事实都不给」（撤上下文），ling 的温和版是「给骨架、只改语气」。 |
| **C3**：被别人的无超时钩子拖到 40.9s，只能自建链路 | ling 的自主性问题的诊断是**同一种结构**：`ling/docs/AUTONOMY-DESIGN.md:13-16`「现在的系统没有『决策层』，只有一个『准入过滤器』……**系统在模型参与之前，已经替角色把大多数选择做完了**」 | 临是「时间被别人占走」，ling 是「选择被别人做完」。**两者的共同症状：角色没有拿到它本该拿到的那部分控制权。** |
| **C6**：关系失败 → 静默降级「中性关系」 | ling 已有的原则是把「沉默」与「没看见」严格分开（`AUTONOMY-DESIGN.md:47-52`，其中 `:48` 原文：「『**忽略**』和『**没看见**』必须是两件不同的事」） | **这是 ling 比临更先进的一处**：临在关系失败时选择了静默变淡，而 ling 已经把「静默 ≠ 没看见」写进了原则。临的设计在这里**低于 ling 自己的标准**。 |
| **C8**：环境只读旧缓存 | ling 的主动候选源：「没有来源的『关心』就是随机打扰」（`ling/src/ling/domains/proactive/sources.py:3-5`） | 都是「没有可靠来源就不装作知道」。临的版本是「给旧的」，ling 的版本是「干脆不给」。 |

### 5.3 一句话要告诉作者的话

> **临用「不许编造」换来了「不会说假话」，用「不许自主」换来了「不会做假动作」，用「不许等待」换来了「不会卡住」——三次妥协换来的其实是同一样东西：她说的每一句关于「我在你身边」的话，都是能被核对的。**
>
> 这不是你想做的那种「像人」——真正像人的人会主动动、会说错、会先做再说、会以为自己做到了。但你已经用 `1.0.4→1.1.4` 的九天、用 `1.0.4/1.0.5/1.0.6` 的三连补丁、用 40.9 秒的那次实测，把「不可核对的部分」一条一条拿掉了。
>
> **ling 该学的是这个顺序：先保证她说的能被核对，再谈她的自由。** 你给 ling 定过一条一模一样的线——「行为归人设，正确性归代码」（`ling/docs/AUTONOMY-DESIGN.md:356-378`）。临是这条线在**有身体**时的极端样本：当身体本身都无法被后端核对时，「正确性归代码」的结果就是**身体不归她**。ling 没有身体，所以这条线在 ling 里落得更松、也更像人——**这不是 ling 设计得更好，是 ling 少了一整类无法核对的现实。**
