# 「知」「情」产品考古：知识与关系为何分开

核对日期：2026-11-11。本文以本机当前「知」「情」仓库为主，并只读核对「序」的桥接；不把早期变更记录当作现行行为。下文路径均相对 `/Users/lingxi/project/`：`知/` 指 `astrbot_plugin_active_learner/`，`情/` 指 `astrbot_plugin_relationship/`，`序/` 指 `astrbot_plugin_identity_guardian/`，`ling/` 指 `ling/`。**「作者明说」**表示 README、配置、CHANGELOG 或代码注释直接陈述；**「代码显示」**表示当前执行路径；**「推断」**是基于这些证据的产品判断，不冒充作者原话。

## 1. 系列定位

| 模块 | 作者明说的职责 | 对 ling 的含义 |
|---|---|---|
| 知 | 学习、检索与验证知识；注入事实参考，按私聊、群聊、全局分作用域。它不负责关系分数。`知/README.md:3,46-56,103-120` | **推断**：它解决“模型下一轮仍能找到有根据的知识，以及发现旧知识不可靠时如何核验”的问题，主要是事实证据层。`知/README.md:48-54,125-143` |
| 情 | 管理疲劳、短期态度、长期好感/信任/熟悉度；输出只读行为建议，决定表达分寸，但不接管发送、事实判断或权限。`情/README.md:24-39` | **推断**：它解决“不能把每轮聊天当作与同一个陌生人的对话，也不能让 LLM 凭一句话任意改关系”的问题，主要是关系状态与表达层。`情/README.md:26-39,74-92` |

**不能把“统一记忆池”理解为知、情、境、序四仓共享数据库。** 这个词出现在知的元数据与 2026-07-06 旧 CHANGELOG；当时指知**自己**的知识库把 scope 从硬过滤改为软权重，理由是通用知识不应因“换了房间”消失。`知/metadata.yaml:3-4`、`知/CHANGELOG.md:837-846`。后来 2026-07-29 的记录明确收紧作用域；当前 README 和 SQL 只允许本 scope 与可选 global，其他私聊、其他群一律不得读取。`知/CHANGELOG.md:259-267`、`知/README.md:103-114`、`知/storage.py:881-915,1036-1054,1071-1089`。当前可核实的跨插件协作是：序、知、情登记同轮提示片段并由言排序去重；序通过版本化只读接口查询知的知识，且明确不直接读取知的私有数据库。对境参与同一个持久记忆池，**文档里没写**。这些是**上下文/接口协作**，不是统一事实池。`知/README.md:69-70`、`知/constants.py:51-65`、`知/main.py:511-524,546-553`、`情/core/request_context.py:1-17`、`序/core/knowledge.py:1-16`。情的跨平台长期记忆又是读取第三方 Memory Companion 的公开桥，明确不改其数据库，也非知的存储。`情/README.md:115-129`。

作者没有在这两个仓库的 README/metadata 中明确说“AstrBot 原生记忆缺少 X，所以我做知/情”；**文档里没写**这个直接因果。可确认的具体问题是：知识若只靠裸 LLM，无法带来源纠错、处理时效和实体不匹配；关系若交给 LLM 自行改数值，则缺稳定的时间尺度、可信事件和权限边界。前半句是**推断**，依据是知明确加入检索、来源、实体覆盖、核验与版本；后半句是**推断**，依据是情明说“规则驱动数值”、时间尺度分层与身份双轨。`知/README.md:46-54,83-90,125-143`、`情/README.md:30-39`。

## 2. 「知」的设计意图与关键机制

### 为什么设计

作者明说：长期记忆要做到请求前检索即注入、多源学习、实体完整匹配、私聊/群聊隔离和质疑后留版本；特别指出宽泛词可能把另一实体的高置信知识误当答案。`知/README.md:46-56`。他还记录了两个关键取舍：外部搜索由本次**主模型**结合不确定性、时效性、实体完整度、答错代价决定，不为了决策多调一次模型；旧知识可能过时时用 `force_refresh` 跳过本地短路。`知/README.md:83-90`。**推断**：这是将“有记忆”与“有可靠答案”区分开，防止旧、错、跨实体的片段先入为主；代码里非对比查询要求候选覆盖全部核心实体，注释明确写了污染风险。`知/retrieval.py:514-526`、`知/runtime.py:131-178`。

### 召回与注入：上限，不是保底

- 当前默认开启确定性按需门控：消息少于 3 字直接返回；没有回忆、时间、人物、事件等线索时跳过 FTS、向量和访问统计，得到 `hits=[]`。代码注释明确说“宁可不召回，也不让普通聊天付全库 FTS/向量检索成本”。`知/main.py:227-230,737-747,768-786`、`知/_conf_schema.json:127-131`。**局限（推断）**：正则只识别预设线索，可能漏掉隐含而相关的问法；它是廉价门控，不是语义相关性证明。`知/main.py:737-747`。
- 门控通过后，FTS 与可选 Embedding 并发；FTS 命中数量、分数及对比对象覆盖都足够时取消向量任务，否则合并两路；复杂问题可选派生线索图补查，默认关闭。实体覆盖再筛一遍。因此可返回 0、1、2 或 3 条，并非每次凑满 3。`知/retrieval.py:268-301,394-445,446-526`、`知/README.md:218-220`。可选图的 `fast` 只查本地，`smart` 在复杂问题最多额外一次 LLM 排序；图只索引既有记忆，不自产新事实。`知/README.md:52,119-120,218-220`、`知/main.py:250-254`。
- 注入配置默认最多 3 条且硬上限 3，单条最多 700 字符、总共最多 1800 字符；超预算就停。`知/README.md:223`、`知/main.py:247-249`、`知/constants.py:26-37`、`知/retrieval.py:533-556`。`search_top_k=5` 是搜索工具/命令的结果上限，**不是**自动上下文注入条数。`知/README.md:199,223`。
- 还有**不注入**的情况：无文本/过短、门控跳过、检索失败、无命中、实体不完整或字符预算放不下；其中门控和实体过滤有明确代码路径。`知/main.py:768-786,819-837`、`知/retrieval.py:514-555`。不过 `context_inject_count` 的合法值是 **1–3**，并无“用户将数量配成 0”的配置；零召回来自门控和候选结果。`知/main.py:247-249`。

### 多源学习、可信度与版本

- 外部来源是管理员配置的固定 URL/MediaWiki、Web 搜索，以及默认关闭的 B 站补充来源；本地记忆是搜索工具的前置短路，不算外部来源。固定网页须含主题核心词；最多登记 20 个手动来源、每次最多并行 5 个、单来源 5 秒；B 站标题/简介只作补充证据。`知/README.md:74-81,94-101,170,203-208`、`知/retrieval.py:97-101,153-198`。另有对话后置学习：后台用模型判定是否有新知识，过短、管理员没有明确学习意图或 30 秒内重复分析会跳过；群黑话学习默认关闭、批量一次模型调用。`知/learning.py:25-73,88-126,207-244`、`知/README.md:227`。文档也明确把通用知识和个人资料分开，早期 `save_memory` 只收“概念、原理、事实”，不收个人信息/偏好/日程。`知/CHANGELOG.md:857-861`。
- 可信度不是“来源多就真”：当前精炼器把原先两步合为**一次 LLM 调用**，在一轮提示中抽取事实、生成知识卡并自评置信度；`tools.py` 的“两步”注释是过时描述。精炼失败时按结果数算规则分；保留来源详情、置信度与 verified 标志。核验时做来源搜索与三轮模型自辩论，来源不足会退化为 **LLM-only**，因此“已验证”也不等于独立外部事实证明。`知/refiner.py:51-99`、`知/tools.py:161-189,222-236`、`知/verifier.py:127-160,176-194`、`知/README.md:125-143`。**借鉴时须补防线（推断）**：不能把模型自评或多个同源网页直接当作强事实证据。依据是上述降级和规则分路径；两仓文档没有声称它们能证明外部来源独立。`知/tools.py:183-189`、`知/verifier.py:127-154`。
- `memory_versions` 保存旧正文、旧置信度、来源和原因；核验/更新使正文变化或置信度下降超过 0.15 时写快照，随后更新当前条目。**这是纠错留痕，不是自动冲突消解**：当前条目仍是一个版本，旧值供追溯，版本号也不同于 `metadata.yaml` 的插件版本。`知/README.md:117-120,125-143`、`知/storage.py:423-475,584-595`。旧记忆过时可强制外搜，作者记录过“看似调用搜索、实际只返回旧记忆”的修复原因。`知/CHANGELOG.md:245-253`、`知/tools.py:122-150`。

### 检索信号与成本边界

当前检索的**候选来源**是 FTS5/BM25 与可选向量余弦；对比对象可分别补查，可选图索引可补关系线索。核心实体覆盖是筛选条件，不是独立“实体索引召回路”；时间是候选后的衰减排序，按最后访问/创建时间与 30 天默认半衰期计算，也不是独立时间召回路。最终分数还结合 FTS/向量权重（默认 0.4/0.6）、scope 惩罚、置信度和关心领域 boost。`知/storage.py:881-925,982-1005,1036-1054,1094-1130`、`知/retrieval.py:418-526`、`知/README.md:214-224`。检索成本由最多 3 条、Embedding 1.5 秒等待、外搜总 deadline 10 秒、缓存和插件内部 LLM 并发默认 1 控制。`知/constants.py:26-37`、`知/retrieval.py:45-53,356-365`、`知/README.md:213`。

**不要误以为知已经修好了 ling 的“第 501 条不可见”。** 知的 FTS 在当前 scope 执行 `MATCH`，不会先按 `updated_at` 取最新 500 条；这点值得借鉴。但当前 `_search_fts` 的 SQL 也在 `LIMIT` 之前没有 `ORDER BY bm25`，向量路则在当前 scope 载入向量矩阵后排序；它的实现并不构成可直接移植到 ling 的完整覆盖/成本方案。`知/storage.py:881-925,927-1005`、`ling/src/ling/domains/memory/service.py:582-603`。知的 `max_entries=500` 是**每个 scope 的存储容量淘汰上限**，不是 ling 的候选截断 500，两者不可混为一谈。`知/README.md:123,195`、`知/storage.py:597-600`。

### 是否做模型压缩

知**会**在明确搜索学习、对话学习、`save_memory` 和核验时调用模型提取/精炼知识，也可在 `smart` 图路由额外调一次模型；它有开关、节流、批量与内部并发限制。`知/tools.py:169-174,500-559`、`知/learning.py:25-39,88-126,207-244`、`知/verifier.py:143-173`、`知/README.md:213,218-220,227`。但在当前 README 与这些实现中，**文档里没写睡眠期压缩**；上述精炼属于知识入库/纠错，不应称为“睡眠整合”。`知/README.md:72-81,125-143`、`知/tools.py:169-174`。ling 当前睡眠整合明说零模型、只做确定性整理；将来若引入 gist，必须单独标注为非事实线索。`ling/src/ling/domains/memory/consolidate.py:1-21`。

## 3. 「情」的设计意图与关键机制

### 为什么设计

作者明说将疲劳与短期态度、好感、信任、熟悉度放在不同时间尺度；“短期烦躁不会直接降低长期好感”，数值由规则计算，LLM 只接收表达建议。`情/README.md:30-39`、`情/core/affinity.py:1-7`。**推断**：这是为持续相处建立可控、可解释、不会被一次聊天或模型临场发挥带偏的关系状态，而不是把所有互动压成一个亲密分数。`情/README.md:30-39,43-92`。边界同样是目的：关系不是恋爱/占有授权，也不给发送和权限；权限仍以原始平台账号为准。`情/README.md:26-28,38-39,82-88`。

### 关系如何计算、衰减

- **好感**：普通有效消息默认 +0.2，60 秒冷却；夸奖 +1.5、帮助 +2、冒犯 −2 的配置增量。非白名单默认上限 68；白名单也须通过信任、熟悉度门槛，高好感区普通聊天不再刷分；每天正负额度分别限幅。计算器只算增量，Manager 做证据权重、门槛、每日额度与 0–100 限幅。`情/core/affinity.py:18-33,82-139`、`情/core/manager.py:1248-1318`。长期无互动向 50 回归，默认每天回归偏离量的 2%。`情/core/decay.py:1-9,21-39,50-76`。
- **信任**：可靠性、善意、诚信、认知四维；普通聊天或不可信来源不改信任，只有可信的履约、失约、帮助、冒犯等事实事件改变相应维度。证据权重为截断后的 `confidence × severity`，早期小幅可塑性增益随累计证据平滑消退；长期信任默认每天向 50 回归偏离量的 0.5%。平台聊天原文不能自证履约/失约。`情/README.md:32-37,86-88,228-249`、`情/core/trust.py:1-5,37-71`、`情/core/dynamics.py:38-81`、`情/core/decay.py:21-27,60-75`。
- **熟悉度**：有效互动默认增量 `0.8×(1−familiarity/100)^2`，120 秒冷却；只增不减，不随时间衰减。`情/core/familiarity.py:1-7,17-55`、`情/core/decay.py:75-77`。分钟到小时尺度的疲劳和短期亲近/戒备另行恢复，不写入长期分数；日内好感趋势也只影响语气。`情/README.md:43-62`。

### 语气参考如何起作用

关系计算器先产出只读快照，再映射到 `tone/length/initiative/boundary/silence` 等建议；模型收到的是本轮表达约束文字，而不是原始分数，且不改变事实、安全、工具权限。`情/README.md:26-28,152-168,264-273`、`情/core/policy.py:88-115`、`情/core/prompts.py:1-10,27-65,98-156`。暖色语气有好感≥80、信任≥75、熟悉度≥60 的同时门槛，朋友区的短期升温仍用友好但有分寸的语气；群聊再加公开披露边界。`情/README.md:78-84`、`情/core/policy.py:29-36,113-115`、`情/core/prompts.py:131-155`。显式关闭注入、快照建议静默或没有表达建议时返回空块；即使有静默建议，是否真正发送仍由言决定。`情/core/prompts.py:98-142`、`情/README.md:26-28,295-307`。

### 跨平台身份与记忆连续性

情的一个自然人可以由管理员**手工确认**多个平台账号，绝不根据昵称、头像或聊天内容自动猜；同一关系人格内共享长期关系，短期疲劳/态度仍按会话和原账号隔离，序的主人/黑名单/群权限不继承。`情/README.md:98-113,115-123,138-145`。桥接只在私聊、账号已明确绑定、关系人格一致、第三方 Memory Companion 桥可用且有相关结果时追加其他账号的片段；默认每账号最多 3 条、总共最多 1200 字符。查询后还要重新确认身份未变，提示将片段当资料而非指令；言已选近期跨会话背景时跳过长期桥接，避免重复。`情/README.md:125-133,308-310`、`情/main.py:1306-1357,1360-1461`。这不是知的跨平台共享记忆池。`情/README.md:125-129`。

**与 ling 的 `merged_into` 对照。** 情的合并会把来源自然人的账号移到目标、移除来源身份，并对关系状态做显式迁移、冲突预检与中断恢复；解绑还要选承接关系的账号。`情/core/identity_registry.py:339-373`、`情/README.md:108-110`。ling 的合并只写 `subjects.merged_into` 指针，原账号/原记忆保留在来源主体名下，查询时展开主体组；拆分时清指针并按 `source_account` 归位合并期间的新记忆。`ling/src/ling/domains/identity/service.py:705-758,760-834`。**推断**：情在跨插件边界、明确账号身份、关系人格隔离与事务恢复上更严格，值得参考；ling 的指针合并更利于可逆拆分，不能直接换成情的搬迁式合并。`情/README.md:106-110,115-133`、`ling/src/ling/domains/identity/service.py:705-715,784-829`。此外，ling 当前断言会展开合并主体组，但情节只按单 `subject_id` 查；这与情的桥接不是同一种问题，应在 ling 自己的召回层修。`ling/docs/REQUIREMENTS-AUDIT.md:71`、`ling/src/ling/domains/memory/service.py:566-570`。

## 4. 对 ling 的借鉴清单

| 判断 | 具体做法和理由 |
|---|---|
| **值得抄：零召回优先、上限不是定额。** | 知默认先判是否需要长期回忆，无需求直接零检索；检索后最多 3 条、受字符预算限制。ling 目前每轮调用 `limit=6`，虽空候选可回空，但有分数时相对门槛保底留首条。应把“需不需要回忆”和“相关性够不够”分开，并允许有候选却 0 注入。`知/main.py:737-747,782-786,247-249`、`知/retrieval.py:533-556`、`ling/src/ling/kernel/context.py:624-643`、`ling/src/ling/domains/memory/service.py:860-869`。**不该抄**知的固定正则当作唯一门控，隐含线索会漏；应结合 ling 已有的多路相关性与绝对门槛。`知/main.py:737-747`、`ling/docs/design/MEMORY-CANDIDATE-DESIGN.md:5-11`。 |
| **值得抄：候选按查询线索取，不按最近修改取。** | 知用 FTS `MATCH` 和可选向量，从当前 scope 找候选，旧但相关的知识有进入机会。ling 当前先截最新 500 再排 BM25/向量/实体/时间，已复现 500/501 断崖。**不该抄**知 `_search_fts` 的无 `ORDER BY` 限额写法或全 scope 向量矩阵方式作为最终方案；ling 已有候选入口设计稿，应按其覆盖/上界约束做。`知/storage.py:881-925,927-1005`、`ling/src/ling/domains/memory/service.py:582-603`、`ling/docs/design/MEMORY-CANDIDATE-DESIGN.md:5-11`。 |
| **值得抄：旧事实可刷新、有来源、留旧版本。** | 知的 `force_refresh` 防旧记忆短路，核验改动前留正文/置信度/来源/原因快照。ling 可将纠错与覆盖留痕，避免旧地址之类的失效事实与新值混用。**不该抄**“有版本表就自动解决冲突”的理解；知版本是审计，真伪仍取决于证据和当前条目的裁决。`知/CHANGELOG.md:245-253`、`知/storage.py:423-475,584-595`、`ling/src/ling/kernel/context.py:629-635`。 |
| **值得抄：事实记忆与关系状态分开。** | 情的数值按规则和可信事件更新，短期心情不改长期好感，关系提示只改表达；知的知识检索提供事实证据。ling 不应把“她对这个人更亲近”当作该用户说过某事实，也不应让关系分数直接决定权限。`情/README.md:26-39,74-92`、`知/README.md:46-54`。 |
| **值得抄：身份连续性与授权分轨。** | 情手工绑定账号、关系人格隔离、跨平台只读片段限制字数并标为不可执行资料，权限仍看原始平台账号。ling 已有可拆分的 `merged_into`，应保留其可逆性，并检查合并组下断言与情节是否都能召回。`情/README.md:98-133`、`ling/src/ling/domains/identity/service.py:705-715`、`ling/docs/REQUIREMENTS-AUDIT.md:71`。 |
| **不该抄：把模型精炼当作睡眠压缩事实。** | 知的模型调用发生在知识提取、学习、验证或可选路由，且 LLM-only 核验仍可能标为一致；它没有展示可复用的睡眠 gist 流程。ling 当前刻意零模型，以免模型编的摘要顶替原始事实；若将来做睡眠 gist，必须与事实证据分层并控制来源、批量与调用额度。`知/tools.py:169-189`、`知/verifier.py:127-154`、`知/learning.py:25-39,207-244`、`ling/src/ling/domains/memory/consolidate.py:1-21`。 |

**可操作的前三项**：先实现“允许零召回且 0–N 条”的检索/注入判定；再替换 `updated_at DESC LIMIT 500` 的候选入口；最后为被纠错或过时的事实保留来源与旧值快照。它们分别对应知的按需门控与预算、查询驱动候选、`force_refresh` 与版本留痕；ling 的既有问题和实现证据见上表各行。

## 5. 作者的原话摘录

下列均是仓库原文，历史文字标明时间，不代表当前生效：

> “更像人类记忆——不会‘换了房间就忘记’”——**历史方案**，知 2026-07-06 的统一池理由；当前已改回硬边界。`知/CHANGELOG.md:841-846,259-267`

> “不再依赖‘搜一下 / 查一下’等硬编码词表，也不会为了判断是否搜索而额外调用一次 LLM。”——外搜交由主模型本轮判断。`知/README.md:83`
