## 1. 一句话结论

**系列不是「AI 角色」，而是一张「人的构成表」。**

裸 LLM 能决定「回什么」，却不能决定「何时不回、怎么说话、以什么身份说、
有没有声音、在不在场」。八个字就是把这些「不像人」的部分逐项建仓。

**关键留白**：表里没有任何字承担「人格／生活／整体状态」——
这是刻意的，也正是 ling 的立足点。系列是「在框架内把 bot 修剪到多像人」，
ling 是「她本人即主体」。

## 2. 各模块的设计意图

### 2.1 知（知识）——让知识可检索、可核验、可纠错

**存在理由**：「知」负责让知识可检索、可核验、可纠错；「情」负责让关系状态持续、
可解释，并只影响表达建议。**两者不是同一个记忆系统**。（知/`README.md:46-54`、情/`README.md:24-39`）

**必须纠正的一个误解**：`metadata.yaml` 里写的「统一记忆池」是「知」**2026 年 7 月的
历史方案**，指其自身知识库的 scope 软权重。**当前已改为私聊/群聊硬隔离**：

> 「收紧知识作用域：私聊、群聊与全局的检索、详情、验证、遗忘、版本、导出和写入
> 使用同一显式作用域，**不再允许无命中时跨用户、跨群或回退全局库**。」
> ——（知/`CHANGELOG.md:259-267`）

所以它**从来不是**知/情/境/序共享数据库。这一点与「枢」未完成的事实吻合：
系列实际是各自独立，没有共享记忆池。

**最有价值的设计：默认先做无模型门控，允许零召回**

```python
# 知/main.py:782-786
if self._memory_recall_gate_enabled and not self._memory_recall_demanded(msg):
    # 按需触发：本轮无回忆/时间/人物/事件指代，跳过全库检索，
    # 不 FTS、不向量、不 track_search_hits、不调整 priority boost。
    hits = []
    retrieval_mode = "gated"
```

**它连检索都不做**——比「召回后过滤」更彻底。

**注入预算**（知/`constants.py:26-37`）：

```
_MEMORY_INJECT_MAX_COUNT = 3
_MEMORY_INJECT_TOTAL_CHARS = 1800
_MEMORY_INJECT_ITEM_CHARS = 700
```

**纠错流程**：外部搜索 → 来源记录 → 模型精炼 → 质疑核验 → 旧版本快照，
接成一条纠错流水线。版本表提供**追溯**，但**不会自动裁决冲突或证明知识为真**
（知/`tools.py:148-189,222-236`、`verifier.py:127-194`、`storage.py:423-475`）。

### 2.2 情（关系）——关系影响表达，但不授予权限

**设计原则**（情/`README.md:30-39,86-92`）：

| 机制 | 设计 |
|---|---|
| 短期烦躁 | **不**直接改长期好感（`core/trust.py:37-71`） |
| 普通聊天 | **不**直接改信任 |
| 熟悉度 | **只增不减**（`core/familiarity.py:1-7`） |
| 关系快照 | 只给**语气/篇幅/主动性建议**，**不交原始分数**，**不授予发送或平台权限** |

最后一条是最干净的设计：**关系状态影响怎么说，不影响能不能做**。

跨平台账号须由管理员**明确绑定**（`README.md:152-168`）——这与 ling 的
`merged_into` 目标一致，但 ling 现在合并后会丢情节（已修）。

### 2.3 言（对话）——何时沉默、如何分段、被插话怎么办

**存在理由（作者原话）**：

> 「让 AstrBot 像真人一样判断何时沉默、何时分段、被插话时如何自然衔接。」
> ——（言/`README.md:3`）

**他要消灭的行为，逐条写在 `README.md:40`**：

> 「bot 逢 @ 必回且永远精神饱满；换平台后丢失刚才话题；短追问丢失上一轮对象；
> 多 bot 刷屏；打断群友对话；引用归属错乱；图片消息一刀切；重复客服式收尾；
> 暴露工具机制词」

**沉默的两条路径，成本完全不同**（这是最容易被误抄的地方）：

| 策略 | 做法 | 成本 |
|---|---|---|
| `inject`（**默认**，推荐） | 在**已有**主模型请求里加一条高门槛沉默指令，模型输出 `<SILENCE/>` 则清空回复 | **不额外调用模型**，但**该消息确实被模型看过** |
| `prejudge`（可选） | 先调轻量 LLM 输出 JSON 判定，沉默则拦下主模型 | 每次合格短输入**额外一次**调用 |

**⚠️ 关键陷阱**：`inject` 模式**不是**零成本的「看不看」分类器。它仍需要本轮主模型推理
（言/`silence_judge.py:123-130,152-166`）。

**不要用固定疑问词做判据**：`astrbot_plugin_memory_companion` 的提示语原文写着
「不要依赖固定疑问词判断用户意图」（`core/injection.py:91`）。

**硬门在前、语境判断在后**：群聊刷屏和重复客套可由本地规则在调模型前拦下；
判断一句话指向 bot、别人还是全群也不需要额外调用（言/`README.md:334-352`）。

**短期跨会话感知默认关闭**；启用后仍须通过同一人身份、读取方向、当前会话优先级和
话题线索筛选，**不能仅凭时间近就注入**（言/`README.md:406-424`）。

### 2.4 序（身份）——bot 以什么身份、能对谁做什么

**存在理由**：「让 bot 在 QQ 群里像真实成员一样理解『自己是谁、对方是谁、
双方是什么关系、当前能做什么』」（序/`README.md:3`）。

**两条哲学（作者明确，`README.md:52-53`）**：

> 「**身份不等于授权**」
> 「**允许行动而非强制行动**：工具可用只表示『可以做』，不代表『必须做』；
> 是否执行由主对话 LLM 结合人设、情绪与上下文自主判断」

**权限与连续性分离**（重要设计）：原始平台账号的权限身份与跨账号的自然人连续性
**分开**——**账号合并不会自动继承群管或主动发送权限**。

**入群审核**：按平台实例和群隔离；**没有参考答案或知识证据时不让模型自由裁决**，
也不自动拒绝申请。

### 2.5 境（环境）——让模型不必猜，也不必装作知道

**存在理由**（境/`README.md:32-45`）：

> 「模型自主决定：注册语义清晰的只读工具，**不增加一次『要不要查询』的 LLM 请求**，
> 不使用关键词硬路由」
> 「不误报无风险：**数据源失败与『已查询但没有相关事件』是两种不同状态**」
> 「隐私克制：经纬度不进入工具公共结果」

**「按需获取」的真实含义**：六个只读 LLM 工具（`get_local_datetime`、`get_local_calendar`、
`get_weather`、`get_air_quality`、`get_environment_alerts`、`list_environment_locations`），
**什么时候查由模型自己判断**（境/`tools.py:108-124`）。工具描述里写满边界：

> 「文学比喻、虚构场景、天气回忆和纯情绪化表达（如『心里阴天』）不要调用；
> 仅提到出门、上班或季节也不自动调用。**仍由当前主模型在本轮自主判断**，
> 不按关键词强制调用」

**历史修正**：`0.2.3` 修过一条语义——直接询问当前天气「属于显式实时事实请求，
**不再要求必须同时存在穿衣、通勤或出行决策**」（`CHANGELOG.md:140-143`）。
说明他最初把环境感知绑在「决策场景」上，后来意识到**用户随便一句「今天几度」也该查**。

**成本控法：不靠省钱，靠「不在请求路径上联网」**

- 请求钩子内**零联网**，写成跨插件契约的硬声明：`request_hook_network: False`（境/`main.py:285-294`）
- 所有数据源**均不要求 API Key**——**成本主要是延迟，不是钱**
- 并发同 key 请求合并为一次上游调用（`core/cache.py:19-70`）
- 分层 TTL：地点 30 天、空气 1800s、故障回退 3600s

**「她想知道今天天气」这种自主行为：没有**（作者明确）。

后台每 900 秒刷新一条候选，但要说出口需连过四道门：缓存开关+常驻地点 → `care_person_id`
精确匹配 → 「序」授权 → 「情」确认归属 → 最后交「言」决定措辞。
主动发送默认关闭、每日上限 1 条，且**境自己从不发送**（境/`README.md:124-135`）。

> **推断**：他对「角色自己关心你」的态度是——**允许她注意到，但几乎不允许她主动说**。

**不写入长期记忆**：「不把天气和灾害事件写入『知』的长期记忆」（`README.md:278`）。
实现核对：全仓无向「知」写记忆的调用，唯一持久化是地点解析缓存（`core/service.py:144-147`）。

### 2.6 声（语音）——嗓子存在，但不一定用

- **默认关闭**；概率模式推荐 **0.1–0.3**「避免群聊过度刷屏」（声/`README.md:174`）
- 门控链与 `random.random()` 在 `main.py:1820-1826`，**每次决策连 `roll` 都写进
  `request_context`（可审计）**
- **AI 语音导演只决定「怎么说」，不动「说什么」**：只产出隐藏 `style_context`/
  `speech_text`，**「最终聊天文字仍保持原样」**（`README.md:193-195`）
- 概率语音与导演**继承自上游 `mimo_tts_clone`**（`README.md:26`），作者的增量是
  多后端/取消/契约

**可取消交付**（对 ling 最有用的一条）：分段 + 令牌 + 每段前后检查，
**只停未发之段、不终止整轮、状态交回模型、不额外调 LLM**（`README.md:68-80`）。

### 2.7 核（更新）——批准的那件事被原样执行，坏了自己退回去

- **冻结计划的理由**：防「执行与预览漂移」（`README.md:26-35`、`core/planner.py:132-157`）
- 事务自动回滚且**回滚后再验**，并诚实写「共享依赖可能已变化」
  （`core/transaction.py:205-275`）
- 29k 行 ≈ 系列的免疫层

## 3. 贯穿全系列的同一把尺子

**代码只管「能不能」，模型管「想不想」。** 同一个原则的七次应用：

| 模块 | 表现 |
|---|---|
| 序 | 「身份不等于授权」「工具可用≠必须做」（`README.md:52-53`） |
| 情 | LLM 只收表达建议，**不允许直接改关系数值**（`README.md:41`） |
| 言 | 本地规则拦刷屏，模型只管语境（`README.md:334-352`） |
| 境 | 注册只读工具，**不增加一次「要不要查」的请求**（`README.md:32-45`） |
| 声 | 概率模式不向 LLM 提供 TTS 工具，LLM 模式不执行概率自动 TTS（`README.md:35`） |
| 核 | 「检查可并发，写操作串行」（`README.md:32`） |
| 知 | 版本表可追溯，**但不自动裁决冲突**（`storage.py:423-475`） |

**ling 有同一条线**：`AUTONOMY-DESIGN.md:356-378`
「**行为风格归人设，正确性归代码**」，且他 2026-10-28 明确要求「我想给 LLM 一个高自由度」。

**两者不冲突**：系列说的是「权限与事实归代码」，ling 说的是「语气与风格归人设」。

## 4. 最有价值的一句话：三层时间观

**用户原话**（经 `凝心溯溪-开发状态记录.md:99-103` 转述，2026-09-11）：

> 「第二轮『注入即标注』对记忆层过于机械——人不会精确记得『什么时候学过什么』，
> 与拟人化方向冲突。结论：**拟人 ≠ 没有时间感，而是『节奏层精确、记忆层模糊、
> 表达层拟人』**」

据此**回滚了知与核的改动**，「只有言按拟人化方案修订」。落地为「**时间是感知不是台词**」
（`:111`）。

**当时已定好的模糊桶方案**（`:118`）：

> 记忆注入时间改模糊桶——<1h 刚刚记下的 / 当天 今天记下的 / 昨天 /
> N天前记下的（MM-DD）/ N周前记下的（MM-DD）/ 很久以前（YYYY-MM）；
> 括号内日级锚点保留给「下周二生日」类相对日期事实推算。

> **⚠️ 这条判据尚未应用到 ling。** ling 的记忆召回目前没有对应的模糊化设计。
> 这是本文识别出的、**最值得优先跟进的一条**——它改动面小，且方向由作者本人论证过。

## 5. 一个需要你知道的立场差异：ling 与系列的「是否承认自己是 AI」

> **说明**：本节只做立场对照，不引用已排除插件的设计细节。

**系列的取向（作者明确，见于系列文档）**：倾向于**删掉暴露中介的东西**，
让角色不把自己描述为 AI／程序／虚拟角色。这是沉浸优先。

**ling 的既有取向**（`ling/src/ling/domains/persona/service.py:31`，作者明确）：

> 「被问到『你是不是 AI』时**如实说明**自己是 ling 这个角色程序」

同文件 `:25` 还有：「可以有自己的判断、偏好和小情绪，但**不假装自己是人类**，
也不编造现实履历。」

**这是两种对立的设计选择：**

| | 沉浸优先（系列取向） | 诚实优先（ling 现行） |
|---|---|---|
| 被问是不是 AI | 不承认／回避 | **如实说明** |
| 代价 | 一旦被戳穿，前面所有话都不可信 | 沉浸感有边界 |

**ling 现行做法是自洽的**：它与 ling 反复强调的「不声称做过没做过的事」
「`model_inference` 不进事实」「模拟活动标注 `clock_only`」属于同一条原则——
**可核对优先于沉浸**。

> **这不需要改。** 本文指出它，是因为若将来想改，那是一次**立场变更**，
> 而非「抄系列的做法」。同时要意识到：一旦允许她自认是真人，就与 ling
> 现有的「诚实性」条款系列冲突，需要一并重写。

## 6. 对 ling 的借鉴清单

### 6.1 值得抄

| # | 建议 | 依据 |
|---|---|---|
| 1 | **允许零召回**——有候选也可以一条都不注入；门控未命中时连检索都不做 | 知 `main.py:782-786`；Memory Companion `core/injection.py:443`「没候选就跳过」 |
| 2 | **按查询线索生成候选**，而非先截「最新 500 条」 | 知 `storage.py:881-915`；ling `service.py:582-603`（500/501 实测） |
| 3 | **把记忆层时间模糊化**（模糊桶 + 日级锚点） | 用户 2026-09-11 原话 `状态记录:99-103,118` |
| 4 | **过时/纠错事实保留来源与旧值** | 知 `storage.py:423-475` |
| 5 | **「不知道」与「没有」必须可区分**——三态 `observed`/`unavailable`/`not_applicable` | 境 `README.md:40`；ling 已有 `clock_only`、`model_inference` 不进事实 |
| 6 | **按需获取而非每轮注入**——让模型自己决定要不要看，不增加判断请求 | 境 `main.py:285-294`；`README.md:32-45` |
| 7 | **后台算 / 前台只读 / 发送另授权**三段式 | 境 `main.py:337-382`；可与 ling 的 `ProactiveOpportunity` 管线复用 |
| 8 | **发言和语音交付分层**：是否说 → 说什么 → 怎么发声 → 能否继续发 | 声 `README.md:68-80`；`CONVENTIONS.md:139-142` |
| 9 | **可预览、可撤销、可诊断**的变更纪律 | 核 `core/planner.py:103-157`、`core/transaction.py:205-275` |
| 10 | **领域单写者 + 显式契约**，只交换可序列化数据和可解释的失败 | `CONVENTIONS.md:244-260`（见 §6.3 教训） |

### 6.2 不该抄

| # | 不要做 | 理由 |
|---|---|---|
| 1 | 照搬别的项目的召回条数（`top_k=4`/3/5 等） | 那是**检索 API 上限**，不等于**每轮注入量**；ling 需按自己的回放集定 |
| 2 | 把「每轮必回至少 1 条」当常态 | 三个成熟插件都不做；ling `scored = kept or scored[:1]` 是异类 |
| 3 | 把天气/环境快照写进长期记忆 | 境明确不写（`README.md:278`）；旧天气会被当成现状 |
| 4 | 默认就让她主动开口 | 境四道门全关、默认 `proactive_enabled=false`、每日 1 条 |
| 5 | 用固定疑问词判断「要不要检索」 | `injection.py:91`「不要依赖固定疑问词判断用户意图」 |
| 6 | 把 `inject` 沉默模式当成零成本分类器 | 它仍需主模型推理，只是不额外调用 |
| 7 | 机械照搬「Cowan 4 组块 → 每轮 0–2 条」 | **那是工程推论，不是论文结论**（见 `MEMORY-REDESIGN.md`） |
| 8 | 迁移「临」的具身协议 | 52.9k 行绝大部分是「让 Unity 安全连上来」的成本，不是「更像人」的成本 |

### 6.3 两条具体的工程教训（系列踩过的坑）

- **duck-typing 静默失效**：0.x 时代靠 duck-typing 探测「知」的 `recall`，
  对端没实现时桥接**静默失效、排查成本很高**（`CONVENTIONS.md:244-260`）
- **热重载类身份冲突**：跨插件传 Python 对象，热重载后「同名不同类」导致
  `isinstance` 失败 → 统一上下文只放 **JSON 可表达的普通 dict**，并规定字段单写者

> **对 ling 的意义**：ling 是单体，但**领域之间传什么**值得查一遍——
> 若跨域传 ORM 对象，会出现类似的隐式耦合（改一个域会静默影响另一个）。

## 7. ling 的现状对照

| 插件 | ling 里的对应物 | 差距 |
|---|---|---|
| 知（知识/记忆） | `MemoryRow`/`MemoryEpisode`/`core_memories` | **有**，但每轮无条件 `limit=6` + 强制至少 1 条 |
| 情（关系） | `trust_level` | **很粗**（只有 `owner` 之类判定） |
| 言（对话节奏） | — | **缺失**：没有「要不要回」的判定 |
| 序（身份边界） | `AudienceSnapshot`、`PolicyGate` | **有**，但只做可见性，不做行动授权 |
| 境（环境） | — | **完全缺失**（主动候选源明确写「天气变化不在其中」） |
| 声（语音） | `ports/speech.py` | **有入站链路，无 ASR/TTS provider**（`FEATURES.md:147-154`） |
| 核（更新） | `deploy/update/executor.py` + `ling-updater` | **有**，但 Docker 升级/回滚**未演练**（`UPDATES.md`） |

**这说明**：ling 在「记忆」和「身份」上有实现，在「对话节奏」和「环境感知」上基本是空的。
