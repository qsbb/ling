# ling 记忆与回复可靠性分批推进方案

日期：2026-11-11。范围：评估与实施排期；本文不改运行代码。源码行号按本日工作树和所列上游分支快照，开发前重核。外部项目只评价下列读到的代码；“没查到”不等于证明整个项目不存在。

## 0. 裁决与现状

**三件事的上线顺序是：① 候选池覆盖修复（含同域 BM25 统计与全域路名次）→ ② LLM 流开始前重试 → ③ 晚回失败兜底完整功能。** 候选池在 500/501 对照中有确定性漏召回，可在保持 `k=6` 与现有注入规则时独立修；重试随后降低真正进入失败兜底的频率，并先固定错误分类、终态和“部分输出”语义；晚回文案最后据这些终态落地，避免把可恢复错误或半截输出说成“没答上”。三者前置同一批评测基线与观测，但不互相捆成一次发布。依据：`tests/integration/test_memory_recall_scope.py:120-175`、`src/ling/domains/memory/service.py:582-603`、`src/ling/models/router.py:294-374`、`src/ling/worker.py:1578-1627`。

旧文档不可直接当当前任务清单：`docs/design/MEMORY-REDESIGN.md:395-414` 说先做零命中门，`docs/SLEEP-MEMORY-CONSOLIDATION.md:1-29` 已将其修订为先修候选覆盖；`docs/design/MEMORY-CANDIDATE-DESIGN.md:1-18,132-138` 是当前候选契约。清除代次与在途提取栅栏已有 `tests/integration/test_memory_purge_flow.py:156-405`；睡眠期零模型整理已在 `src/ling/domains/memory/consolidate.py:71-178`，调度在 `src/ling/worker.py:4073-4074,4933-4968`；后期工作是**扩展**这些能力，不是重新创建。`updated_at` 的 `onupdate` 在 `src/ling/infra/models.py:48-52`，召回强化发生 UPDATE（`service.py:1431-1476`），它不能充当纯内容时间。群聊中她不主动谈自己的活动是既定可见性边界，后续回放需防回退。

## 2. 候选池与 BM25：必须同批切流

**明确裁决：生产候选池修复必须同时改成 `D(q)` 上一致的 BM25 统计与各路名次；不选择“先并集上线、口径以后再改”。** 可以先把并集代码做成影子计算或 `approximate` 诊断，但不能宣称修好了覆盖，也不能据此切默认流量。原因是 `_bm25_scores(query, docs)` 每换一次 `docs` 都重算 `N`、`df`、平均文长（`src/ling/domains/memory/service.py:84-127`），`_rank_map` 又只排传入行（`:206-218`）。多路并集若仍在并集内打分，会改变某词的 IDF、相对长短和各路名次；旧行虽然进入池，也可能被局部词频或另外一路的局部名次压走。这个中间状态**确会产生短暂不一致**：候选器用全域相关性判断，后续 RRF 用局部语料的另一套分数，无法用 `D(q)` 的外部上界证明池外行不可能进前 `k`。它不等于每次都错，但“500/501 不再空”也不等于 top-k 正确。依据：`MEMORY-CANDIDATE-DESIGN.md:18-47`；`service.py:84-127,206-218,643-745`。

上线批次先构造有权有效域 `E(q)`，再按是否有**完整可用** embedder 定义 `D(q)`：无 embedder 时断言是字面或实体命中、情节是字面命中；有 embedder 时是 `E(q)`，但向量模型错版/缺失/ANN 仅能标近似。受众必须先可编译冻结快照预过滤、再用现有 Python `source_filter` 复验；任意回调不能从 SQL 推导权限，需小库全域精确回退或显式未认证。倒排索引的 token 与现有中文 2-gram `_tokenize` 等价，索引写入与撤回同事务。各路从 `M_i=k=6` 起（来自现有生产 `limit=6`），同分取全，按 `6→12→24→…` 扩张；只有第六条经 MMR 后分数**严格大于** `U=max_i[1/(60+b_i+1)]` 才标 `certified`，否则继续扩张/全域精确回退；500 仅是旧代码的内存软预算，绝不是证明阈值。重排器可任意改序，`certified` 只承诺**重排前** RRF/MMR 覆盖。依据：`MEMORY-CANDIDATE-DESIGN.md:18-105`，`service.py:84-127,206-227,298,1394-1435`。

### 三项重点的完整验收边界

候选池：`tests/integration/test_memory_recall_scope.py:134-175` 现有 `xfail(strict=False)` 是必须从 XPASS 转为普通通过的真实 500/501 回归；但**不能只看 XPASS**，还要与全域 oracle 同序，并明确 `certified/approximate`。`tests/eval/probes.yaml` 44 条没有 501 条长尾压力，也不能判定是否应该跳过整轮注入。C2 前后均保持原 `k=6` 和 `test_floor_never_returns_empty_when_hit_exists` 旧行为；M1 才改这条用例。

LLM：当前 `src/ling/models/openai_compatible.py:100-110` 的 **429 已是 `retriable=True`**，`docs/design/LLM-RETRY-RESEARCH.md:338-370` 的“429 还需改 true”是旧结论，实施重点在路由消费。`router.py:294-374` 的 `delivered_any` 目前以正文 delta 为界；实现须区分“尚无任何对外可见或不可重放输出，可重试”与“已发正文/工具结果/投递副作用，只能部分完成”，按 `trace_id` 贯穿一次业务调用并统计候选/尝试次数。400/401/403 以及取消不重试；网络、超时、429、5xx 最多三次含首次；指数退避+抖动需受整轮 deadline 和 `Retry-After` 约束。即使没有 `[DONE]` 或 `finish_reason`，也不能把断流默认为正常完成。任务级 `MAX_ATTEMPTS=5` 只管调度/基础设施重放，同一 LLM 作业耗尽后不可再由 outbox 自动把调用放大至 15；当前主候选加一个 fallback 时，每候选三次给出整轮最多 `3×2=6` 次供应商请求，且仍受总 deadline 约束。熔断失败计数按一次候选耗尽记，不把内部三次都算作三次独立业务失败。参考 `docs/design/LLM-RETRY-RESEARCH.md:15-40,298-406`。

晚回：`DEFERRED-FALLBACK-DESIGN.md:94-137` 的示例句有“等下再跟你讲”“回头补”，与其自身 `:14-24,76-84` 的“不承诺时间”冲突，**不采纳这些句子**。事实骨架只包含“先前有对用户可见的晚回约定”“此问题仍未答上”，不能编造忙碌原因、待办活动、未来补答时间或已送达。首批仅对当前支持的私聊/Web 窗口渲染；群聊 `test_group_window_is_refused_instead_of_delivering` 仍为取消，不因为设计了群聊模板就解禁。送达判断必须以外发回执/落库事实与 `fallback_used` 一致；已部分发言就用“回答中断”事实，而非谎称“完全没答”。离线个性化可以后置，无缓存、模型故障时完全不影响 F1。依据：`worker.py:1252-1264,1578-1720`、`tests/integration/test_deferred_reply_flow.py:403-504`。

| 有可见承诺，截止时零正文，窗口仍有效，尚未有投递记录 | 私聊/Web 发短模板，标 `fallback_used=true`；例：「刚才说了晚点回你，但这个问题我还没答上。」 | 只包含“承诺晚回”和“未答上”；超时/模型故障不写进角色台词。 |

| 平台回执不确定或送达失败 | 记录 `uncertain/failed` 与同一业务投递键；不盲重发、不标 delivered。 | `worker.py:1637-1720` 当前先落 actor 消息再发外部渠道，F1 必须消除这种幽灵消息。 |
| 未来群聊渠道明确支持晚回且单独验收后 | 用更短的通用句，不提自己的活动或原问题私密内容；例：「刚才说要晚点回，这个问题我还没答上。」 | 仍受受众、抢占、投递闸与用户已确认的群聊可见性约束。 |

模板选择只依赖确定性场景和经审核的人格语气，不能依赖失败时再调模型；可选 F2 的离线变体必须保留这两个事实命题并通过人工/程序审核，缓存无效就回模块常量。外部渠道不能与数据库做原子提交：先按 `deferred_id` 派生稳定投递键并冻结受众/序号，发送后以回执提交可见消息和状态；崩溃时按同一键查询/对账，不能用新随机 `operation_id` 重发。Web 的“落库即送达”可在本地事务内完成。日志不留原问题正文，重复 sweep 对同一承诺最多生成一份兜底；这一上界来自幂等键，而不是拍定“几分钟内只发一次”。依据：`src/ling/worker.py:1578-1720`、`docs/design/DEFERRED-FALLBACK-DESIGN.md:14-24,34-87,138-172`。

## 4. 风险总表与总回滚线

| 风险 | 发现条件 | 阻断／回滚动作 |
| --- | --- | --- |
| 跨主体、跨群、私聊外泄或清除后复活 | 44 探针隐私命中非零，或受众/代次回放失败；`source_filter` 与 SQL 作用域不等价。 | C2/M2/M3 一律停止切流，回旧读入口；已生成索引停读并保留原行审计；不靠夜间重建才撤销。 |
| BM25 局部口径伪装全域认证 | `N/df/avgdl` 只来自并集或同分页被截断；oracle 与 `certified=True` 结果不同。 | 关闭新入口，修同域统计与路名次后重测；影子结果只能标近似，绝不调高固定配额遮掩。 |
| 新索引拖慢召回或向量缺口 | p95/p99、扫描行数、扩页次数显著恶化；模型版不一致或 ANN 无上界。 | 关闭昂贵分路/回退精确小库路径，未认证的结果显式标近似；用 `EXPLAIN` 和独立容量压测决定是否可上大库。 |
| 误注入与漏注入 | M1 整轮标注集出现不相关旧事、关键旧事不见；44 条只反映直接 recall。 | 分开关掉按需 gate/绝对门/条数限制，保留 C2；按正负例重新校准，不改探针基线洗掉退化。 |
| LLM 超时成本、熔断、重复输出 | 单轮请求数超过批准的三次/候选，后台同任务累计超过上界，首字后重发，或半句记成功。 | 关闭 R1 内部重试；保留错误分类和部分完成记录；不自动重放已耗尽模型调用，人工诊断后重试。 |
| 晚回重复或越权补话 | cancelled/无承诺/群聊拒绝场景出现投递、重复 sweep 发两句、投递失败却 `delivered`。 | 关闭 F1/F2 文案与投递新路径，回原常量及原抢占闸；保留事件 ID 对账并修复状态，不删审计。 |
| gist 伪事实、跨受众整合、遗忘误删 | 生成摘要包含无来源具体值、`fact_eligible` 被绕过、源撤回后仍可读；软衰减触发物理删除。 | 关 M3 gist 读/写，原情节/断言不动；物理清除只由现有显式清除与保留策略执行，软分可单独关。 |

每一批只迁移所需结构，切换依靠各自特性开关；回滚代码**不回滚已发生的用户可见发送**，所以晚回尤其必须在投递前用冻结受众、抢占状态和幂等键阻断。生产开关关闭后应能继续读旧原行；若新索引或 gist 写入过，先停读并审计，不简单 drop 表。全量 pytest、相关 lint、`git diff --check` 和 44 探针是每批发布门；涉及注入、LLM、投递的批次另须整轮回放与故障注入，不能用“探针绿”代替。
