# Ling 整包备份与导入恢复：冻结验收判据

状态：冻结于实现之前。本文只定义“什么算通过”，不引用实现细节。后续实现必须按这些判据验收；若判据要改，必须在此文件记录改动理由和时间。

## 观测对象

每次验收开始和结束都记录：

```bash
git status --short
git log -1 --format=%H
sha256sum <本轮被测文件>
```

“干净”断言必须附当时输出；过程性汇总必须标明是汇总，不冒充逐条留证。

## 判据 C1：默认完整包的内容完整性

输入：在版本 A 的隔离实例写入会话、记忆、人设、配置、媒体、受管插件样本，然后生成一份默认备份包。

通过条件：

1. 包内存在 PostgreSQL custom-format 逻辑备份、媒体字节归档、根密钥材料或明确且可恢复的来源说明、部署配置、Ling 管理的插件配置与持久状态、可启动对应版本的产物或固定身份记录。
2. 清单至少含：格式版本、应用版本、提交、数据库迁移版本、依赖范围、所有纳入文件的哈希、根密钥来源、镜像 digest＋平台架构或源码发行产物身份。
3. 清单里声明 present 的每个文件都通过 sha256；声明 absent 的字段必须给出“为什么可以缺席”的可判定条件。
4. 包内不得出现数据库口令、Provider 凭据明文或根密钥内容；凭据只能以受控材料与来源说明存在。

反例：只含 DB dump 的旧式备份必须通过不了 C1；缺根密钥来源、缺版本产物、缺插件状态和 hash 错一项都必须失败。

区分力：字段名“有 root key 文件”与“应用实际生效的 root key”不能混为一谈；两者不一致时清单必须显式报出而不是静默通过。

## 判据 C2：导入预检能拒绝不可恢复包

输入至少四组：缺声明文件、hash 不匹配、版本/产物不可用、目标空间/架构/迁移链不兼容。

通过条件：每组都在切换任何运行实例之前非零退出，并说明具体失败项；没有创建半成品目标卷、没有覆盖数据库、没有停写生产服务。

反例：把预检实现成“只看 manifest 是否存在”时，缺文件和 hash 错两组必须红。

## 判据 C3：同实例 A→B→A 精确回退

输入：版本 A 写入样本并备份；升级到版本 B 并追加新数据；导入 A 包并恢复。

通过条件：

1. 运行中 `/v1/version` 的应用版本与提交等于 A 包清单记录。
2. 镜像模式运行 digest 与平台架构等于包内记录；源码模式发行产物身份等于包内记录。
3. 数据库 schema 版本等于 A 包记录，且 A 时点的会话、记忆、人设、配置、媒体引用与受管插件状态可读。
4. B 时点新增的数据不出现在恢复后的关键表中。
5. 媒体引用指向的实体文件可读。
6. 包内凭据恢复后可被应用实际使用，不只是文件存在。

反例：恢复后只把 DB 恢复到 A、运行版本仍是 B，必须通过不了 C3。

## 判据 C4：干净实例离线恢复

输入：同一 A 包导入一套空的 Compose 项目；限制对外网络。

通过条件：包内记录的应用版本产物能直接载入并启动；不依赖拉取最新镜像或重新构建源码；健康检查通过；C3 的数据与凭据断言成立。

若当前环境 Docker daemon 不可用，此项保留为可复验脚本；脚本必须显式检查 digest、架构、镜像文件和装载结果，任何一步缺失都判“未验证”，不得写成“通过”。

## 判据 C5：切换前回退点与失败恢复

输入：制造启动失败（错误版本产物、坏配置或坏数据任选一种可重复方式），执行恢复切换。

通过条件：

1. 切换前生成可用回退点，并记录其位置与身份。
2. 启动失败后自动回到切换前实例；原服务的数据与版本可从回退点启动。
3. 恢复过程中使用安装/更新锁；恢复期间写入、进程重启、任务重试不会造成双写或半切换。
4. 日志保留预检、切换、失败、回退和健康检查各阶段。

反例：只打印“回退成功”而没有可启动的回退点，必须通过不了 C5。

## 判据 C6：恢复语义

输入：撤回墓碑、旧外发任务、受管插件状态、人设开关的样本随包恢复。

通过条件：

1. 已撤回内容保持撤回，不能复活。
2. 旧外发任务按其状态语义恢复，不能把已完成任务重新投递。
3. 受管插件配置与启用状态恢复到 A 时点。
4. 当前激活人设与人设开关恢复到 A 时点。

反例：仅恢复 DB 而不恢复文件侧插件状态，必须至少被一条断言抓到。

## 判据 C7：Web 与宿主入口

输入：通过 Web 管理页完成创建、列出/下载、导入预检、版本与覆盖范围核对、确认恢复、查看结果；另用宿主单命令在现有服务无法启动时完成恢复。

通过条件：Web 每一步都显示真实后端状态；下载入口对含凭据的完整包执行与管理权限相称的保护；宿主命令不依赖 Web 进程；历史 `ling backup` 与 `ling restore-drill` 仍可验证旧产物。

反例：Web 只放一个静态按钮而无真实状态/动作，必须通过不了 C7。

## 判据 C8：测试有效性

1. 至少两条关键测试做变异验证：去掉清单版本校验、去掉墓碑/媒体覆盖校验，各观察对应测试变红。
2. 每条负向断言都有同一次运行里的正向配对，且打同一注入点。
3. 报告区分“实测”“推理”“转述”，转述资料标注未核实。
4. 中文文本通过 U+FFFD 检查。
