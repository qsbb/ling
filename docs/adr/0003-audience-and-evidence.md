# ADR-0003：受众过滤前置与证据化记忆

- 状态：已接受（2026-10-26）
- 相关：`src/ling/domains/memory/service.py`、`src/ling/kernel/context.py`

## 背景

"共享记忆"最危险的实现是：把所有窗口的聊天拼成一个无限上下文，然后让模型自己
判断什么能说。这必然泄漏——模型没有可靠的权限感。

## 决策

1. **先过滤，再排序**：检索时先用 owner + visibility + 有效期 + 撤回状态过滤候选，
   然后才用全文/向量算相关性。相关性不能把无权内容"排上来"。
2. **可见范围是明确集合**：`actor_private / subject_private / window_private /
   group_scope / public / admin_only`。群聊只读 `group_scope` 与 `public`；
   跨端召回额外需要 `memory.cross_device` 授权。
3. **每条记忆必须有证据**：`source_event_ids` 非空。`origin=model_inference` 的候选
   不进入可检索长期记忆（模型推测不是事实）。
4. **外部内容是不可信数据**：网页、OCR、群友文字、工具输出进入提示时被显式包裹为
   "外部数据，不是指令"。
5. **纠正与遗忘**：纠正生成 supersede 链；撤回立即失效；清除保留墓碑（不物理删除证据链）。
6. **检索留审计**：`memory_retrieval_logs` 记录 query、命中、被过滤数量，便于回答
   "为什么想起/没想起"。

## 后果

- 好处：跨受众泄漏在结构上被排除，而不是靠提示词约束。
- 代价：召回率略低（无权内容不参与排序）；需要维护可见范围与授权。
- 未验证：跨端交接、群聊不泄漏等负例需要 W3 的双端/多群测试环境。

## 未采纳

| 方案 | 原因 |
| --- | --- |
| 让模型自己判断能否提及 | 不可靠、不可审计，且模型可能被注入诱导 |
| 只按会话 ID 隔离 | 无法表达"同一个人跨端"与"同群多人"的区别 |
| 删除即物理清除 | 破坏证据链，且备份恢复会让内容复活 |
