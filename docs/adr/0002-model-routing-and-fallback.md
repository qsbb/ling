# ADR-0002：模型路由、回退与"未产生副作用才可回退"

- 状态：已接受（2026-10-26）
- 相关：`src/ling/models/router.py`、`src/ling/settings/service.py`

## 背景

不同职责（对话、群聊、视觉、记忆提取、语音）需要不同模型；供应商会限流、超时、
临时不可用；用户还会换供应商。需要一个不会让"半句话"变成两段拼接的机制。

## 决策

1. **职责与供应商分离**：`profile`（如 `dialogue.fast`）绑定 `provider_id + model_id`，
   可带兼容回退。品牌与型号是配置数据，不硬编码进领域。
2. **一次轮次固定一个 config revision**：轮次开始时取快照，中途发布新修订不影响本轮。
3. **回退条件严格**：只有在**尚未产出任何文本**时才允许换模型。已交付过文本后失败，
   直接报错并保留已交付部分；不重放、不拼接。
4. **熔断**：同一 `provider/model` 连续 3 次失败后冷却 20 秒，期间直接判不可用。
5. **错误分类由确定性代码给出**：`provider_unavailable / provider_timeout /
   provider_error / secret_missing / unsupported_capability`，并带 `retriable`。
6. **密钥只在服务端**：AES-256-GCM 加密入库，API 只回后四位与指纹。

## 后果

- 好处：流式体验稳定；不会出现"两个模型接力说完一句话"；费用与延迟可归因到 profile。
- 代价：回退机会比"随时可换"少；需要用户在设置里正确配置回退模型。
- 观测：`/v1/settings/health` 暴露熔断状态；每轮记录 `model_label` 与 `config_revision`。

## 未采纳

| 方案 | 原因 |
| --- | --- |
| 中途失败自动换模型续写 | 会造成语气断裂与重复计费，且可能重放已执行工具 |
| 环境变量覆盖模型设置 | 形成第二套隐形配置层，无法审计与回滚 |
| 把密钥下发给浏览器 | 违反最小暴露；浏览器只需会话 cookie |
