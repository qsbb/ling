# 功能与使用边界

本页介绍用户可以做什么，以及哪些能力需要额外配置。确认某次发布实际测过什么，请看[发布验收记录](evidence/release-0.0.9-acceptance.md)；测试模式和替身接口的结果不能替代真实渠道或模型的验收。

## 对话与角色

| 功能 | 使用时会看到什么 |
| --- | --- |
| Web 对话 | 可以开多个会话窗口、查看历史、归档会话、停止生成或重试。回复按流式显示。 |
| 人格与情绪 | 人格设定决定表达方式；情绪、精力与关系会影响回复意愿，而不是替角色写死台词。 |
| 关系与身份 | 渠道账号与自然人身份分开管理；绑定前先核实账号属于谁，避免把不同人的上下文合到一起。 |
| 日程与主动联系 | 日程、承诺和其他事件可能产生联系机会。是否真的发出还受时段、每日限额、权限和渠道能力约束。 |
| 总览 | 查看角色状态、近期记忆、主动联系与渠道状态。没有数据和数据读取失败是不同状态。 |

衔接模型前先看[模型配置](DEPLOYMENT.md#3-设置模型唯一入口)。`LING_TEST_MODE=1` 使用确定性替身回复，适合开发和排查，不会验证供应商的实际生成能力。

## 记忆与可见性

- **分层存储**：结构化事实、互动情节与核心记忆各有用途，不是把整份聊天记录都放进每轮上下文。
- **按证据使用**：用户陈述、外部观察、已核验来源和模型推断分开标记。模型推断不当作已确认事实。
- **支持更正和撤回**：例如用户先说住杭州、后来明确说搬到苏州，当前住址与历史住址应分开；「打算搬」不等于「已经搬」。
- **受可见范围约束**：私聊内容不会自动进入群聊。实体关联和摘要也不能绕过范围过滤；`sealed` 模式连核心记忆也不注入。
- **语义检索可选**：可以配置 embedding 和 rerank；未配置时仍可使用字面检索。环境变量见[配置示例](../deploy/env.example)。

## 渠道、多模态与工具

| 入口 | 条件与边界 |
| --- | --- |
| Web 控制台 | 可直接登录使用，不需要外部聊天平台。历史浏览器验收使用了测试或降级环境，不能据此判断真实模型效果。 |
| QQ 官方机器人 | 已接入 QQ 开放平台网关；需要配置应用凭据、启用连接器并核对 OpenID 和访问权限。见 [QQ 官方接入](DEPLOYMENT.md#64-qq-官方机器人qq-开放平台--qq-bot)。 |
| OneBot V11 | 需要单独运行兼容端，例如 NapCat。HTTP 与 WebSocket 的接法不同；上报、身份绑定和鉴权见 [OneBot 接入](DEPLOYMENT.md#6-接入-qqonebot-v11)。没有平台确认的发送结果不作为成功回执。 |
| 移动端与微信 | 仓库有 [Flutter 客户端](../clients/mobile/README.md)和微信适配代码，不等于已完成真实终端或渠道验收。 |
| 图片 | 配置合适的视觉模型后，图片描述可以进入对话上下文，并按推断内容处理。这不包含设备相机或位置采集。 |
| 语音 | 入站转写和回复语音已接线，需要相应 ASR/TTS 供应商；OneBot 语音条还需要[编码依赖](DEPLOYMENT.md#116-语音条依赖ffmpeg--pysilk-mod)。自动化覆盖不等于真实厂商的识别、合成和播放都已通过。 |
| 工具调用 | 对话可以按配置向模型提供工具；具体可用工具受当前配置和权限限制。异步执行的范围见[异步工具说明](ASYNC-TOOL-EXECUTION.md)。 |

具身设备接入、公开发布、Discord 和 Telegram 不在本页的可用部署路径内。

## 运维

- `/healthz` 检查进程，`/readyz` 检查服务就绪状态；模型和渠道不通时，先看对应设置页与日志。就绪不表示外部模型已验证。
- 常规 Compose 部署按单实例文档操作。不因内部有租约和幂等机制，就假定可以直接增加容器副本。
- 备份、恢复演练和网页更新是不同操作；先核对部署模式，再进入[部署手册](DEPLOYMENT.md)或[升级指南](UPDATES.md)。
